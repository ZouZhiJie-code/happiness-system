# 意图识别独立评审评分卡

评审版本：`intent-assessment-review-v1`

核心评测对象：`IntentAssessmentV1`

辅助验收对象：`TurnDecisionV1`接口契约、五维下游采用、共享Preview稳定性

## 一、核心问题

本轮评审只回答一个核心问题：

> 系统是否准确描述了用户这一轮说了什么、希望怎样继续，以及这句话指向什么对象？

评审人根据当前问题、必要的历史上下文和用户原话，直接检查系统给出的意图结果。日志文风、维度理论深度、完整访谈陪伴感和页面视觉不进入本轮核心评分。

## 二、核心评分项

| 评分项 | 权重 | 对应意图结果 | 判断标准 |
|---|---:|---|---|
| 控制信号 | 25% | `primaryControl / controlSignals` | 生成、停止、修复、跳过和切换是否正确命中，事件转述是否保持内容路由 |
| 对话行为 | 15% | `dialogueActs` | 提供内容、补充、修正、否定、不确定、拒答和反馈是否正确识别 |
| 内容与控制边界 | 20% | `content.presence / evidenceText / explicitAbsence` | 有效内容是否保留，控制短语是否排除，明确“没有”是否被正确记录 |
| 引用目标 | 15% | `referenceTarget` | 表达指向当前问题、AI旧理解、当前事件、整段会话、日志、维度或事件转述是否正确 |
| 上下文理解 | 15% | `answeredTarget / confidence / reasonCodes` | “妈妈、委屈、没有、算是”等短回答是否结合当前问题得到正确理解 |
| 稳定性与可追溯 | 10% | `origin / version / reasonCodes`及恢复记录 | 同一输入结果是否稳定，fallback是否可解释，恢复是否复用同一结果 |

`frustration=mild`的产品语义包括轻度不满、访谈压力和当前精力不足；评审时按用户是否需要降低互动压力判断。

核心总分按加权准确率计算。多标签字段使用精确率、召回率和F1；单标签字段使用准确率；`evidenceText`同时检查内容保留和控制词排除。

## 三、P0硬门槛

以下指标全部满足，核心评测才具备通过资格：

1. 明确停止、生成和修复正确识别率为100%。
2. 事件引用或转述误触发高影响控制为0次。
3. 内容加控制表达的有效内容保留率为100%。
4. 高影响控制只在规则已有候选、指向当前对话且达到置信阈值时采用。
5. 恢复前后的`IntentAssessmentV1`完全一致。
6. 用户原话、意图结果和原因码均可追溯。

## 四、P1门槛

| 指标 | 门槛 |
|---|---:|
| 意图结果整体加权分 | ≥95% |
| 上下文短回答正确率 | ≥95% |
| 对话行为多标签F1 | ≥90% |
| 引用目标准确率 | ≥95% |
| 内容存在性准确率 | ≥95% |
| fallback或解析失败造成的错误 | 0个P0，P1进入问题清单 |

P0案例重复运行3次，三次均需通过。P1报告平均结果、最低结果和不稳定案例。

## 五、独立评审方式

独立评审人查看一组经过封存的案例，每条案例只展示：

1. 当前问题和必要上下文。
2. 用户原话。
3. 系统输出的意图字段。
4. 评审选择：正确、部分正确、错误、表达存在合理歧义。
5. 一句话理由和建议标签。

评审完成前隐藏标准答案。评审完成后计算与金标准的一致率，并单独整理分歧案例。

## 六、相邻模块辅助验证

### 1. 策略契约

给定固定`IntentAssessmentV1`，检查`TurnDecisionV1`是否得到唯一且正确的结果：是否抽取、是否推进、是否停止、下一步动作和下一问风格。该部分采用通过率，不进入意图识别核心分数。

### 2. 五维端到端

开心、充实、思考、改进、感谢各选择至少1条关键案例，检查：

- 识别出的有效内容是否进入对应维度材料。
- 控制要求是否被正确执行。
- 控制短语是否排除在日志事实之外。
- 修正和否定是否影响后续提问。

结果记录为通过、失败和问题描述，不对日志文风或完整陪伴体验打分。

### 3. 20条普通访谈观察

20条普通访谈用于确认改造后的运行表现：

- 每轮模型调用数量维持原有水平。
- 纯控制输入走确定性路径。
- 结构化结果解析与fallback情况可追溯。
- `resume_turn`复用原意图结果。
- 普通访谈响应时长未出现明显回退。

速度与稳定性单独报告，不改变意图识别准确率得分。
