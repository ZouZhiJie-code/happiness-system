# AI 访谈模块分析与优化地图

版本：`1.0`

最后更新：`2026-07-21`

使用者：产品负责人、AI

## 1. 文档用途

本文档规定 AI 分析、设计和实现一个访谈模块时：

1. 开始前读取什么；
2. 按什么顺序分析；
3. 每一步产出什么；
4. 怎样分析 Badcase；
5. 怎样设计指标和评测集；
6. 怎样确定优化顺序；
7. 怎样判断一轮工作完成。

本文档只保存通用方法。模块目标、具体场景、指标名称、计算方式、合格数值、评测案例和实现方案，写入对应的模块文档。

## 2. AI 执行规则

1. 先研究当前产品设计、实际运行方式、数据和 Badcase，再提出方案。
2. 先划分用户场景，再定义场景目标，随后讨论指标和方案。
3. 分开表达已知事实、基于事实的判断、准备验证的假设。
4. 用户输入提供目标、限制和已有信息。AI 独立检查其中的假设，并说明判断依据。
5. 使用可以观察、记录和判断的语言。少用比喻、形容词和含义宽泛的概念。
6. 每个结论说明适用场景、原因和证据。
7. 优先修改最早产生问题的位置，并控制一次改动涉及的范围。
8. 信息不足时，说明缺少什么、影响哪个判断，再提问或调研。
9. 发现其他模块可能需要调整时先记录影响；完成本轮讨论后集中处理。

## 3. 开始前的材料检查

AI 开始分析前，读取：

- 本文档；
- 当前模块的产品设计和实际实现；
- 上游模块已经确定的输出；
- 下游模块怎样使用当前模块的结果；
- 已经确定的产品原则和限制；
- 线上数据、用户反馈和 Badcase；
- 已有评测集和最近一次评测结果。

材料缺失时，列出缺失项，并说明哪些问题可以继续讨论，哪些结论需要等待材料补齐。

读取完成后先说明：

- 当前模块解决什么问题；
- 当前模块接收什么、产出什么；
- 哪些结论已经确定；
- 哪些问题需要调研；
- 本轮讨论范围。

## 4. 统一分析顺序

每个模块都按照以下顺序研究：

> 模块范围 → 用户场景与目标 → 输入、判断和输出 → 成功标准与指标 → 失败分类与归因 → 评测集 → 优化顺序与实现 → 验证与跨模块影响

### 4.1 模块范围

回答：

- 当前模块在访谈链路中的位置是什么？
- 它接收哪些上游结果？
- 它负责作出哪些判断？
- 它需要产出什么？
- 下游怎样使用这些输出？
- 哪些问题由其他模块负责？
- 哪些能力需要与当前模块共同设计、评测和优化？

产出：

- 一句话模块定义；
- 输入、判断和输出列表；
- 上游依赖和下游用途；
- 本轮研究范围。

判断标准：给定一个 Badcase，两名分析者能够判断它是否属于当前模块。

### 4.2 用户场景与目标

场景至少覆盖：

- 常见场景；
- 信息少、表达模糊等边界场景；
- 某个行为不应触发的反向场景；
- 依赖历史对话的多轮场景；
- 用户纠正、否定和补充的场景；
- 失败、刷新或退出后的恢复场景；
- 会改变用户原意、忽略用户要求或造成最终结果失真的高影响场景。

每个场景记录：

- 用户状态和当前表达；
- 系统已经掌握的信息；
- 用户希望接下来发生什么；
- 当前模块应该产出什么；
- 需要避免什么结果；
- 本场景的目标优先级及理由。

产出：场景清单、用户目标、模块目标、场景优先级、目标冲突时的选择理由。

### 4.3 输入、判断和输出

用一条完整链路说明模块怎样工作：

> 输入信息 → 判断过程 → 输出结果 → 下游使用方式

需要说明：

- 模块实际能够获得哪些信息；
- 哪些信息可以直接使用，哪些还需要确认；
- 模块作出哪些判断；
- 判断冲突时怎样处理；
- 每项输出代表什么、允许哪些结果；
- 输出在什么情况下新增、更新、保留或撤销；
- 信息不足时怎样处理；
- 输出错误会影响哪些下游结果。

产出：模块处理过程、输出定义、状态更新规则、上下游依赖。

### 4.4 成功标准和指标

先定义怎样算做对，再选择指标。

成功标准覆盖：

- 应该发生的行为是否发生；
- 不该发生的行为是否被避免；
- 输出是否准确；
- 多轮状态是否一致；
- 用户明确要求是否被执行；
- 下游能否正确使用输出。

每个模块设计四类指标：

| 指标类型 | 回答的问题 |
|---|---|
| 结果指标 | 模块是否完成核心目标 |
| 过程指标 | 问题发生在哪一步 |
| 护栏指标 | 局部优化是否引入新的用户问题 |
| 运行指标 | 响应时间、失败、重复处理和资源消耗是否符合要求 |

每项指标说明：衡量的问题、统计对象、数据来源、数值方向、适用场景、能否主要归因到当前模块。

具体指标、计算方式、当前数值和合格线，在研究对应模块时确定。

产出：成功标准、四类指标候选、数据来源和适用场景。

### 4.5 失败分类和 Badcase 归因

所有模块先使用以下基础失败类型，再增加当前模块的子类型。

| 失败类型 | 判断标准 |
|---|---|
| 遗漏 | 应该处理的内容没有处理 |
| 错误选择 | 选择了错误的判断或下一步行为 |
| 多余触发 | 执行了当前场景不需要的行为 |
| 内容错误 | 遗漏、增加、改变或错误归属用户信息 |
| 时机错误 | 行为合理，发生时间或顺序错误 |
| 状态错误 | 当前结果与历史信息、用户修正或最新状态冲突 |
| 表达错误 | 输出难以理解、造成压力或容易引起误解 |
| 运行错误 | 输入丢失、重复处理、超时或服务失败 |

一个 Badcase 可以包含多个失败类型，需要指定主要类型。

每个 Badcase 记录：

- 用户看到的问题；
- 发生问题时的完整场景；
- 预期结果和实际结果；
- 问题最早出现的位置；
- 主要责任模块；
- 共同影响模块；
- 直接原因及证据；
- 需要补充的评测案例。

责任判断：

- **主要责任模块**：最早产生错误，并且修正后大概率可以避免最终问题的模块。
- **共同影响模块**：放大错误、未能纠正错误，或继续使用错误结果的模块。

分析顺序：描述用户问题 → 对比预期与实际 → 按时间检查处理过程 → 找到第一次偏离 → 判断责任模块 → 说明直接原因 → 转成评测案例。

产出：当前模块失败分类、Badcase 归因结果、新增评测案例。

### 4.6 评测集

评测集分为两组：

- **能力评测集**：当前处理较差、需要继续优化的场景；
- **回归评测集**：已经处理正确、每次修改后需要继续通过的场景。

每条评测案例包含：

- 场景说明；
- 对话历史和当前用户输入；
- 上游模块输入；
- 期望输出或行为；
- 需要避免的输出或行为；
- 判断正确与错误的标准；
- 案例来源、失败类型和影响程度。

评测集需要同时覆盖：应该触发和不应触发、清楚和模糊表达、单轮和多轮、纠正和否定、切换和停止、历史 Badcase、上下游组合场景。

评测方式：

- 固定条件可以判断的内容使用固定规则；
- 语义和表达质量使用 AI 评分；
- 用户原意、主观感受和高影响结果使用人工抽查；
- 重要案例重复运行，观察结果是否稳定；
- 定期抽查对话和评分，确认评测标准符合真实用户体验。

产出：能力评测集、回归评测集、判断方式、运行方式和结果记录格式。

### 4.7 优化顺序和实现方案

每个问题根据以下信息排序：

- 对用户结果的影响；
- 线上出现频率；
- 影响的下游范围；
- 原因证据是否充分；
- 修改成本和引入新问题的风险。

具体模块结合场景决定权重，并记录排序理由。影响接近时，优先处理发生位置更早、原因证据更充分、可以直接评测、修改范围更集中的问题。

每项优化说明：

- 解决哪个场景和失败类型；
- 依据哪些案例和数据；
- 希望系统行为发生什么变化；
- 需要修改输入、判断、状态、表达、交互还是运行机制；
- 哪些已有行为需要保持；
- 影响哪些上下游模块；
- 增加或修改哪些评测案例；
- 上线后观察哪些指标；
- 出现什么情况需要撤回。

实现时先处理已经找到直接原因的问题，修改产生问题的直接位置，并让每项改动对应至少一个评测案例。

产出：问题优先级、原因证据、产品方案、实现方案、评测变更、上线观察和撤回条件。

### 4.8 验证结果和跨模块影响

模块内验证：

- 能力评测是否改善；
- 回归评测是否继续通过；
- 多次运行结果是否稳定；
- 响应时间、失败率和成本是否符合本轮要求。

跨模块验证：

- 上游输入变化后，当前模块是否仍能处理；
- 当前输出变化后，下游模块是否仍能使用；
- 端到端关键场景是否继续完成；
- 是否出现新的失败类型。

发现其他模块可能需要调整时，记录：受影响模块、原有设计、新证据、可能的调整、对当前模块的影响、紧急程度。

完成本轮模块讨论后，集中审查所有影响记录，决定调整已有模块、留到下一轮处理，或者保留原设计并记录理由。

产出：模块评测结果、回归结果、端到端结果、线上观察计划、跨模块影响、本轮结论和遗留问题。

## 5. 完成标准

### 5.1 模块分析完成

以下内容全部具备：

- 模块范围；
- 用户场景和场景目标；
- 输入、判断和输出；
- 成功标准和四类指标设计；
- 失败分类；
- 初始评测集；
- 问题优化顺序；
- 跨模块影响记录。

### 5.2 一轮优化完成

以下内容全部具备：

- 本轮优先问题已经处理；
- 新增评测案例覆盖本轮问题；
- 能力评测达到本轮设定的标准；
- 回归评测继续通过；
- 关键端到端场景继续通过；
- 上线观察指标和异常处理方式已经确定；
- 跨模块影响已经集中审查。

## 6. 每个模块最终提交的结果

1. **模块设计说明**：目标、场景、输入、判断、输出和依赖。
2. **指标说明**：结果、过程、护栏和运行指标，以及数据来源和适用场景。
3. **评测集**：能力评测、回归评测、判断标准和本轮新增 Badcase。
4. **优化与实现清单**：问题排序、原因证据、修改方案、验证结果、上线观察和跨模块影响。
