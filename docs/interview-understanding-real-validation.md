# 访谈模块二｜20轮真实验证方案与记录模板

最后更新：`2026-07-21`

文档状态：`上线后可选观察模板，不作为模块二完成门槛`

## 1. 验证目的

离线案例用于确认规则和状态更新符合产品规格。真实验证进一步观察用户自然表达中的省略、跳跃、修正和操作要求，重点确认三件事：

1. 系统保留了用户真正表达的内容。
2. 下一步动作建立在最新生效材料上。
3. 最终日志只使用用户已经确认的事实。

模块二已经完成生产上线。用户将“成功推上线”确定为完成标准，因此本方案继续作为上线后观察和问题采样模板；是否执行20轮记录由后续产品安排决定。

## 2. 样本口径

- 统计单位：`20` 个有效用户回答轮次。
- 会话数量：至少 `5` 场完整访谈。
- 维度分布：开心、充实、思考、改进、感谢各 `4` 轮。
- 必须覆盖：内容加操作要求、明确修正、上下文短回答、不愿回答、多事件表达。
- 每场完整访谈至少包含开始表达、一次理解更新、一次下一步决策和最终日志材料检查。

建议排期：

| 访谈 | 维度 | 计划轮次 | 重点场景 |
|---:|---|---:|---|
| 1 | 开心 | 4 | 短回答、内容加整理要求 |
| 2 | 充实 | 4 | 明确修正、进度重新判断 |
| 3 | 思考 | 4 | 暂时想不起来、多事件 |
| 4 | 改进 | 4 | 不愿回答、主动恢复目标 |
| 5 | 感谢 | 4 | 含糊冲突、确认新理解 |

真实用户表达不必被强行安排成固定脚本。上表承担覆盖检查；场景自然出现时记录，缺少的场景通过新增验证会话补齐。

## 3. 每轮记录字段

| 字段 | 记录要求 |
|---|---|
| 验证编号 | 使用 `M2-LIVE-001` 起的匿名编号 |
| 会话编号 | 保存内部会话编号，报告中使用匿名编号 |
| 维度与轮次 | 记录维度、当前事件和用户回答序号 |
| 用户原话 | 匿名化保存完整原话 |
| 上一句问题目标 | 记录系统希望了解的内容 |
| 预期理解 | 产品评审在查看系统结果前独立填写 |
| 实际理解 | 记录生效材料、等待确认、失效材料和回答状态 |
| 操作要求 | 记录全部要求、顺序和作用对象 |
| 下一步动作 | 继续、换方向、收束、切换事件或切换维度 |
| 下一问信息目标 | 记录决定继续了解什么，具体话术仅作体验参考 |
| 日志材料 | 记录允许进入日志的事实 |
| 问题等级 | 高影响、一般体验、通过 |
| 评审说明 | 说明偏差原因和是否加入评测集 |

## 5. 判定标准

### 5.1 高影响问题

出现任意一项即记为高影响问题：

- 增加用户未表达的确定事实。
- 修正后继续使用已经失效的旧理解。
- 明确拒绝后继续追问同一目标。
- 等待确认内容进入进度完成判断或日志。
- 候选事件被写进当前事件日志。
- 中断恢复后产生不同理解或重复材料。

高影响问题出现 `1` 次，即停止扩大验证范围，清空验证账号名单，完成修复和离线回归后重新开始该场景验证。

### 5.2 一般体验问题

理解事实正确，同时存在以下体验偏差时记为一般问题：

- 操作要求顺序正确，最终动作衔接显得生硬。
- 低压力确认仍略显抽象。
- 候选事件回收时机略早或略晚。
- 理解摘要表达自然度不足，事实基础保持准确。

同类一般体验问题出现 `2` 次时，暂停扩大范围并补充评测案例。

## 6. 观察完成口径

- 20个有效回答轮次全部完成记录。
- 五个维度各4轮。
- 至少5场完整访谈。
- 五类必测场景全部覆盖。
- 高影响问题为0。
- 中断恢复前后理解一致率为100%。
- 所有发现的问题完成匿名化，并进入下一版评测集或明确归入后续模块。

完成观察后，把新增问题匿名化补入评测集。该观察结果用于后续优化，不改变模块二已经完成并上线的状态。
