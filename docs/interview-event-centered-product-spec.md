# 事件中心自我探索产品规格

最后更新：`2026-07-22`

文档状态：`产品方案已确认，技术阶段 1 讨论中`

适用版本：`事件中心 MVP`

适用终端：`桌面端`

使用者：产品、设计、AI 产品策略、测试、技术方案讨论参与者

## 1. 文档目的

Daily Light 将从“先选维度、再讲事情”的访谈方式，调整为“先完整讲一件事、再选择想从哪个方面理解自己”。这次调整会改变用户进入访谈、组织表达、选择复盘方向、生成事件日志和汇总当天记录的完整体验。

本文档统一回答以下产品问题：

1. 这次重构解决什么用户问题。
2. 用户进入产品后会看到什么、经历什么、得到什么。
3. 事件、复盘角度、事件日志和当天完整日志之间是什么关系。
4. 每个阶段有哪些用户操作、产品状态和体验边界。
5. 常见场景、边界场景和失败场景应该得到怎样的处理。
6. 产品怎样判断事件中心 MVP 达到可发布水平。
7. 后续技术方案应该分成哪些阶段逐项讨论。

本文档描述产品结果与用户体验。原话可靠保存、事件隔离、失败恢复、成果一致性等内容以产品能力要求表达；数据库、接口、模型调用、代码结构、迁移脚本和基础设施选择进入后续技术方案。

## 2. 产品背景与重构原因

### 2.1 当前产品方式

当前用户需要先从开心、充实、思考、改进、感谢五个维度中选择一个入口，再围绕该维度讲述当天片段。每个维度拥有独立访谈、日志和日历状态，当天完整日志再汇总已经保存的维度日志。

这套方式已经验证了结构化访谈、日志生成、编辑保存和当天汇总的完整闭环，也沉淀了原话保存、刷新恢复、问题修复、回复重新生成、日志质量控制等成熟能力。

### 2.2 当前方式带来的用户问题

#### 用户要先理解产品分类

很多真实经历同时包含感受、判断、关系和行动。用户进入产品时需要先决定“这件事属于哪个维度”，会把注意力从事情本身转向产品分类。

#### 同一事件容易被切碎

一场工作冲突可能既带来委屈，也暴露双方期待，还包含一次重要选择。维度入口会把同一事件拆成几段独立访谈，用户需要重复交代背景，系统也容易重复追问。

#### 记录与探索的深度缺少清晰层次

有些时刻用户只想留下事情，有些时刻用户希望获得一点引导，还有一些时刻用户愿意继续深入。当前入口先绑定维度，用户难以先轻量记录，再根据当时的精力决定是否深入。

#### 当天成果难以还原真实事件脉络

当天完整日志目前按照维度组织。用户回看时先看到“开心、充实、思考”等分类，真实的一天却通常由几件具体事情组成。事件脉络被分散后，回忆感和个人意义都会变弱。

### 2.3 重构方向

- 产品定位：帮助用户持续进行自我探索。
- 高频任务：完成一次日常复盘。
- 最小单位：一件具体发生的事。
- 产品方法：先让用户完整表达事件，再由用户选择想理解自己的哪个方面。
- 交流深度：轻量记录、中度复盘、深度陪伴。
- 成果层级：事件日志承接单件事，当天完整日志承接一天中的多件事。
- 使用节奏：随时记录，按天汇总。

## 3. 产品目标与成功定义

### 3.1 产品目标

事件中心 MVP 需要让用户获得五项确定变化：

1. 可以直接讲事情，无需先理解产品分类。
2. 可以只记录，也可以根据自己的精力逐步深入。
3. 同一事件的背景只需表达一次，后续角度共享可信事实。
4. 每完成一个复盘角度，都能获得一句具体、可信、贴近自己的认识。
5. 最终日志忠于用户表达，能够保存、编辑和再次阅读。

### 3.2 三层成功

#### 单事件闭环

用户能够从自由表达开始，经过轻整理或复盘，生成并保存一篇忠于自己的事件日志。

#### 当天闭环

用户能够在同一天连续记录多件事，并在需要时形成一篇保留事件脉络的当天完整日志。

#### 质量闭环

AI能够理解当前事件、尊重用户纠正、提出有价值的问题、形成有证据的自我线索，并把这些材料准确转化为日志。

### 3.3 产品北极星

> 用户愿意从一件真实发生的事开始，在自己需要的深度上完成复盘，并留下值得保存的记录。

北极星同时约束三件事：进入门槛要低、交流深度由用户掌握、最终成果需要有保存价值。

## 4. 产品原则

### 4.1 一次只处理一件事

当前访谈只围绕当前事件展开。另一件独立事件可以被自然回应，也可以在当前事件成稿后通过“记下一件”开始。它不会自动进入当前事件的事实、复盘成果或日志。

### 4.2 用户自主选择角度和深度

AI负责帮助用户理解当前事件，复盘角度由用户选择。用户可以在第一检查点直接生成日志，也可以选择一个角度完成中度复盘；中度复盘结束后，用户还可以继续深入或选择剩余角度。

### 4.3 轻量记录拥有完整价值

用户只想留下事情时，产品仍然要帮助他形成一篇可信、可读的事件日志。自我探索深度由用户决定，日志资格不依赖用户完成全部角度。

### 4.4 用户表达拥有最高优先级

用户原话、明确纠正、用户对AI理解的正式采用和手动编辑共同构成最终可信来源。AI可以提出理解和可能性；每轮最多提出一个缺少原话支持的新推测，用户执行向前操作后视为正式采用，后续仍可通过新的表达完成修正。

### 4.5 所有理解受当前事件证据约束

一次事件可以支持一条当前线索。稳定性格、长期规律和人生结论需要跨事件证据与用户确认，事件中心 MVP 保持在单事件能够支持的范围内。

### 4.6 事件之间保持隔离

当前事件不读取当天其他事件的对话和内部成果。用户明确授权的长期记忆可以继续按照现有政策参与；普通当天事件内容不会自动成为下一事件的上下文。

### 4.7 用户控制清楚、低压力

生成日志、选择角度、继续补充、退出事件和记下一件都通过清晰操作入口表达。用户表达停止意愿时，AI停止继续施加问题压力，并把可以执行的下一步交给用户。

### 4.8 成熟产品形态优先复用

访谈主区、桌面端“今日日志”右栏、日志书页、自动暂存、月周日历、日视图和失败恢复继续作为新体验的基础。重构聚焦内容组织和产品语义，减少无必要的页面重建。

## 5. 关键概念与用户可见语言

| 概念 | 产品含义 | 用户可见方式 |
|---|---|---|
| 事件 | 用户当前正在讲的一件具体事情或同一条因果过程 | “这件事”“当前记录”，避免暴露内部编号 |
| 轻量记录 | 完成事件事实与基本感受的整理 | 第一检查点前的自然对话 |
| 自我探索角度 | 用户希望从当前事件中进一步理解自己的方面 | 理解感受、理清想法、梳理关系、复盘行动 |
| 中度复盘 | 用通常一至两问形成一条当前事件支持的自我线索 | 选择角度后的引导交流 |
| 深度陪伴 | 用户主动继续表达后，围绕当前角度展开更充分交流 | 继续输入即可进入，不增加模式设置 |
| 事件日志 | 一件事最终形成的一篇日志 | 可编辑标题、事件叙事、“我看见的” |
| 今日日志 | 访谈页内当天事件成果的集合 | 桌面端右侧面板 |
| 完整日志 | 两篇及以上已保存事件日志形成的当天成果 | 独立日志工作区 |

产品对用户统一使用“角度”，避免继续使用“五维”“标签”“槽位”“阶段状态”等内部概念。

## 6. 使用场景

### 6.1 场景 A｜事件发生后立即留下

- 用户状态：记得事情细节，时间和精力有限。
- 用户表达：“刚开完会，方案终于过了，我想先记一下。”
- 用户目标：快速留下这件事，稍后也能读懂。
- 产品响应：理解事件、轻整理、尽快进入第一检查点。
- 用户成果：一篇简洁的事件日志。
- 需要避免：为了寻找深层意义连续追问。

### 6.2 场景 B｜晚上集中回顾

- 用户状态：一天结束后想整理几件印象深刻的事。
- 用户表达：先讲一件，成稿后再讲下一件。
- 用户目标：分别保留每件事，最后形成当天完整日志。
- 产品响应：串行完成每个事件；今日日志持续展示已完成成果。
- 用户成果：多篇事件日志和可选的当天完整日志。
- 需要避免：把几件事混成同一个访谈上下文。

### 6.3 场景 C｜想理解但不知道从哪里开始

- 用户状态：知道这件事对自己有影响，暂时说不清影响在哪里。
- 用户表达：“今天那次沟通让我一直有点在意。”
- 用户目标：获得一个具体、容易回答的切入点。
- 产品响应：先帮助用户说清事件，再让用户从四个角度中选择。
- 用户成果：一条关于感受、想法、关系或行动的自然线索。
- 需要避免：AI替用户决定“真正的问题”。

### 6.4 场景 D｜只想记录，不想复盘

- 用户状态：精力有限，或者当下只希望保存事实。
- 用户表达：“我先记下来，不想再聊了。”
- 用户目标：停止追问并形成日志。
- 产品响应：停止施加问题压力，展示生成或退出入口。
- 用户成果：基于当前材料的事件日志。
- 需要避免：以“材料还不够”为理由反复追问。

### 6.5 场景 E｜愿意继续深入

- 用户状态：中度复盘已经带来一条线索，用户仍有内容想说。
- 用户表达：在第二检查点后直接继续补充。
- 用户目标：保持当前方向，不被新的模式选择打断。
- 产品响应：进入当前角度的深度陪伴；有增量价值时提问，其余情况回应或总结。
- 用户成果：更完整的理解和更充分的事件日志材料。
- 需要避免：为了维持对话而持续制造问题。

### 6.6 场景 F｜用户纠正 AI

- 用户状态：AI理解了大意，但某个事实或重点出现偏差。
- 用户表达：“不是我害怕做不好，我是不喜欢他们临时改决定。”
- 用户目标：让后续问题和日志基于正确理解继续。
- 产品响应：明确接住纠正，更新当前事件理解和受影响的角度线索。
- 用户成果：后续对话与日志采用最新表达。
- 需要避免：继续沿用被用户否定的解释。

### 6.7 场景 G｜从日历回看

- 用户状态：希望阅读过去某天发生的事情。
- 用户目标：快速进入事件日志或当天完整日志。
- 产品响应：月、周、日视图按事件成果提供直达动作；历史五维记录继续使用旧展示方式。
- 用户成果：清楚阅读某一天的记录。
- 需要避免：把历史五维记录与新事件成果混合成新的统计结论。

## 7. 产品信息架构

### 7.1 访谈页

访谈页继续使用现有工作台结构：

- 主区：当前事件对话、事件日志工作区或当天完整日志工作区。
- 桌面端右侧：今日日志面板。
- 顶部导航：继续承载日历、分析、画像、设置和当天评分等现有入口。

事件中心启用后：

- 统一事件入口替代五维选择页。
- 新访谈不再显示五维控制条。
- 主区始终聚焦当前事件，右侧面板承担当天多事件导航。
- 当前记录日期继续明确展示，避免用户把过去日期记录到今天。

### 7.2 今日日志面板

固定五维列表调整为当天实际存在的事件列表。面板继续保持三层信息：

1. 当天概况：待继续、已完成、完整日志。
2. 事件列表：正在记录、待保存、已保存。
3. 日级动作：生成日志、更新日志、查看日志。

### 7.3 日历

- 月视图：快速识别某天有几篇已保存事件日志，以及当天完整日志状态。
- 周视图：七天同屏比较，并提供继续记录、继续编辑、查看日志等直达动作。
- 日视图：展示当天事件列表、活动状态、事件日志和完整日志入口。

### 7.4 分析

历史五维分析继续读取旧数据。新事件、新四角度和长期自我模式的分析设计进入后续产品阶段，MVP 不把两套口径混合展示。

## 8. 完整用户旅程

### 8.1 主流程

```text
进入统一入口
→ 恢复当天活动事件，或开始一件新事件
→ 用户自由表达
→ AI 理解并轻整理
→ 第一检查点
→ 可直接生成，或选择一个角度
→ 中度复盘形成自然线索
→ 第二检查点
→ 可直接生成、选择剩余角度，或继续输入进入深度陪伴
→ 生成事件日志
→ 编辑 / 保存 / 记下一件
→ 多篇事件日志形成当天完整日志
```

### 8.2 进入统一入口

#### 当天存在活动事件

- 主区恢复这件事的当前对话和未完成输入。
- AI不重复开场，不创建新事件。
- 今日日志面板突出“正在记录”。

#### 当天不存在活动事件

- AI使用低门槛开场，例如：“今天有什么想记下来的事？”
- 输入区直接可用。
- 页面不要求用户先选择角度或交流深度。

#### 从日历进入指定日期

- 页面显示当前记录日期。
- 该日期存在可继续状态时，按既有主动作进入。
- 未来日期继续采用中性待到来语义，不开放记录。

### 8.3 事件记录与轻整理

AI首先完成三件用户可感知的事：

1. 接住用户刚说的内容。
2. 说明当前理解到的事件重点。
3. 只在需要时补充一个容易回答的事实锚点。

如果用户表达已经足以形成一段可读记录，AI直接进入第一检查点。AI不需要先判断事件属于哪个角度。

### 8.4 模糊事件

用户只说“今天有点烦”“发生了一件事”时：

1. AI用一个低压力问题寻找可描述锚点，例如发生在哪个时刻、和谁有关、脑中最先出现的画面。
2. 用户仍然说不清时，AI接受当前模糊程度。
3. 第一检查点继续出现，用户可以生成一个严格受现有材料约束的轻量记录，也可以退出。

### 8.5 第一检查点

第一检查点在事件已经被轻整理后出现，提供：

- `生成事件日志`
- `理解感受`
- `理清想法`
- `梳理关系`
- `复盘行动`
- `继续补充这件事`

四个角度平级展示，每个角度配一行用户能理解的说明：

- 理解感受：看看这件事带来了什么感受，触动了哪些在意。
- 理清想法：梳理当时怎么理解、判断和衡量。
- 梳理关系：看看互动中的期待、回应、位置或边界。
- 复盘行动：回看目标、选择、有效之处和阻力。

AI不推荐角度，不使用“更适合你”“真正的问题是”等引导性判断。

### 8.6 中度复盘

- 用户选择一个角度后，AI围绕当前事件提出第一个角度问题。
- 通常一至两问，最多三问。
- 一旦形成有效线索，立即收束。
- 达到三问后仍然只有有限材料时，AI基于现有内容诚实总结，不继续延长中度复盘。
- 暂时未形成可信线索时，AI自然说明当前能够确认的范围；日志中省略该角度线索。

中度复盘的完成结果是一句自然表达，例如：

- “这次真正让你难受的，是决定临时改变后那种失去准备空间的感觉。”
- “你仍然觉得临时调整并非完全不可接受，你更在意重要协作应该提前沟通。”
- “这段互动里，你在意自己有没有被当成共同做决定的人。”
- “这次最值得保留的，是先搭好框架再处理细节，节奏明显更稳。”

这句话由AI直接形成，无需增加确认步骤。用户有异议时可以直接纠正。

### 8.7 第二检查点

中度复盘结束后提供：

- `生成事件日志`
- 仍未聊过的角度
- 输入框继续可用

用户选择剩余角度时，开始一次新的中度复盘。用户直接继续输入时，产品把这视为对当前角度的进一步展开，进入深度陪伴。

已经聊过的角度从可选集合中退出。本次 MVP 不提供角度重入、恢复和来回切换。

### 8.8 深度陪伴

- 深度陪伴保持当前角度。
- 用户可以自由表达，不需要选择子路径。
- AI在存在清楚增量价值时提出问题。
- AI已经理解充分时，使用回应、整理或总结，等待用户决定是否继续。
- 当前阶段只保留`生成事件日志`作为成果动作。
- AI不以“还可以再深一点”为由维持无效交流。

### 8.9 生成事件日志

- 用户点击生成后，当前事件进入整理状态。
- 继续复用现有阶段式生成反馈，包括骨架、细节和润色的过程感知。
- 生成成功后，事件访谈永久结束，事件日志工作区打开。
- 用户可以编辑标题和正文、保存正式日志，或者先以草稿状态记下一件。
- 生成失败且无法形成可信基础版本时，事件保持在原检查点，并提供重试。

### 8.10 记下一件

- `记下一件`只在当前事件已经生成日志后开放。
- 当前日志存在未暂存修改时，先完成草稿暂存。
- 新事件使用新的空白对话，不读取上一事件内容。
- 今日日志面板继续保留上一事件的草稿或已保存状态。

## 9. 用户操作与阶段状态

| 当前阶段 | 用户看到的主要状态 | 可执行动作 | 完成条件 |
|---|---|---|---|
| 事件记录 | AI正在理解当前事件 | 继续表达、退出当前事件 | 事件可被轻整理 |
| 第一检查点 | 当前内容已经可以记录，也可以继续探索 | 生成、选择角度、继续补充、退出 | 用户选择下一步 |
| 中度复盘 | 当前角度的自然对话 | 回答、纠正、问题修复、退出 | 形成线索或达到三问上限 |
| 第二检查点 | 展示本轮线索和剩余方向 | 生成、选择剩余角度、直接继续输入 | 用户选择下一步 |
| 深度陪伴 | 当前角度持续交流 | 继续表达、纠正、问题修复、生成 | 用户生成日志 |
| 日志生成 | 阶段式整理反馈 | 取消当前整理 | 草稿成功生成或返回原检查点 |
| 事件日志草稿 | 可编辑书页 | 编辑、保存、记下一件、关闭 | 保存或保留草稿 |
| 事件日志已保存 | 当天正式成果 | 查看、重新编辑、记下一件 | 无额外要求 |

### 9.1 自然语言操作请求

生成、退出、记下一件和选择角度最终由用户点击明确入口执行。用户通过自然语言表达这些意愿时：

- AI立即停止继续施加问题压力。
- AI简短说明当前可执行的动作。
- 页面展示对应按钮。
- 系统等待用户点击后再改变事件状态。

问题修复和纠正理解继续使用自然语言直接生效，因为它们只调整当前交流内容，不替用户完成成果动作。

## 10. 事件定义与边界

### 10.1 产品定义

一件事是用户当前希望作为一个整体讲述和理解的经历。时间、地点和人物可以帮助辨认边界，用户叙事焦点和同一条因果过程拥有更高优先级。

### 10.2 边界决策表

| 用户表达 | 当前事件怎样处理 | 产品回应 |
|---|---|---|
| 先讲结果，后补原因 | 继续属于当前事件 | 吸收补充并更新理解 |
| 同一冲突从上午延续到晚上 | 因果过程连续时保留为一件事 | 关注过程变化，无需拆分 |
| 一句话包含两件同等重要的事 | 请用户选择当前想先聊哪一件 | 只把被选择内容进入成果 |
| 回答中顺带想起另一件独立事件 | 原话保留，结构化成果排除 | 自然回应，并提示成稿后可以记下一件 |
| 过去经历用于解释今天 | 作为当前事件背景 | 只提取对当前理解必要的部分 |
| 用户明确说“那不是重点” | 被否定内容退出当前主线 | 按用户新重点继续 |
| 用户补充一个新的客观事实 | 更新当前事件公共事实 | 后续角度可以共同使用 |
| 用户退出但没有成稿 | 保留对话，排除于成果 | 返回新的记录入口 |

### 10.3 两件事同时出现

用户第一次表达就包含两个并列事件时，AI只进行一次低压力选择，例如：“这两件都值得记。你想先从会议那段聊，还是先从回家后的那段聊？”

- 被选择事件成为当前事件。
- 未选择事件继续留在用户原话中。
- 产品不创建待办事件，也不承诺稍后自动提醒。
- 用户完成当前事件后，可以主动使用“记下一件”。

### 10.4 当前事件中出现另一件事

另一件事与当前理解直接相关时，可以作为背景。它拥有独立行动、结果或叙事目标时，只保留为用户原话，不写入当前事件事实、角度线索和事件日志。

### 10.5 产品暂不提供的事件管理

- 自动创建新事件。
- 暂停事件并切换到另一事件。
- 事件队列。
- 手动拆分或合并事件。
- 已成稿事件重新进入访谈。
- 多事件共用同一段复盘对话。

## 11. 信息可信度与用户纠正

### 11.1 用户原话

- 已发送原话完整保留。
- 用户通过新的表达完成补充和纠正。
- 刷新、失败或继续生成后仍然回到同一轮原话。

### 11.2 AI理解

- AI理解以自然语言展示，用户可以直接纠正。
- AI提出的解释保持可能性语气。
- 每轮自然理解最多包含一个缺少用户原话支持的新推测。
- 用户执行普通内容回复、选择当前事件、选择探索角度、继续探索或生成事件日志后，当前新推测成为正式采用的事件事实。
- 纠正理解、换问法、切换回复版本、问题修复、退出事件和失败后的继续生成不会触发采用。
- 用户新表达与当前待确认推测直接冲突时，冲突判断优先；该推测进入已拒绝状态，后续向前操作不会再次采用。
- 产品继续使用现有自然理解、纠正理解和换问法入口，不增加额外确认提示。
- 用户明确否定后，旧解释停止影响后续问题和日志。
- AI接住纠正的当轮只说明最新有效理解，可以基于已确认内容回应或提问，不再加入新的无原话推测。

### 11.3 事件事实

- 用户明确说出的具体内容可以直接成为当前事件事实。
- AI推测需要用户后续表达或向前操作支持；系统保留“AI提出、用户正式采用”的来源记录。
- 纠正、换问法、问题修复或退出都不会采用AI推测；纠正内容直接指向或语义冲突于当前推测时，该推测进入已拒绝状态，其余情况保持待确认。
- “没有”“不知道”“想不起来”同样属于有效回答，用于阻止重复追问。
- “对”“是的”等简短回答只在回应单一、清楚命题时形成事实，并同时保留AI问题和用户回答作为来源。
- 事实正文保持原记录；补充、替代、否定和撤回通过新的用户表达追加，系统保留完整变化过程，后续只使用当前有效结果。
- 兼容的新内容按补充处理，新旧事实分别有效；明确替代时旧事实退出，新事实进入。
- 明确否定会保留一条否定事实；纯撤回只让旧事实退出，不自动补写相反结论。
- 一次表达可以同时修订多条相关事实，并作为一个整体生效。
- 一条事实被多次表达后，用户最新的明确纠正仍会让整条旧事实退出；此前来源继续用于追溯。
- 用户后来重新采用曾经撤回的说法时，以最新表达创建新的当前事实。
- 用户表达纠正意愿但目标不唯一时，AI先问清具体指哪一部分，当前事实暂时保持原状态。
- 明显互斥的新旧信息缺少改口信号时，AI先澄清冲突点；澄清完成前暂停选择角度、继续探索和生成日志，退出事件继续可用。
- 用户对冲突点回答“不知道、记不清、不想确认”时，争议信息退出成果，保留未知边界回答后继续流程。

### 11.4 角度线索

- 角度线索必须能够在当前事件和用户表达中找到依据。
- 用户在访谈中纠正事实时，相关线索同步修正或退出后续成果。
- 依赖已退出事实的角度线索立即停止参与后续问题和日志；新的线索在重新理解成功后再进入成果。
- 用户说明“这是真的，但不是我想聊的重点”时，事实继续作为必要上下文，后续探索停止围绕它展开。
- 用户后来重新选择该内容为重点时，最新关注选择生效，事实无需重复保存。
- 不同角度可以形成互补理解，AI不强行把它们合并成单一解释。

### 11.5 事件成稿后的修改

事件日志生成后，访谈内容和内部理解保持冻结。用户通过编辑事件日志改变最终呈现；重新保存后的日志成为当天完整日志的新来源。

## 12. 四个自我探索角度

### 12.1 共同能力协议

每个角度都必须具备：

1. 清楚的用户目标。
2. 适用事件和不适用场景。
3. 一组可选择的探索路径。
4. 通常一至两问、最多三问的中度节奏。
5. 一条自然、可写进日志的结果线索。
6. 深度陪伴边界。
7. 事实证据与越界检查。
8. 正例、反例和验收样例。

所有角度共同遵守：

- 只看当前事件。
- 用户选择角度，AI不推荐。
- 客观事实可以在角度之间共享。
- 不同角度的解释分别保留。
- 一次事件可以依次探索多个角度。
- 已聊过角度退出后续可选集合。
- 用户无需额外确认AI形成的自然线索。
- 用户纠正随时生效。
- 新角度需要经过产品策划、理论依据、能力协议和验收后加入固定集合。

### 12.2 理解感受

#### 用户为什么选择

用户知道这件事对自己有影响，希望更准确地看见当时和现在的感受，以及这些感受连接着什么。

#### 适用范围

- 开心、轻松、满足等积极感受。
- 委屈、愤怒、焦虑、失落等困难感受。
- 同时存在的混合感受。
- 暂时说不清、只感到身体或能量变化的状态。

#### 可探索方向

- 识别主要感受。
- 身体、精力和紧张程度的变化。
- 事件前后感受怎样变化。
- 两种感受怎样同时存在。
- 哪个时刻触发了感受。
- 感受连接着怎样的在意、需要或边界。

#### 中度复盘完成标准

用户已经说清一项感受或身体状态，并能和当前事件中的一个具体时刻建立联系。用户经过一个替代问法仍然说不清时，“现在还分辨不出来”也可以成为诚实结果。

#### 深度边界

深度陪伴可以继续理解感受变化、重要需要和边界。它保持自我探索语气，不承诺治疗、情绪平复或症状改善。

#### 日志线索示例

“这次让你一直放不下的，是临时变化带来的失去准备感；你很在意自己能提前知道并参与安排。”

#### 越界示例

- 将一次紧张解释为焦虑症。
- 从一次委屈推断童年经历。
- 把情绪归结为固定人格。

### 12.3 理清想法

#### 用户为什么选择

用户希望把当时脑中的判断、假设和衡量标准说清楚，理解自己为什么会这样看待这件事。

#### 适用范围

- 对一件事反复琢磨。
- 对自己的决定仍有疑问。
- 想确认原来的判断是否站得住。
- 发现自己可能带着某种期待或默认假设。

#### 可探索方向

- 当时最直接的念头。
- 隐含假设和期待。
- 判断依据与比较标准。
- 这件事触动的价值偏好。
- 另一种可能解释。
- 当前事件中呈现的思考线索。

#### 中度复盘完成标准

形成一条关于当前判断及其依据的线索。结果可以是确认原判断、补充判断条件或更新原有看法，产品不要求用户改变立场。

#### 深度边界

AI可以提供有证据支持的另一种解释，并清楚表达为可能性，交给用户判断。一次事件只形成当前思考线索，稳定信念需要跨事件证据。

#### 日志线索示例

“你仍然觉得调整方案本身可以商量，你更坚持的是重要协作应该提前沟通，让参与者有准备空间。”

#### 越界示例

- 把不同意见写成用户认知错误。
- 强迫用户得到“想开了”的结论。
- 用一次判断定义用户的世界观。

### 12.4 梳理关系

#### 用户为什么选择

用户希望理解一段互动中发生了什么，自己期待怎样的回应、位置和边界。

#### 适用范围

- 获得支持、理解、陪伴或信任。
- 表达没有被听见。
- 对角色、责任或期待感到模糊。
- 信任、互惠、边界或自主性受到影响。
- 冲突、修复和群体归属。

#### 可探索方向

- 对方提供了怎样的支持或回应。
- 自己表达了什么，对方理解到了什么。
- 双方对关系和角色有什么期待。
- 信任、互惠和边界发生了什么变化。
- 冲突真正触动的是哪一层关系感受。
- 自己在个人、团队或群体中的位置感。

#### 中度复盘完成标准

形成一条关于关系理解、期待或边界的当前线索。它需要回答用户在这段互动里真正重视什么。

#### 深度边界

深度陪伴继续服务于关系理解。具体沟通方案和行动计划进入用户自主决定范围。涉及他人动机时，AI只能给出多个可能性供用户核对。

#### 日志线索示例

“你在意的不只是方案变了，还在意自己有没有被当成共同参与决定的人。”

#### 越界示例

- 断言对方故意忽视用户。
- 给对方贴人格标签。
- 直接替用户设计沟通话术和关系决策。

### 12.5 复盘行动

#### 用户为什么选择

用户希望看清自己在事件中想实现什么、做了什么选择、哪些地方有效、哪里受阻，以及下一次愿意怎样尝试。

#### 适用范围

- 结果顺利，想知道哪些做法值得保留。
- 结果普通，想理解当时的选择和取舍。
- 结果不理想，想找到一个自己能够调整的部分。
- 当前目标本身还不够清楚。

#### 可探索方向

- 当时真正想达到的结果。
- 做出的选择和放弃的选项。
- 已经有效的行动或条件。
- 主要阻力和卡点。
- 自己能够调整的小块。
- 用户自主提出的下一次尝试。

#### 中度复盘完成标准

以下任一项形成清楚、可信的结果即可收束：目标更清楚、选择与取舍被看见、有效条件被识别、主要阻力被看见、可调整部分被识别、用户提出一个愿意尝试的动作。

#### 深度边界

AI通过提问、比较和澄清帮助用户生成自己的选项。用户明确询问建议时，AI说明会继续帮助他梳理条件和选择，并把最终方案交还给用户。

#### 日志线索示例

“这次最值得保留的是先搭框架再补细节，它让你在时间紧的时候仍然能稳住主线。”

#### 越界示例

- 直接告诉用户下一步应该做什么。
- 把复盘写成检讨、任务清单或绩效计划。
- 用结果不理想证明用户能力不足。

## 13. AI 对话体验

### 13.1 每轮回复结构

正常一轮使用同一回复组中的两条 AI 内容：

1. 自然理解：一至两句，说明AI听见了什么、当前关注什么。
2. 自然回应：一条回应、一个问题或一段收束。

两条内容使用相同视觉层级，共享纠正理解、换问法和反馈入口。自然理解承担“让用户知道AI怎样接住了自己”的作用，不能写成第二个问题，也不能只复述原话。

自然理解可以包含用户原话支持的整理，以及最多一个带可能性语气的新推测。新推测需要与系统保存的待确认命题保持一致；用户执行向前操作后，该命题进入事件事实。界面保持现有自然理解样式，不增加确认提示。

### 13.2 提问标准

- 一次只问一个清楚问题。
- 问题必须服务于当前事件和当前角度。
- 优先使用用户已经说出的词和具体时刻。
- 用户已经明确回答“没有”时，换一个更低压力的具体锚点。
- 用户说看不懂、太抽象或换一个时，使用更具体、更容易回答的问法。
- 已经形成有效线索时及时停止。

### 13.3 回应标准

- 用户只是想表达时，AI可以回应和整理，无需每轮都提问。
- 用户补充内容时，先吸收内容，再决定是否还有增量问题。
- 用户纠正时，明确说明最新理解。
- 用户拒绝继续时，停止追问并展示可执行入口。
- 用户提到另一事件时，保持当前事件边界。

### 13.4 用户可见边界

对话和日志中排除：

- 内部状态、槽位、置信度和流程判断。
- 理论名称和模型推理过程。
- 心理诊断和人格分类。
- 归责、道德评价和强制行动要求。
- 当前事件无法支持的稳定结论。

## 14. 事件日志产品规格

### 14.1 成果结构

事件日志由三部分组成：

1. 可编辑短标题。
2. 完整、自然的事件叙事。
3. 可选的“我看见的”。

### 14.2 不同交流深度的成稿

#### 轻量记录

- 保留发生了什么、用户怎样感受到这件事等已有信息。
- 内容缺少可靠自我线索时，只生成事件叙事。
- 不补写意义、规律或行动启示。

#### 中度复盘

- 事件叙事保持完整。
- “我看见的”收录实际形成的角度线索。
- 未聊过或材料不足的角度不出现。

#### 深度陪伴

- 沿用相同结构。
- 允许线索带入更充分的判断过程和用户证据。
- 保持一篇事件日志的整体感，避免写成咨询报告。

### 14.3 写作要求

- 采用贴近用户表达的自然中文。
- 优先使用第一人称，让日志像用户自己的记录。
- 事件经过和自我线索区分清楚。
- 标题保持简洁、自然，继续沿用不超过 16 个字的治理标准。
- “我看见的”使用自然段或简短条目，不显示内部角度字段。
- 不编造对话、动机、结果和情绪。
- 不添加建议、口号和抽象升华。

### 14.4 生成、编辑与保存

- 一件事只生成一篇事件日志。
- 第一次生成成功后，事件访谈结束。
- 生成结果首先进入草稿。
- 用户可以修改标题和正文。
- 离开工作区前自动暂存未完成编辑。
- 用户点击保存后进入当天正式成果，日志书页沿用现有保存完成体验。
- 已保存日志重新编辑后进入待保存状态；再次保存后更新当天来源。
- 日志只保留当前版本，MVP不提供历史版本和回滚。

### 14.5 生成失败

- AI整理失败时，可以使用已确认事件内容和角度线索形成基础版本。
- 基础版本也要通过事实忠实和越界检查。
- 基础版本合格时正常打开日志工作区。
- 基础版本缺乏可信材料时，事件保持在生成前检查点，展示失败原因和重试入口。

## 15. 今日日志与当天完整日志

### 15.1 今日日志概况

右侧面板继续使用三个概况：

| 概况 | 新语义 |
|---|---|
| 待继续 | 当前活动事件数量与待保存事件日志数量 |
| 已完成 | 当天已保存事件日志数量 |
| 完整日志 | 未生成、可汇总、草稿、已保存、需更新 |

### 15.2 事件列表

- 只展示当天真实存在的活动事件和事件日志。
- 按用户记录顺序排列。
- 活动事件显示事件摘要和“继续记录”。
- 事件日志草稿显示标题或摘要和“继续编辑”。
- 已保存事件日志显示标题和“查看日志”。
- 屏幕空间不足时沿用面板内部滚动。
- 退出且未成稿的事件不进入成果列表。

### 15.3 完整日志入口

| 当天成果 | 入口行为 |
|---|---|
| 没有已保存事件日志 | 完整日志入口不可用，并提示先完成一篇事件日志 |
| 只有一篇已保存事件日志 | 入口直接打开这篇事件日志 |
| 两篇及以上，尚未生成完整日志 | 显示“生成日志” |
| 完整日志来源有更新 | 显示“更新日志” |
| 完整日志已经就绪 | 显示“查看日志” |

### 15.4 多事件完整日志结构

多事件完整日志包含：

1. 可编辑的当天标题。
2. 按记录顺序原样保留的事件日志全文。
3. 可选的“今天看见的自己”。

事件正文在整合时保持原文，AI只负责生成最后的当天线索。

### 15.5 当天线索

- 单个事件的线索可以作为材料。
- 新的跨事件联系至少需要两件事共同支持。
- 使用“今天暂时看见”“这几件事里都出现了”等阶段性表达。
- 证据不足时省略整节。
- 不形成长期人格、稳定模式和人生方向结论。

### 15.6 来源变化与更新

- 完整日志只读取当前已保存的事件日志。
- 新事件日志保存、既有事件日志重新保存或来源退出可用状态时，完整日志标记“需更新”。
- 存在尚未重新保存的来源事件日志时，更新入口提示用户先完成事件日志，避免遗漏正在编辑的事件。
- 用户点击更新后，按最新来源直接重新整理并打开完整日志工作区。
- 更新会替换完整日志中此前的手动编辑，入口附近明确提示这一结果。
- 用户修改更新后的完整日志时，完整日志进入草稿；重新保存后成为当天最新成果。

## 16. 日历、历史与旧数据

### 16.1 月视图

- 新事件日期显示已保存事件日志数量。
- 当天完整日志已保存时显示轻量完整状态。
- 当前活动或草稿状态保持轻提示，不挤占日期主体。
- 未来日期继续使用待到来语义。

### 16.2 周视图

- 每天卡片展示事件日志数量、待继续状态和完整日志状态。
- 主动作按以下优先级解析：继续记录、继续编辑、查看日志、开始记录。
- 当天只有一篇已保存事件日志时，“查看日志”直达该事件日志。

### 16.3 日视图

- 展示当天事件列表。
- 每项说明正在记录、待保存或已保存。
- 提供继续记录、继续编辑、查看日志和开始记录。
- 两篇及以上已保存事件日志时展示完整日志入口和状态。

### 16.4 历史五维记录

- 历史五维会话、维度日志和当天完整日志继续可读。
- 历史记录采用原有维度名称和展示结构。
- 新事件数据与旧五维数据使用各自口径。
- 新旧数据不共同生成关系线索、角度统计和长期模式。
- 切换日期时依据该日期的数据版本进入对应阅读体验。

## 17. 边界、异常与恢复体验

### 17.1 用户不想继续

- AI停止继续提问。
- 记录或中度阶段展示生成或退出入口。
- AI不因槽位、轮次或理论目标继续施压。

### 17.2 用户说问题看不懂

- 保持当前事件和角度。
- 使用更具体、句式更简单的问题。
- 连续多次修复后改为低压力选择，避免反复换同一问题。

### 17.3 用户纠正理解

- AI先说明最新理解。
- 当前事件事实和角度线索同步采用纠正。
- 已经被否定的解释停止参与后续日志。
- 纠正目标唯一时直接生效；目标存在歧义时只澄清一个具体冲突点。
- 事实修订成功后先保持有效，再生成AI回应；回应失败时，继续生成只补齐回应。
- 用户纠正较早的AI理解时，从对应位置形成新的对话路径；原路径完整保留，当前成果只采用新路径。
- 纠正事实真伪与调整访谈重点分别处理，真实但非重点的信息可以保留为事件上下文。

### 17.4 用户提到另一件事

- AI自然接住。
- 当前访谈继续保持原事件。
- 另一事件不进入当前成果。
- 需要时提示用户可以在当前事件成稿后使用“记下一件”。

### 17.5 页面刷新或离开

- 当天活动事件恢复到原来的对话阶段和当前角度。
- 输入框草稿和已经提交但尚未完成回复的内容继续沿用现有恢复体验。
- 已成稿事件保持锁定，不重新开放访谈。

### 17.6 用户回复提交失败

- 用户原话优先保留。
- 页面展示清楚的原因、解决方式、错误码和继续生成入口。
- 继续生成回到同一轮，不重复展示用户原话。

### 17.7 AI回应失败

- 已经完成的自然理解继续保留。
- 已经由用户向前操作正式采用的AI理解继续作为事件事实，不随后续生成失败回退。
- 已经成功提交的事实纠正、否定、撤回和重点调整继续有效。
- 事实识别失败，或可见自然理解与待确认命题不一致时，本轮只保留用户原话；本轮事实、AI理解和回应等待继续生成后一次性生效。
- 用户可以继续生成目标回应。
- 事实和角度成果不会因重试重复累积。

### 17.8 日志生成失败

- 先尝试安全基础版本。
- 仍然失败时返回生成前检查点。
- 当前事件、用户原话和角度成果完整保留。

### 17.9 完整日志更新失败

- 当前完整日志保持原样可读。
- 状态继续显示“需更新”。
- 用户可以重试，不会得到半篇更新结果。

## 18. 产品指标

### 18.1 核心结果指标

| 指标 | 统计定义 | 观察目的 |
|---|---|---|
| 事件日志生成率 | 已生成事件日志的事件数 / 已产生首条有效回复的事件数 | 用户能否完成单事件闭环 |
| 事件日志保存率 | 已保存事件日志数 / 已生成事件日志数 | 成果是否值得保存 |
| 角度有效线索率 | 形成可信自然线索的角度次数 / 用户选择角度次数 | 中度复盘是否有价值 |
| 第二事件开启率 | 同一天开启第二事件的用户日 / 已完成首篇事件日志的用户日 | 多事件流程是否自然 |
| 完整日志生成率 | 生成完整日志的多事件用户日 / 拥有两篇及以上已保存事件日志的用户日 | 当天汇总是否有价值 |
| 完整日志保存率 | 已保存完整日志数 / 已生成完整日志数 | 当天成果是否值得确认 |
| 日志再次打开率 | 后续再次查看事件或完整日志的成果数 / 已保存成果数 | 记录是否具有持续价值 |

### 18.2 过程指标

- 从首条有效表达至第一检查点的用户回复轮次。
- 中度复盘平均问题数及达到三问上限的比例。
- 用户选择四个角度的分布。
- 用户在第二检查点继续深入、选择另一角度和直接生成的比例。
- 理解纠正率、问题修复率和退出事件率。
- 隐式确认事实占比，以及隐式确认后两轮内被纠正或撤销的比例。
- 事实修订成功率、目标歧义澄清率和互斥事实澄清完成率。
- 事实被降为非重点和重新恢复为重点的比例。
- 回复失败后的继续生成成功率。
- 完整日志标记“需更新”后的更新完成率。

### 18.3 质量护栏

- 事件串线率。
- 用户纠正失效率。
- 已被替代、否定或撤回的事实继续进入问题或日志的比例。
- 被用户拒绝的AI推测再次获得事实资格的比例。
- 存在未解决事实冲突时仍进入角度或日志生成的比例。
- AI新推测超过单轮一个的比例。
- 隐式确认事实缺少有效向前操作来源的比例。
- 隐式确认事实被后续纠正或从日志删除的比例。
- 重复追问率。
- 过早收束率。
- 过度追问率。
- 用户明确停止后继续提问率。
- 日志事实偏差率。
- 角度越界率。
- 事件日志被完整日志遗漏或改写的比例。

### 18.4 上线初期指标策略

- 原话丢失、重复成果、事件串线、纠正失效和日志虚构属于发布硬门槛。
- 用户行为指标在全量后先观察七天，建立新流程基线。
- 首次发布不使用内部测试完成率代替真实用户目标。
- 七天基线形成后，再确定后续版本的完成率与留存目标。

## 22. 文档维护规则

1. 本文档是事件中心 MVP 的产品事实源。
2. 产品目标、主流程、角度边界、日志关系和用户可见状态发生变化时，先更新本文档。
3. 技术讨论中发现产品假设无法成立时，回到对应章节重新决策，再继续技术方案。
4. 每个技术阶段的文档需要引用本文档中的相关章节和验收编号。
5. 具体实现事实只进入技术文档、架构文档和运行手册，避免污染产品语义。
6. 新增产品范围需要明确属于 MVP、后续版本或独立专项。
