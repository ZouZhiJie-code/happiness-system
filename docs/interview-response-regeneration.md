# Daily Light 按意图重新生成

## 1. 背景与目标

生成式访谈会出现理解偏差、表达过深、提问抽象和方向重复。Daily Light 的问题还会继续影响结构化理解、访谈阶段和日志证据，因此重新生成需要同时修复用户感受到的问法与系统采用的访谈路径。

功能目标采用“访谈修复成功率”：新版本成为当前采用版本，用户下一条回复形成有效内容，期间未再次换问法、切回旧版本、点踩或暂停。

## 2. 用户体验

- 正式追问的赞踩操作行提供“换个问法”图标。
- 用户可选择更简单、更具体、换角度、再深入、问轻一点。
- 意图浮层通过触发按钮锚定：开场和前几轮优先向下展开，靠近底部时自动向上翻转；上下空间都有限时约束在可视区内滚动，并跟随页面滚动、窗口变化和移动端键盘重新定位。
- “再深入”根据五个维度的已有证据条件展示。
- “纠正理解”提交后立即收起输入卡片，显示“已收到，正在重新理解”的反馈，再保存为可见用户消息并重新处理结构化理解。
- 纠正理解输入支持 `Enter` 提交、`Shift + Enter` 换行，并在中文输入法组合阶段保留回车选字。
- 选择五种换问法后，浮层立即关闭；原回复气泡原位显示加载与最终替换内容。操作区保留静态禁用入口，加载图标和文案只在回复气泡内出现。
- 版本箭头采用 `22px` 圆角 Chevron，桌面点击区为 `36px`、触屏点击区为 `44px`；相邻版本在可视、悬停、聚焦或按下时预加载，已缓存版本优先即时呈现。
- 每个正式回复组保存一个原始版本和两个替代版本。
- 历史回复换问法前会确认开启新的访谈版本，后续原对话完整保留。
- 生成日志后，已经存在后续回答的历史问题停止换问法与版本切换；最新未回答问题继续开放。
- 三个版本用完后，操作区承接换个片段、整理当前内容、先停一下和纠正理解。

旧会话保持线性体验。新会话从创建时写入 `conversationSchemaVersion = 2`。

## 3. 活动路径

前端继续使用根会话 ID。根会话通过 `activeBranchSessionId` 指向当前采用分支。

每个分支只保存分叉后的消息。读取层沿 `parentSessionId` 向上解析，在 `forkMessageSequence` 处裁剪父路径，再拼接当前分支消息。页面恢复、访谈 Prompt、日志生成、日历和分析统一读取这条活动路径。

每条正式追问写入 `InterviewBranchCheckpoint`，其中包含当时的会话阶段、轮次、活动事件、事件结构化理解、进度和待决策状态。历史换问法从对应检查点恢复，保证分支状态与目标问题之前一致。

## 4. 生成与筛选

问法调整先转换 `AssistantQuestionSpec`：

- 更简单：保留目标，降低语言负担。
- 更具体：保留目标，加入可回答的具体锚点。
- 换角度：优先选择尚未覆盖且未被拒绝的目标。
- 再深入：在证据充分时推进到下一层目标。
- 问轻一点：保留核心目标，缩小回答范围。

一次模型调用返回三个结构化候选。模型只负责每个候选的 `thinkingSummary` 与 `question`；`questionSpec`、`stateUpdate` 和 `meta` 由服务端规则统一补齐。候选接口兼容 `{ candidates: [...] }` 与顶层数组两种封装，但都必须恰好包含三个候选。服务端检查单一问题、浅色理解与追问一致、版本差异、内部术语、意图匹配、已拒绝方向和回答压力，再采用确定性评分最高的候选。候选全部未通过时使用对应维度和意图的安全模板。

候选生成完成前保留原回复。页面只展示最终采用候选。

## 5. 可靠提交与并发

- `InterviewUserTurn` 保存动作、目标消息、调整意图和基础分支。
- `clientTurnId` 提供幂等重放。
- 浏览器按根会话和活动分支保存待提交动作。
- 服务端确认接收后通过 SSE `turn` 事件返回持久化记录。
- 失败或中断后使用同一个 `clientTurnId` 继续生成。
- 服务端确认前中断时，浏览器重放原动作；确认后中断时调用 `resume_turn`。
- 活动分支变化后，基于旧分支的请求返回 `INTERVIEW_BRANCH_OUT_OF_DATE`。
- 分支切换、用户回复、换问法和日志生成共享活动路径约束。

## 6. 质量记录

`AIResponseRegeneration` 记录：

- 原消息、原 Trace、新消息和新 Trace。
- 用户选择的意图。
- 候选内容、检查结果和最终候选。
- 状态、耗时与错误码。
- 是否获得有效回答、再次换问法、切回、点踩或暂停。

管理员 AI 质量工作台展示最近 30 天的修复成功率、获得回答率、连续换问法率、切回率、失败率、安全兜底率和 P95 等待时间，并按五类意图、五个维度和原始问题类型拆分使用量与成功率。
