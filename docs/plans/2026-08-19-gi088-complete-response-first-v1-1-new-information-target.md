# GI-088｜完整回应优先 v1.1 新信息目标

- 文档职责：当前专项
- 文档状态：已确认·实施中
- 最后核验：`2026-08-19`
- 权威入口：[生成式访谈重构总 Map](../generative-interview-refactor-map.md)

## 1. 为什么继续这一轮

完整回应优先 v1 已证明一次调用可以稳定、快速地返回完整可见回应：八题技术与正文合同 `8/8` 有效，中位耗时 `3087ms`、最长 `6976ms`，`1280` Token 上限未触发截断。

当前质量失败集中在生成前的目标选择：

- `RPR-REAL-22`：用户表达负担但未要求停止，回应收住了追问，同时增加了用户未提供的前提，也没有留下低负担的继续入口；
- `RPR-REAL-21`：用户刚给出明确结论，回应又复述同一结论，没有进入新的信息层。

这两题共同说明，模型需要先决定“本轮还值得了解什么新信息”，再组织承接、理解和问题。继续修改措辞无法稳定解决目标选择问题。

## 2. 唯一变化

- 候选身份：`2026-08-19.gi088-complete-response-first-v1-1-new-information-target`
- 运行身份：`2026-08-19.gi088-complete-response-first-v1-1-quality-v1`
- 唯一主要因素：生成完整回应前，先从完整对话中选择一项尚未回答、能够带来实际新进展的信息目标。

具体方法：

1. 先识别用户本轮意图与控制要求；
2. 再核对助手问过什么、用户已经完整回答什么；
3. 选择一个尚未回答的新增信息目标；
4. 整条回应围绕这一目标完成承接与推进；
5. 用户明确继续或深挖时进入一个新层次；
6. 用户表达负担但未要求停止时，降低回答负担并保留一个容易接住的继续入口；
7. 每轮最多表达一处有原文依据、可纠正的解释，并最多提出一个主问题；
8. 用户明确停止、少问、结束或直接整理时，直接落实要求并保持零问题。

问号数量继续只承担观察职责。语义是否重复、目标是否真正新增、解释是否有依据，由 Codex 原文初评与产品负责人裁决。

## 5. 质量门与产品裁决

每题固定按以下顺序交付：

1. 完整相关用户与 AI 原文；
2. 本次实际模型输出；
3. 耗时、Token、结束原因和技术状态；
4. Codex 对新增信息目标、重复、忠实度、推测、负担和意图兑现的初评；
5. 产品负责人最终裁决。

质量 Go 条件：

- `8/8` 技术与正文合同有效；
- 明确停止、纠正后继续、负担控制和长上下文硬场景全部 `pass`；
- 全体 `0 fail`，最多 `1 minor`；
- 中位耗时不高于 `6s`，单例不高于 `15s`；
- 已回答内容不会被当作新的追问目标；
- 继续或深挖时形成新的相关推进；
- 非停止负担场景保留一个低负担继续入口；
- 新增解释保持有依据、可纠正且最多一处。
