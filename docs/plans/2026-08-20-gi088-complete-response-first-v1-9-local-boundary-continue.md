# GI-088｜完整回应优先 v1.9 局部边界与继续优先级

## 1. 为什么继续

v1.8 已在真实 Preview 中修复“跳过上一题后继续深挖”：AI 放下旧问题，选择了新的关系期待层。相邻表达“这个方向我现在也不想回答，换个方向继续聊”仍被识别为第一检查点，回应只保存原话，未继续对话。

这次失败由明确的用户控制冲突造成。“不想回答这个方向”限定的是当前问题，“换个方向继续聊”给出了下一步动作。系统需要同时尊重局部边界和继续意图。

## 2. 已确认事实与产品判断

| 类别 | 当前结论 |
|---|---|
| 已确认事实 | v1.8 Preview 本轮 `4` 次，家族累计 `11/15`，剩余 `4`；核心三轮 `pass`，相邻控制题 `fail` |
| 已确认事实 | 失败回合输出 `responseKind=checkpoint`，会话进入 `checkpoint_one`；Production 使用 `event_centered + baseline` |
| 产品判断 | “这个方向不想回答＋换方向继续”表示跳过当前问题并继续；“今天不想继续聊／先到这里”表示结束 |
| Codex 评估 | 根因是旧显式停止规则只看“不想回答”，没有处理范围限定和同句正向继续动作 |
| 待验证假设 | 先确定用户控制范围，再生成正文，可以稳定兑现局部拒答＋继续，同时保持真正停止零提问 |

## 3. 单一变化

新候选身份：`2026-08-20.gi088-complete-response-first-v1-9-local-boundary-continue-priority`。

本轮只修复用户控制范围：

1. 当前句同时包含局部拒答和明确继续／换方向时，判定为“跳过当前问题并继续”。
2. 明确结束本轮且没有正向继续动作时，判定为“整轮停止”。
3. 将这一确定性控制结果提供给模型；模型负责从有效原文选择新的方向并自然回应。
4. 程序继续校验停止时零问题、继续时不得被投影为停止或检查点；程序不判断新方向是否自然、有价值。

## 4. 冻结因素

- 一次调用独立交付完整可见回应；后台调用只整理事实与纠正。
- `deepseek-v4-pro`、Thinking disabled、Temperature `0.2`、`maxTokens=1280`、硬超时 `45s`。
- v1.8 的明确推进方法、完整上下文、页面气泡、后台 v1.7、持久化、幂等和恢复保持不变。
- Production 在产品负责人验收通过前保持 `event_centered + baseline`。

## 5. 验证门与剩余预算

1. 自动验证覆盖：局部拒答＋继续、局部拒答＋换方向、真正停止、负担表达但继续、普通问答。
2. 完成专项、全量测试、类型、Lint、两套 Prisma、Production build、文档和差异检查。
3. 部署新的隔离 Preview。
4. 剩余最多 `4` 次可见调用：优先重放局部拒答＋换方向；通过后验证真正停止和关系表达，最后保留一次相邻控制。
5. 每个语义结果继续按“完整相关原文 → 实际 AI 输出 → Codex 初评 → 产品负责人裁决”交付。

质量门：局部边界继续、明确停止、关系表达全部 `pass`；整体零 `fail`，最多一个 `minor`；单例不高于 `15s`，硬超时 `45s`。速度理想目标仍为约 `5～6s`，当前 Preview 的 `12～15s` 作为独立发布风险记录。

## 6. 停止点与发布边界

任何核心控制场景 `fail` 时停止剩余调用并保持 Production baseline。隔离 Preview 语义验收通过后，执行 Production 快照、备份和回退准备；产品负责人确认真实输出通过后，才切换 Production 并运行线上回归。
