# GI-088｜完整回应优先 v1.4 有依据的意图兑现

- 文档职责：当前专项
- 文档状态：已确认·实施中
- 最后核验：`2026-08-20`
- 权威入口：[生成式访谈总 Map](../generative-interview-refactor-map.md)

## 1. 为什么继续

v1.3 已经证明首个调用输出纯文本完整回应可以稳定达到约 5 秒：八题全部完整返回，中位 `3731ms`、最长 `4956ms`，最高 completion `93/1280`。当前失败集中在生成方法：模型会在正式选择新信息目标前先补出听起来合理的原因或动机，随后又可能询问对话中已经回答的信息。

本轮继续使用单一可见回应负责人。当前案例降为完整回归集中的最后一题，方法必须同时改善第三方原因推断、用户动机推断、已答信息重复和明确意图兑现，避免围绕单个案例设计。

## 2. 本轮选择

候选身份：`2026-08-20.gi088-complete-response-first-v1-4-grounded-intent-owner`

运行身份：`2026-08-20.gi088-complete-response-first-v1-4-grounded-intent-owner-quality-v1`

唯一语义因素是把生成顺序改成“意图与依据先行”：

1. 先识别用户最新一轮要系统完成的动作：承接、继续、深挖、停止、切换或整理。
2. 在完整有效对话中盘点用户已经明确给出的事实、感受、触发、解释与纠正。
3. 只选择一个仍未回答、答案会改变理解或下一步的新信息目标；找不到高价值目标时允许自然回应或结束。
4. 写正文前检查每一处新增理解：用户原文能够直接支持才可陈述；第三方原因、用户动机和心理目标缺少直接依据时省略，或作为本轮唯一可纠正问题。
5. 写问题前先用完整原文作答；能够回答则删除并重新选择。用户已经明确说出某类感受时，不再泛问同一类感受。
6. 用户要求继续或深挖时，用一句短过渡进入新层；上一条已经承接纠正时，不再完整复述纠正。

## 3. 程序责任修正

- 明确停止后仍提问继续作为硬错误。
- 普通场景的问号数量只记录观察。程序从连续问句中提取一个回答焦点片段，不判断这些问句是否语义同焦点。
- 自然度、问题增量、推测依据和用户负担继续由模型方法、Codex 原文初评和产品负责人裁决。
- 这项修正恢复既有责任边界，单独记录为 v1.3 程序缺陷；不计入 v1.4 的语义变化。

## 4. 固定条件与预算

- `deepseek-v4-pro`、Thinking disabled、Temperature `0.2`、`maxTokens=1280`。
- 完整上下文、同一 `3` 条开发题＋`5` 条冻结回归题、单次调用、45 秒硬超时保持固定。
- 新预算 `8` 次，并发 `1`；重试、恢复和回退均为 `0`。
- 普通内容问题完成整批后统一判断；严重隐私泄漏、忽略明确停止、连续两次技术失败或预算失控立即停止。

## 5. 质量门

- 八题均 HTTP 200、`finishReason=stop`、正文非空、单例不高于 `15s`、无 Token 截断。
- 每题按“完整相关原文 → 实际输出 → 耗时与 Token → Codex 初评 → 产品负责人裁决”交付。
- 五个硬案例全部由产品负责人判为 pass；全体零 fail、最多一个 minor。
- 质量通过后才接入第二次后台状态调用和隔离 Preview；后台结果不能追加、修改或阻断已显示正文。
- 页面验收通过后完成全量工程验证、提交、推送、Production 切换与 baseline 回退验证。
