# GI-088｜完整回应优先 v1.6 后台状态与上线准备

- 权威入口：[生成式访谈总 Map](../generative-interview-refactor-map.md)

## 1. 为什么进入这一阶段

v1.6 已证明首个模型调用能够在约五秒内形成一条完整回应：八题 `8/8 technical_valid`，中位 `2915ms`，Codex 初评 `7 pass / 1 minor / 0 fail`。唯一关系题仍等待产品负责人裁决，因此可见质量继续保持待确认。

当前生产链路还把用户原话、可见回应、事实整理和状态提交放在同一整轮里。v1.6 的纯文本调用只稳定拥有可见回应，现有最小投影不会完整提取本轮用户事实。直接上线会形成两个风险：长对话离开最近消息窗口后缺少事实记忆；后台失败或并发写入可能覆盖下一轮状态。

本阶段只验证一个架构选择：首个调用冻结完整可见回应，第二个调用只在后台整理用户明确表达的事实与纠正。第二个调用永远不追加、改写或撤回用户已经看到的文字。

## 2. 产品与程序边界

### 可见回应

- 继续使用冻结候选 `2026-08-20.gi088-complete-response-first-v1-6-contrastive-coverage`。
- 模型、Thinking disabled、Temperature `0.2`、`1280` Token、纯文本和单气泡均保持不变。
- v1.6 产品质量裁决独立保留；后台状态的通过不能替代可见质量 Go。

### 后台状态

候选身份：`2026-08-20.gi088-complete-response-first-v1-6-background-facts-v1`

运行身份：`2026-08-20.gi088-complete-response-first-v1-6-background-facts-quality-v1`

后台模型只输出：

- 用户本轮明确表达的事实、感受、判断、偏好或边界；每条都带当前用户原话中的逐字依据；
- 用户是否明确修订了现有事实；若修订，只能引用当前分支仍有效的事实标识；
- 无可靠新增时允许空事实、无纠正。

后台模型不输出可见回应、问题、开放方向、心理推断或第三方结论。当前问题和页面下一步继续由已经冻结的可见回应确定性投影产生。

程序负责：来源存在、逐字依据、当前分支有效性、回合身份、每回合最多两次模型调用、一次后台预算、顺序应用、幂等、超时、失败记账、隐私和写入权。事实摘要是否忠实、纠正目标是否合理继续由 Codex 和产品负责人依据原文判断。

## 3. 运行与恢复设计

1. 可见回应与最小对话状态先原子提交，用户原话和气泡由此获得稳定保存。
2. 同一事务建立一个持久的后台状态任务；任务与 `clientTurnId`、用户消息、可见回复、分支和输入指纹绑定。
3. 页面回应完成后触发一次后台调用；调用前先持久化“已开始”，因此进程中断后不会重复消费。
4. 后台结果先保存，再按消息顺序应用。较晚回合先返回时等待较早回合形成终态；较早回合超时或结果不确定时记录失败并允许后续回合继续。
5. 后台只增补事实或创建事实修订，不覆盖可见回复、当前问题和新一轮状态。来源消息已离开当前分支时，结果失去写入权并只保留技术记录。
6. 后台失败时保留原话、可见回应和可继续输入状态；页面可展示“回应已保存，整理稍后完成”的非阻断状态。自动恢复不再次调用模型。
