# GI-088｜完整回应优先架构重置

- 文档职责：当前专项
- 文档状态：已确认·实施中
- 最后核验：`2026-08-19`
- 权威入口：[生成式访谈重构总 Map](../generative-interview-refactor-map.md)

## 1. 为什么重置

v2.9 真实 CONTINUE 已证明当前主要问题集中在完整回应责任。用户明确要求继续深挖时，Low 重复上一轮已经承接的纠正，High 返回完整结果但没有覆盖判断、开放目标、问题或可见追加。两次调用纯时间为 `5852ms`，High 只使用 `89/4000` completion Token；速度、网络和截断均已排除。

Low 只负责承接、High 同时负责推进和状态的拆法会产生稳定协同成本：Low 倾向复述最安全的事实，High 倾向用空值避免合同错误。继续增加 High 审计字段会扩大填表负担，并继续围绕单例优化。

本专项停止 v2.10 式字段修补，回到一个用户价值：用户发送一轮内容后，在约五秒内收到一条忠实、自然、兑现当前意图并能继续对话的完整回应。

## 2. 当前选择

候选身份：`2026-08-19.gi088-complete-response-first-v1`

运行身份：`2026-08-19.gi088-complete-response-first-quality-v1`

唯一可见回应负责人由第一次模型调用承担：

- 一次生成完整自然回应；
- 同一回应可以承接、形成一处可纠正理解、提出一个共同回答焦点或自然结束；
- 纠正刚出现时承接一次；纠正已经承接后直接推进；
- 用户明确继续或深挖时，回应必须产生新的相关推进；
- 用户明确停止、少问或直接整理时立即落实控制；
- 已经由有效用户原文回答的信息不再重复询问；
- 用户明确表达的事实和感受可以自然转述；新增解释保持可纠正，缺少依据时省略；
- 问号数量只记录观察，不承担语义通过或拦截职责。

可见回应完成后冻结。首批生产候选复用现有 `one_call` 原子提交链路：同一次调用生成完整回复和最小内部状态，页面只显示完整回复。第二次后台模型调用暂不进入首版；将来若有明确质量收益，仍必须保持零可见写权限并使用独立身份验证。

离线第一门先用纯文本合同验证完整回应与提问策略，排除状态 JSON 对可见质量的干扰。通过后再接入最小状态合同，并重新运行同一代表性门，防止合同负担改变回应质量。

## 4. 代表性质量批次

本轮使用 `3` 条开发检查点与 `5` 条冻结回归检查点，共 `8` 条。当前 RPR-REAL-19 从开发首题移入冻结回归，只承担最终防回退职责。

| 顺序 | 场景 | 主要判断 |
|---:|---|---|
| 1 | 开发 `RPR-REAL-01` | 一个回答焦点下组织相关问题，避免机械按问号裁决 |
| 2 | 开发 `RPR-REAL-05` | 已有答案后选择真正的新入口，或自然交还继续权 |
| 3 | 开发 `RPR-REAL-11` | 把抽象表达转成具体、容易回答且不强加类别的入口 |
| 4 | 回归 `RPR-REAL-13` | 关系表达的自然转述与新增解释依据边界 |
| 5 | 回归 `RPR-REAL-22` | 区分事件烦躁与解释负担，仍提供低负担入口 |
| 6 | 控制反事实 `RPR-CF-03` | 用户明确停止时立即收住并保持零追问 |
| 7 | 回归 `RPR-REAL-21` | 长上下文中吸收已答信息、保持焦点和低负担 |
| 8 | 回归 `RPR-REAL-19` | 纠正后明确要求继续时产生新的相关推进 |

先完整运行三条开发题；普通质量失败不在题间修改候选，三题结束后统一归因。三题通过后冻结候选并一次性运行五条回归题。回归中的普通语义失败不提前终止批次。来源漂移、隐私泄漏、忽略明确停止或最新纠正、严重事实编造、预算失控或连续技术故障触发立即停止。

## 5. 评审与通过门

每题固定按以下顺序交付产品负责人：

1. 完整相关用户与 AI 原文；
2. 本次实际模型输出；
3. 耗时、Token、结束原因和技术状态；
4. Codex 对重复、忠实度、推测、问题增量和意图兑现的逐项初评；
5. 产品负责人最终裁决。

质量 Go 条件：

- `8/8` 技术与输出合同有效；
- 纠正、纠正后继续、明确停止、长上下文四个硬场景全部 `pass`；
- 全体 `0 fail`，最多 `1 minor`；
- 完整可见回应耗时中位数不高于 `6s`，单例不高于 `15s`；
- 不出现重复询问原文已经回答的同层问题；
- 不把新增动机、心理机制或具体体验写成用户事实。

## 6. 接入、验收与发布

纯文本离线质量 Go 后继续完成：

1. 复用现有 `one_call`，同一次调用生成完整回复与最小内部状态；
2. 只把完整回复写入 `naturalResponse`，`naturalUnderstanding` 留空，页面展示一个气泡；
3. 消息、状态、Trace 与轮次完成继续原子提交，提交成功后再发送可见结果；
4. 重新运行同一 `3＋5` 质量门，确认最小状态合同没有损害提问质量；
5. 验证原话先保存、`clientTurnId` 幂等、超时解锁、刷新恢复和迟到写入失效；
6. 在隔离 Preview 完成普通表达、纠正、继续、关系、停止和刷新恢复真人回合；
7. 产品负责人按真实页面体验验收；
8. 验收通过后执行 Production 发布、回读和回退验证。

Production 在产品验收前继续使用 `event_centered + baseline`。

## 7. 程序与模型边界

程序只判断来源、角色、权限、预算、超时、恢复、幂等、写入权、输出非空和内部字段泄漏。问题是否重复、理解是否自然、推测是否有依据、回应是否兑现用户意图，继续由模型方法、Codex 原文初评和产品负责人裁决承担。
