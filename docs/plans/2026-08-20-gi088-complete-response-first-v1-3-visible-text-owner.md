## 1. 为什么换方向

v1.2 在 Provider JSON 模式下 `4/8` 合同有效；v1.2.1 关闭 JSON 模式后 `0/8` 合同有效。两轮共 `16` 次都保持 HTTP 200、stop、15 秒内且远低于 Token 上限，失败集中在模型同时生成自然回应和状态 JSON 时的结构稳定性。

用户本轮真正需要的是一条及时、自然、忠实且能推进的完整回应。v1.3 让首个调用只负责这条纯文本，状态整理退出首屏关键路径。

## 3. 预算与验证门

- 新预算最多 `8` 次；开发 `3`、回归 `5`；并发 `1`；重试、恢复、回退 `0`。
- 八题均需 HTTP 200、`finishReason=stop`、非空纯文本、Thinking 关闭、单例不高于 `15s`、无 length。
- 明确停止必须零问题；其他回应允许零问题或一个共同焦点问题。自然度、忠实度、信息增量和回答负担由 Codex 与产品负责人根据原文判断。
- 普通语义失败完成整批后统一评审；连续两次技术失败、严重内部泄漏、忽略明确停止／纠正或预算失控立即停止。
- 硬案例全部由产品负责人判为 pass，总计零 fail、最多一个 minor，才进入页面接入。

## 4. 接入、验收与发布边界

- 离线质量通过后，把纯文本原样写入一个气泡，并验证刷新恢复、重复提交、超时、错误回退和历史消息兼容。
- 第二次后台状态调用单独记账；它可以失败并留下待整理状态，用户本轮回应保持可用。
- 隔离 Preview 最多 `15` 次，覆盖普通表达、纠正、纠正后继续、关系表达、负担／停止和刷新恢复。
- 产品负责人页面验收通过后切换 Production；保留 `event_centered + baseline` 一键回退，并完成线上冒烟与回退验证。
- 当前页面、Preview、提交、推送、部署和 Production 结果均待验证。
