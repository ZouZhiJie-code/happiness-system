# GI-088｜完整回应优先 v1.8 明确推进义务

- 文档职责：当前专项
- 文档状态：已确认·实施中
- 最后核验：`2026-08-20`
- 权威入口：[生成式访谈总 Map](../generative-interview-refactor-map.md)

## 1. 为什么继续优化

v1.6 的隔离 Preview 已完成 `7/15` 次可见调用。普通承接、纠正和停止场景可以工作；真实连续回合暴露出一个跨场景问题：用户已经明确要求“继续深挖”或已经点明“想聊这种差别”时，AI 仍会重复上一问题，或再次确认用户已经给出的讨论方向。

这会让用户感觉对话停在原地。当前应修复的产品问题是：用户已经给出推进动作时，完整回应要兑现这个动作，并进入一个原文尚未回答的新层。

## 2. 已确认事实与判断

| 类别 | 当前结论 |
|---|---|
| 已确认事实 | v1.6 Preview 技术链路通过；可见预算 `7/15`，剩余 `8`；Production 使用 `event_centered + baseline` |
| 已确认事实 | 连续深挖回合几乎逐字重复上一问题；关系表达回合再次询问是否讨论用户已明确指定的差别 |
| 产品判断 | “继续、深挖、换个方向、聊这个差别”等明确表达要转化为本轮动作，AI 直接执行，避免再次请求用户确认 |
| Codex 评估 | v1.6 Preview 质量门 No-Go；根因是明确推进意图仍被当成可确认内容，上一条未回答问题仍被当成可重复的开放目标 |
| 待验证假设 | 增加“明确推进义务”后，模型能跳过上一条未回答问题，选择有依据的新层，同时保持约 5 秒、忠实和低负担 |

## 3. 单一变化

新候选身份：`2026-08-20.gi088-complete-response-first-v1-8-explicit-progress-obligation`。

只增加以下模型方法：

1. 用户明确要求继续、深挖或换方向，并且没有回答上一条 AI 问题时，把上一问题视为本轮已跳过；回应不能重复、改写、缩窄该问题，也不能基于其某个选项继续追问。
2. 用户明确点名要讨论的对象或差别时，直接沿该方向推进；回应不能再次询问是否讨论它。
3. 从用户已经提供的完整原文中选择一个尚未回答、与当前主题有关的新层。若找不到有价值的新问题，可以给出一处有依据且可纠正的高层理解，并提供低负担继续入口。
4. 停止、少问、直接整理等用户控制继续优先执行。

## 4. 冻结因素与责任边界

- 可见架构仍为一次调用独立交付完整回应；后台调用只整理事实与纠正，不能修改可见气泡。
- 模型继续使用 `deepseek-v4-pro`；Thinking disabled；Temperature `0.2`；`maxTokens=1280`；单次硬超时 `45s`。
- 上下文、输出结构、页面气泡、后台 v1.7 来源对齐、持久化、幂等与恢复保持不变。
- 程序校验策略身份、预算、来源、权限、超时、写入权和幂等；问题是否真正进入新层继续由 Codex 和产品负责人依据原文判断。

## 5. 验证门与预算

1. 先完成候选单测、策略注册、Provider 配置、正式链路专项测试、类型检查、Lint、Production build、Prisma 和文档检查。
2. 部署新的隔离 Preview，Production 保持 baseline。
3. 剩余可见预算最多 `8` 次，优先验证：
   - 原失败连续链：背景表达 → 纠正 → 明确继续深挖；
   - 相邻表达：上一问未回答，用户要求换个方向继续；
   - 用户直接点名要聊某种差别；
   - 停止／少问控制回归。
4. 每例交付“完整相关原文 → 实际 AI 输出 → Codex 初评 → 产品负责人裁决”。
5. 普通质量问题完成代表性回归后统一看分布；忽略停止、事实编造、隐私泄漏、连续技术失败或预算失控时立即停止。

质量门：明确继续、纠正、关系表达和用户控制全部 `pass`；整体零 `fail`，最多一项 `minor`；可见完整回应中位不高于 `6s`、单例不高于 `15s`，技术硬超时仍为 `45s`。

当前本地工程结果：v1.8 专项 `95/95`、全量 `3673` 条通过，类型检查与两套 Prisma 有效；Lint `0` error、`45` 条既有 warning；Production build 通过并保留 `16` 条既有动态文件系统 warning。真实模型输出与 Preview 质量仍为待验证。
