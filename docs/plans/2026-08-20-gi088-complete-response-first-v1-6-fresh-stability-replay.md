# GI-088 v1.6 新案例稳定性复验

- 文档职责：当前专项
- 文档状态：已确认·实施中
- 最后核验：`2026-08-20`
- 权威入口：[`../generative-interview-refactor-map.md`](../generative-interview-refactor-map.md)

## 1. 为什么做这轮

v1.6 已在原八题完成可见回应与后台事实整理的离线验证，也已完成本地持久化、顺序写入和失败恢复。当前仍需回答一个产品问题：这套提问方法离开参与调优的案例后，能否继续稳定地产生自然、忠实且有推进价值的完整回应。

本轮使用八个未参与 v1.6 调优的真实历史检查点。它承担新案例稳定性复验，不承担独立隐藏准入，也不改变尚待产品负责人裁决的原八题结论。

## 2. 冻结范围

- 可见回应候选：`2026-08-20.gi088-complete-response-first-v1-6-contrastive-coverage`。
- 后台事实候选：`event-centered-complete-response-background-facts-v1`。
- 数据集：`2026-08-20.gi088-complete-response-first-v1-6-fresh-regression-eight-v1`。
- 运行身份：`2026-08-20.gi088-complete-response-first-v1-6-fresh-stability-replay-v1`。
- 模型：`deepseek-v4-pro`；Thinking 关闭。
- 可见回应：纯文本、`1280` Token、单次调用、单例目标 `15s`、硬超时 `45s`。
- 后台事实：JSON、`1600` Token、单次调用、硬超时 `20s`。
- 每例先完成可见回应，再用其实际输出运行后台事实整理。
- 并发 `1`；重试、恢复、回退均为 `0`。

## 3. 样本与预算

八题依次为：

1. `RPR-REAL-03`：亲密关系是否继续；
2. `RPR-REAL-07`：害怕未来无法继续养狗；
3. `RPR-REAL-09`：从养狗风险切换到帮助朋友的新事件；
4. `RPR-REAL-15`：惦记流浪狗黑豆；
5. `RPR-REAL-17`：梦境与考试话题中明确要求继续；
6. `RPR-REAL-20`：持续补充朋友关系与情绪材料；
7. `RPR-CF-02`：用户明确建立两个事件的关系；
8. `RPR-CF-05`：纠正后明确要求收住。

总预算 `16` 次：八次可见回应、八次后台事实。任何调用前先写入已消费状态；存在未完成调用时停止恢复，避免重复消费。

## 4. 验证门

技术门：

- 每次调用均为目标模型、HTTP 成功、`finish=stop`、正文完整、合同有效；
- 可见回应不泄漏内部结构，后台事实来源只引用有效用户消息；
- 可见回应与后台事实分别记账；可见回应失败时，该例后台调用保持 `not_run`；
- 单次严重隐私、来源、停止控制或程序门失败立即停止；连续两次技术失败立即停止。

产品质量门：

- 普通内容问题不提前停止整批，八题完成后看分布；
- 明确停止、纠正、事件边界和继续请求等硬场景全部通过；
- 可见回应整体 `0 fail`，最多 `1 minor`；
- 后台事实不得编造来源或恢复被纠正内容；高层主题遗漏由原文评审和产品负责人裁决；
- 每例按“完整相关用户输入 → 实际可见回应 → 实际后台事实 → Codex 初评 → 产品负责人裁决”交付。

## 5. 停止点与发布边界

本轮完成离线新案例稳定性复验后，等待产品负责人基于原文裁决。页面 Preview、Production 切换、提交、推送和部署均不由本专项自动触发。Production 持续使用 `event_centered + baseline`。
