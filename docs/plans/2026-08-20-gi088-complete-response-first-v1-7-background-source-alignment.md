# GI-088 v1.7 后台来源标点对齐与稳定性续跑

- 文档职责：当前专项
- 文档状态：已确认·实施中
- 最后核验：`2026-08-20`
- 权威入口：[`../generative-interview-refactor-map.md`](../generative-interview-refactor-map.md)

## 1. 已确认问题

v1.6 新案例稳定性复验已消费 `12/16`：六条可见回应全部技术与合同有效，前五条后台事实有效；`RPR-REAL-20` 后台事实的语义内容与来源消息一致，但模型把用户原话中的一个逗号改成句号，触发逐字来源合同，批次按计划停止，剩余两题四次调用保持 `not_run`。

根因是后台合同同时把“判断事实含义”和“逐字复制标点”交给模型。来源和原文片段属于程序能够确定的工作，继续要求模型逐字复制会引入与语义质量无关的脆弱性。

## 2. 唯一主要变化

后台输出仍提交用户消息标识、事实摘要和原文片段。程序新增窄范围来源对齐：

- 汉字、数字、字母和其他非标点字符必须在同一用户消息中连续、逐字、唯一匹配；
- 只允许空白与标点不同；
- 最终保存的证据片段由程序从用户原文中截取；
- 任一实质字符变化、跨消息拼接或多处无法唯一定位时继续拒绝。

模型、Prompt、Thinking、Temperature、Token、超时、事实结构、纠正规则和可见回应候选保持不变。语义摘要是否忠实、是否遗漏重要事实继续由 Codex 与产品负责人依据原文裁决。
