最后更新：`2026-08-13`

状态：`第二轮视觉基线已验收并于 2026-08-13 发布 Production；域名、迁移、匿名保护与登录态只读主链验收通过`

适用对象：产品负责人、前端设计／联调会话、访谈链路会话、日志生成会话

## 1. 为什么需要这份交接

Daily Light 的完整体验横跨三个工作流：前端页面、访谈链路和日志链路。三个会话无法稳定共享聊天上下文，因此联调需要一份仓库内的共同事实源，统一说明当前状态、接口边界、问题归属、验收顺序和停止点。

本文件承担端到端联调总控。前端设计／联调会话负责推进顺序和最终复验；访谈链路会话与日志生成会话分别交付自己的能力，修复完成后统一回到前端会话复验。

用户最终要完成的闭环是：

```text
选择【陪我聊／帮我记】
→ 完成当前记录
→ 当天形成一张记录卡
→ 返回日记页
→ 生成或更新今日日记
```

### 5.3 访谈链路 Ready

访谈接入前，需要由访谈链路会话交付以下结果：

1. 【帮我记】和【陪我聊】均可按当前 `entryDate` 创建新记录，模式在当前记录内保持；
2. 每条新记录由用户重新选择模式；
3. 用户提交后先收到 `turn`，明确原话已保存；随后收到完整 `session`；
4. 刷新、网络中断或生成取消后，页面能从 `pendingTurn` 恢复，并使用同一个 `clientTurnId` 继续生成；
5. 页面只发送工作区 `allowedActions` 当前允许的动作；
6. 用户完成记录后，服务端幂等形成一张记录卡，记录卡绑定正确的 `entryDate`、事件、记录方式、来源和内容版本；
7. 完成记录时同步完成卡片确认，卡片自动成为当天可用素材，页面保持单步收束；
8. 返回日记页后，`GET /api/journal/day` 能立即读取这张卡片，并据此生成或更新今日日记；
9. 重复完成、重复提交、旧页面提交和并发设备操作只保留一个有效结果；
10. 原话不足以形成记录卡时，页面展示可理解的收束结果，空开场保持空记录状态；
11. 所有失败返回结构化 `issue`，用户能执行重试、刷新、继续生成或回到当天；
12. 【帮我记】和【陪我聊】各提供一条自动化闭环证据与一条隔离浏览器闭环证据。

当前状态：`Ready，已接入隔离 Preview`。

Ready 证据：

- 【帮我记】采用确定性承接，用户表达后不继续追问；【陪我聊】继续使用当前三阶段访谈；模式和日期均随会话持久化；
- `turn → delta → session` 顺序、`pendingTurn` 同一 `clientTurnId` 恢复、旧消息序列拒绝和 `allowedActions` 双侧保护均有自动验证；
- `exit_event` 在同一可靠动作中完成会话并形成已确认记录卡，重复或并发完成只保留一张；完成动作本身不会进入卡片正文；
- 空开场不能形成记录卡，自动结束的空记录不会显示“已记下”；
- 完成后 `GET /api/journal/day` 可立即读取记录卡，并继续生成、更新、编辑和保存今日日记；
- 结构化错误覆盖创建、读取、列表、提交和流式回复，页面保留输入并提供唯一恢复动作；
- 两种模式均具有自动闭环与隔离浏览器闭环证据，真实数据库并发矩阵已通过。

## 6. 页面动作、接口与状态映射

### 6.1 访谈与记录卡

| 用户动作 | 接口／导航 | 关键请求 | 页面期望状态 |
| --- | --- | --- | --- |
| 在日记页点击【帮我记】 | 进入 `/interview?mode=event-centered&entryDate=YYYY-MM-DD`，再调用 `POST /api/interview/event-centered/session/start` | `entryDate`、`recordMode: "capture"`、`clientOperationId` | 创建当前记录，显示记录日期和模式 |
| 在日记页点击【陪我聊】 | 同上 | `recordMode: "chat"` | 创建当前记录，显示记录日期和模式 |
| 发送内容 | `POST /api/interview/event-centered/session/respond/stream` | `action: "reply"`、`rootSessionId`、`clientTurnId`、`baseBranchSessionId`、`baseMessageSequence`、`rawText` | `turn` 后显示原话已保存；`session` 后更新对话和允许动作 |
| 继续失败的一轮 | 同一流式接口 | `action: "resume_turn"`、原 `clientTurnId`、`rootSessionId` | 沿用已经保存的原话继续原回合 |
| 完成当前记录 | 同一流式接口 | `action: "exit_event"`、新的 `clientTurnId`、当前分支和消息版本 | 会话完成；只形成一张记录卡 |
| 返回当天 | `/calendar?view=day&date=YYYY-MM-DD` | 使用当前 `entryDate` | 时间线出现新卡片，今日日记状态随来源变化 |
| 读取记录卡 | `GET /api/interview/event-centered/journal/:entryId` | 当前卡片 ID | 显示当前标题、正文和版本 |
| 编辑／保存记录卡 | `PATCH` 与 `POST .../:entryId/save` | `title`、`content`、`expectedContentRevision` | 保存成功后版本增加；相关日记进入“需更新” |

访谈流式事件的用户可见含义：

| 事件 | 用户可见含义 |
| --- | --- |
| `turn` | 原话已经保存，页面可安全显示“已保存” |
| `phase / delta` | AI 正在形成当前回应 |
| `session` | 回应、对话状态、允许动作和版本已经完整提交 |
| `error` | 按 `issue.resolution` 与 `issue.action` 提供唯一恢复动作 |

### 6.2 今日日记

| 用户动作 | 接口 | 关键请求 | 页面期望状态 |
| --- | --- | --- | --- |
| 打开当天 | `GET /api/journal/day?entryDate=YYYY-MM-DD` | `entryDate` | 渲染当天卡片、日记、来源签名和唯一主动作 |
| 首次生成 | `POST /api/journal/daily/generate` | `task: "generate"`、`clientOperationId`、`expectedSourceSignature`、`expectedContentRevision: null` | `ungenerated → generating → draft` |
| 编辑日记 | `PATCH /api/journal/daily/:entryId` | `title`、`content`、`expectedContentRevision` | 自动暂存，内容版本增加 |
| 保存日记 | `POST /api/journal/daily/:entryId/save` | `expectedContentRevision` | `draft / modified → saved` |
| 卡片新增或变化 | 重新读取当天 | 当前来源签名 | 已有日记进入 `stale`，页面显示“需更新” |
| 更新日记 | `POST /api/journal/daily/generate` | `task: "update"`、当前 `expectedSourceSignature`、当前 `expectedContentRevision`、新 `clientOperationId` | 保留当前正文，成功后形成新草稿 |
| 更新失败 | 同一位置重试 | 新操作编号，继续绑定当前版本 | 显示“更新失败”，原日记继续可读可编辑 |

页面以 `JournalDailyJournalView.displayStatus` 为准：

```text
ungenerated → generating → draft → saved → stale → update_failed
```

`pendingSaveEntryIds` 或 `updateBlockedByPendingSource` 出现时，页面先引导完成记录卡保存，再开放生成或更新动作。

### 7.3 `v7r4-a1` 必验流程

1. 读取当天，确认基线记录卡和已封存今日日记；
2. 编辑记录卡标题或正文；
3. 保存记录卡，确认内容版本增加；
4. 重新读取当天，确认今日日记进入“需更新”；
5. 手工修改今日日记正文并完成暂存；
6. 点击“更新今日日记”，使用固定更新样本；
7. 检查卡片修改已经进入日记；
8. 检查更新前的人工补充仍然保留；
9. 保存更新后的日记；
10. 切换案例、刷新并返回，确认当前会话修改仍在；
11. 结束并重新创建 Preview 会话，确认六个案例恢复固定基线；
12. 核对响应头 `X-Daily-Light-Preview-Model-Calls: 0`。

4. 完成记录；
5. 回到同一天，确认出现且只出现一张记录卡；
6. 生成今日日记；
7. 编辑并保存今日日记；
8. 再开始一条新记录，确认重新选择模式。

### 8.2 【陪我聊】闭环

1. 在当天日记页选择【陪我聊】；
2. 完成至少两轮自然对话；
3. 中途刷新一次，确认会话和原话恢复；
4. 完成记录并返回当天；
5. 确认记录卡内容、来源和日期正确；
6. 确认已有今日日记进入“需更新”；
7. 手工修改日记的一段文字；
8. 更新今日日记；
9. 确认新卡片已加入，原人工修改得到保护；
10. 保存并刷新，确认最终内容和状态保持。

### 8.3 异常、恢复与并发

至少覆盖：

- `turn` 已收到、`session` 尚未完成时刷新；
- 网络失败后使用同一 `clientTurnId` 继续生成；
- 快速重复发送与快速重复完成记录；
- 较早页面基于旧 `baseMessageSequence` 提交；
- 两个页面同时编辑同一记录卡；
- 日记生成中重复点击；
- 卡片变化后使用旧来源签名更新日记；
- 日记人工编辑后收到迟到的生成结果；
- 更新失败后原日记和人工修改保持可用；
- 跨日期、跨案例和跨 Preview 会话请求；
- 同时存在两条未完成记录时继续新建；
- 只有开场、缺少用户内容时完成记录。

每个失败场景都要验证三件事：用户已输入内容的去向、页面下一步动作、刷新后的恢复结果。
