# 访谈内容理解与事实更新协议

最后更新：`2026-07-21`

文档角色：`历史实现协议参考`

产品目标、规则、模块边界与验收标准以[模块二｜本轮理解与事实更新产品规格](./interview-understanding-product-spec.md)为准。当前内部协议、兼容方式和开发验收以[模块二技术设计](./interview-understanding-technical-design.md)为准。本文件继续记录早期实现背景。

## 1. 为什么需要独立协议

意图识别回答“用户希望系统怎样继续”，内容理解回答“用户这一轮说了什么、哪些内容可以信、哪些旧理解已经失效”。访谈进度、下一问和日志都依赖同一份可信事实，因此需要统一的内部协议。

本模块的稳定产物是“本轮可信理解结果”。自然理解摘要和具体提问继续由下一问模块生成。

## 2. 模块边界

完整链路：

> 用户有效内容 → 独立信息单元 → 可信状态 → 事件关系 → 事件档案更新 → 本轮可信理解 → 访谈决策 → 理解摘要与具体提问

内部状态保存在 `InterviewEvent.understandingData`。会话接口和前端继续只展示对话、浅色理解摘要和日志正文。

## 3. 可信理解协议

### 3.1 材料状态

| 状态 | 含义 | 下游权限 |
|---|---|---|
| `explicit_confirmed` | 用户在本轮直接表达 | 可用于进度、下一问和日志 |
| `contextual_confirmed` | 结合上一问可以直接还原的短回答 | 可用于进度、下一问和日志 |
| `pending_inference` | 有合理性，仍需用户确认 | 只允许低压假设式追问 |
| `retracted` | 已被用户修正、否定或替换 | 所有下游停止使用 |

每条材料保留：信息类型、规范文本、原话依据、字段、来源轮次、事件关系、候选维度和替换链。

### 3.2 回答状态

| 状态 | 系统行为 |
|---|---|
| `answered` | 正常推进 |
| `explicit_absence` | 关闭当前信息目标，转向其他目标 |
| `recall_unavailable` | 第一次换成具体锚点，第二次暂停该方向 |
| `uncertain` | 清除假设压力，回到具体场景或感受 |
| `declined` | 当前访谈避开该目标 |
| `unaddressed` | 保持当前目标状态 |

回答状态在跳过抽取的轮次也会保存，因此“先跳过”“想不起来”“不确定”在刷新、恢复和换问后仍然有效。

### 3.3 事件关系

| 关系 | 处理方式 |
|---|---|
| `current_detail` | 合入当前主事件 |
| `linked_scene` | 作为原因、后果、对比或例证保留；核心场景仍由主事件提供 |
| `candidate_event` | 退出当前快照；当前事件结束后优先回收一次 |
| `incidental` | 保留在用户原话，退出结构化事实 |

候选事件被回收后会标记 `revisited=true`，同一候选只提示一次。跨维度内容通过 `candidateDimension` 保存，当前维度继续承接正在表达的主线。

## 4. 更新规则

1. 新事实使用 `add`。
2. 同一字段的补充使用 `refine`，旧材料继续有效。
3. 明确修正使用 `replace`，旧材料立即进入 `retracted`。
4. 明确撤回使用 `retract`。
5. 同一用户轮次重放使用 `keep`，状态保持幂等。

当可信理解参与实际决策时，待确认推测、候选事件、顺带信息不会进入当前结构化快照；明确修正会先清除旧字段，再写入用户的新表达，避免较长旧文本覆盖较短的新事实。

## 5. 下游使用

- 访谈决策读取可信材料、回答状态、候选事件和候选维度。
- 问题规划根据回答状态关闭目标、降低问题压力或更换角度。
- 下一问生成读取最新快照和信息目标；用户发生修正时，浅色理解摘要先确认修正。
- 日志继续读取结构化快照；可信材料准入会在快照写入前拦截待确认和错误归属材料。
- 分支检查点会保存 `understandingData`，按意图重新生成、纠正理解、刷新恢复和同轮重放沿用同一条事实路径。

## 6. 使用与恢复

当前协议已经在正式环境全量采用。历史状态继续由兼容读取层按需转换；出现高影响问题时，可以切换回上一稳定协议并恢复上一正式部署，新结构数据继续保留。

## 7. 评测与发布门槛

专项评测共 `280` 条：120条操作要求案例、120条内容理解案例和40条组合案例。原120条内容理解案例已经全部接入回答状态、材料更新、历史变化、事件归属和下游准入的真实处理链路；新增40条覆盖多要求顺序、多目标、冲突、跨事件和恢复。

运行命令：

```bash
npm run eval:interview-content-understanding
npm run eval:interview-content-understanding:stability
```

发布门槛：

- 凭空增加事实、继续使用已撤回材料、明确拒绝后重复追问、错误事件进入日志：`100%` 通过。
- 已确认材料准确率：`≥98%`。
- 重要内容保留率、事件归属准确率：`≥95%`。
- 关键语义连续三次稳定通过。
- 输入可靠性和意图识别回归集全部通过。

运行记录会保存协议版本、回答状态、更新动作、有效材料数、候选事件数和候选维度，用于问题回放和验收记录。离线稳定性结果见[最新报告](../evals/interview-content-understanding/reports/latest-summary.md)。
