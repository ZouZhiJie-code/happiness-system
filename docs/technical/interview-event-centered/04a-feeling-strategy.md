## 板块 3–4 原冻结基线与当前校准

本文继续保存 `0.20` 的理解感受实现基线。生成式目标产品要求有效成果带来认识增量，只使用当前有效事实并保持感受角度与安全边界；内容成立而表达晦涩时直接重写，不增加回答机会。`honest_limit` 在目标产品中只承担收束说明，不构成角度成果或日志认识。

原“具体触发 → 准确感受或身体状态”继续作为证据基础。`3.29.0` 用户裁决表明，仅连接触发、感受和身体状态容易退化为原话复述。生成式成果现改为：在这些事实之上形成新的感受区分、变化关系、混合体验，或身体与事件的关系。

### 当前提问标准

- 引导复盘帮助用户辨认一种更准确的体验或一条变化关系；已有证据支持时允许提出一个可否认的试探理解。
- 深度聊天继续理解感受为何重要，以及它可能指向什么在意、需要或边界。
- 问题使用用户已经说过的时刻、身体反应或表达作入口，让用户可以回忆、辨认或确认。
- 只复述“先出现什么、后来出现什么”不能形成成果；询问抽象“转折点”和“二者有什么关系”且缺少具体入口时判定失败。
- 混合感受允许同时成立，避免迫使用户选择唯一主导感受。

## 1. 用户结果

理解感受帮助用户把笼统的“难受、开心、烦、复杂”区分得更准确。中度复盘保持低压力，通常一至两问，最多提供三次回答机会；已经具备可信新增认识时可以零问收束。

## 2. 自适应路径（`0.20` 现有实现基线）

基础路径固定为：

```text
直接体验 → 具体触发
```

直接体验已经清楚时，优先寻找带出感受的具体时刻。基础路径完成后，只把原话已经呈现迹象的方向放入候选：

- 感受发生变化。
- 混合感受。
- 身体反应。
- 在意、需要或边界。

候选问题先通过“能带来新增认识”的门槛，再按好回答程度和具体程度排序。缺少迹象时不追问在意、需要或边界，避免把可能性提前写成用户结论。

### 生成式目标产品

- 当前材料已经把具体触发与准确感受或身体状态连接起来时，零问形成成果。
- 只有“烦、难受、复杂”等笼统体验、且一个具体问题很可能帮助用户区分时，继续一问。
- 最低成果成立后立即进入第二检查点；感受连接的在意、需要或边界留给用户主动进入的深度聊天。
- 多个可问方向先判断认识价值，再选择最贴近用户当前重点、最具体、最容易回答的方向。
- 代表案例：用户说“汇报前临时改结构，我特别烦”时，AI 继续一个具体问题区分准确感受；用户说清“听到决定已经做完时感到恼火”后形成成果并收束。

## 3. 收束与边界

- 可信事实已经支持“具体触发 → 准确感受或身体状态”时，直接形成角度成果。
- 当前无法形成最低成果，且继续提问也难以带来明显新认识时，展示 `honest_limit` 收束说明，角度成果保持为空。
- “没有、不知道、想不起来、说不清、都不贴切、没法再具体、不想答”等用户边界继续交由公共保护层稳定执行。
- 第三次回答机会用尽后立即收束。
- 用户要求停止时立即收束。
- `insight`必须引用当前活动事实；兄弟分支或失效事实不能成为支持来源。

## 4. 问题质量

`0.20` 问题使用确定性模板，继续复用现有理解质量门，检查单一目标、具体锚点、用户语言和可回答性。生成式目标产品由 AI 自主生成具体问题，以下问句只作为参考案例：

- “当时最先出现的具体感受是什么？”
- “这份感受最先被哪个具体瞬间带出来？”
- “当时身体上最明显的具体反应是什么？”

## 5. 接入契约

公共编排层调用`decideFeelingOrThoughtStrategy`，传入当前活动事实、最新原话、回答机会计数、文本边界或停止信号，以及已回答和有迹象的目标。

返回下一问或角度成果，同时给出更新后的回答机会计数。历史快照中的低压力锚点字段继续可读，新会话不再写入。事实写入、AI自然表达、分支、幂等和Trace由公共编排层负责。
