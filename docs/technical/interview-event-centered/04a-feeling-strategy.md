# 批次 B 附录｜理解感受策略

状态：`策略模块与定向测试已完成，等待公共编排层接入`

## 1. 用户结果

理解感受帮助用户把笼统的“难受、开心、烦、复杂”区分得更准确。中度复盘保持低压力，通常一至两问，最多提供三次回答机会；已经具备可信新增认识时可以零问收束。

## 2. 自适应路径

基础路径固定为：

```text
直接体验 → 具体触发
```

直接体验已经清楚时，优先寻找带出感受的具体时刻。基础路径完成后，只把原话已经呈现迹象的方向放入候选：

- 感受发生变化。
- 混合感受。
- 身体反应。
- 在意、需要或边界。

候选问题先通过“能带来新增认识”的门槛，再按好回答程度和具体程度排序。缺少迹象时不追问在意、需要或边界，避免把可能性提前写成用户结论。

## 3. 收束与边界

- 可信事实已经支持一句比原话更准确的认识时，直接生成 `insight`。
- “没有、不知道、想不起来、说不清、都不贴切、没法再具体、不想答”后直接收束；已有材料形成`insight`，其余情况形成`honest_limit`。
- 第三次回答机会用尽后立即收束。
- 用户要求停止时立即收束。
- `insight`必须引用当前活动事实；兄弟分支或失效事实不能成为支持来源。

## 4. 问题质量

问题使用确定性模板，继续复用现有理解质量门，检查单一目标、具体锚点、用户语言和可回答性。代表性问题：

- “当时最先出现的具体感受是什么？”
- “这份感受最先被哪个具体瞬间带出来？”
- “当时身体上最明显的具体反应是什么？”

## 5. 接入契约

公共编排层调用`decideFeelingOrThoughtStrategy`，传入当前活动事实、最新原话、回答机会计数、文本边界或停止信号，以及已回答和有迹象的目标。

返回下一问或角度成果，同时给出更新后的回答机会计数。历史快照中的低压力锚点字段继续可读，新会话不再写入。事实写入、AI自然表达、分支、幂等和Trace由公共编排层负责。
