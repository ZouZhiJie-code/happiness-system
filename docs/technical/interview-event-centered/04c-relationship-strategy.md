## 板块 3–4 原冻结基线与当前校准

本文继续保存 `0.20` 的梳理关系实现基线。生成式目标产品要求有效成果带来认识增量，只使用当前有效事实并保持关系角度与安全边界；内容成立而表达晦涩时直接重写，不增加回答机会。`honest_limit` 在目标产品中只承担收束说明，不构成角度成果或日志认识。

原“可观察互动 → 用户的期待、位置或边界”继续作为证据基础。`3.29.0` 用户裁决表明，只复述互动和期待，或转向如何行动，无法形成关系认识。生成式成果现改为：说明互动怎样影响用户的信任、位置、互惠、期待或边界。

### 当前提问标准

- 引导复盘帮助用户看见互动对自己在关系中位置、期待或边界的影响。
- 深度聊天继续理解关心与自主、支持与受伤、合作与被绕开等可以同时存在的张力。
- 理解层需要承接用户明确表达的全部重要关系线索，问题层只选择一个目标推进。
- 问题聚焦用户体验和关系意义，不转成沟通方案、决定权分配或第三方评价管理。
- 他人动机只允许有条件猜测，不能写成事实；把关系问题问成行动安排时判定目标偏离。

## 1. 用户结果

梳理关系帮助用户从一段具体互动中看见自己的期待、位置或边界。AI 始终围绕用户经历和用户在意的部分推进，不解释他人的内心动机，也不替用户判断一段关系应该怎样处理。

## 2. 自适应路径（`0.20` 现有实现基线）

默认目标顺序为：

```text
实际互动
→ 用户期待的回应
→ 用户想守住的位置或边界
→ insight / honest_limit
```

策略会跳过已经被可信事实覆盖的目标。实际互动是必经目标；建立互动基础后，其余候选问题先通过新增价值门槛，再按容易回答、具体程度排序。只要现有事实已经支持一条有新增价值、且不包含他人动机推测的认识，可以零问收束。

问题示例：

- 实际互动：“当时你和对方之间，最关键的互动细节是什么？”
- 期待回应：“那次互动里，你当时最希望对方怎样回应？”
- 位置或边界：“在这段关系里，这件事让你最想守住什么？”

### 生成式目标产品

- 当前材料已经把可观察互动与用户的期待、位置或边界连接起来时，零问形成成果。
- 已有互动和关系感受、但用户期待仍带有推测空间时，继续一个具体问题，避免替用户补写“参与决定”“提前告知”等关系结论。
- 最低成果成立后立即进入第二检查点；沟通方案和进一步关系选择留给用户主动进入的深度聊天。
- 多种解释优先采用证据更强者；证据接近时跟随用户最新重点。成果始终聚焦用户，不推测他人动机。
- 代表案例：用户说“他们改完才告诉我，我觉得没被当回事”时，AI 继续一问，请用户说清当时希望获得怎样的回应。

## 3. 边界与停止

- 每个问题只推进一个目标。
- 关系成果只写用户自己的期待、位置、信任、互惠或边界。
- 包含“对方其实、对方故意、对方一定”等未经用户事实支持的动机判断时，成果候选不生效。
- 当前无法形成最低成果，且继续提问也难以带来明显新认识时，展示 `honest_limit` 收束说明，角度成果保持为空。
- “没有、不知道、想不起来、说不清、都不贴切、没法再具体、不想答”等用户边界继续交由公共保护层稳定执行。
- 最多创建三次回答机会。目标产品成果成立后立即收束，三次继续作为保护上限。
- 用户要求停止时立即收束；已有可信认识继续保留。

## 4. 工程契约

公共编排调用：

```ts
decideRelationshipOrActionStrategy(input)
```

关系角度使用：

- `angle = relationship`
- `facts`：当前活动分支的有效事实编号与文本。
- `coveredTargets`：已经被可信事实覆盖的关系目标。
- `askedTargets`：当前成果版本已经创建过回答机会的目标。
- `candidateAssessments`：候选问题的新增价值、回答难度和具体程度评估。低价值候选退出本轮选择；通过门槛后优先选择更容易回答、更具体的问题。
- `supportedOutcome`：理解层生成的成果候选，必须声明依赖的事实编号、新增价值和证据强度。依赖事实都在当前活动路径、价值达到 `meaningful`、证据达到 `clear` 后才能零问收束。
- `questionOpportunityCount`：公共状态层持有的计数。历史快照中的`lowPressureAnchorUsed`继续可读，新会话不再写入。

返回 `ask / outcome`。问题继续经过现有问题规格与理解门检查；问题表达与现有换问法能力共用同一套 `questionSpec`。

## 5. 验证重点

- 从实际互动开始，并跳过已经覆盖的目标。
- 事实充分时零问收束。
- 他人动机推测无法成为角度成果。
- 文本否定或无法继续时直接收束。
- 三次回答机会后强制形成 `insight / honest_limit`。
- 回复版本切换复用当前回答机会，不重复计数。
- 回答机会计数必须是 `0–3` 的整数；异常状态直接抛出并交由公共恢复链路处理。
