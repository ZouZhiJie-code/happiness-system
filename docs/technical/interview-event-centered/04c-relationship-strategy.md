# 04c｜梳理关系策略

版本：`1.0`

状态：`策略实现完成，等待公共编排接入`

## 1. 用户结果

梳理关系帮助用户从一段具体互动中看见自己的期待、位置或边界。AI 始终围绕用户经历和用户在意的部分推进，不解释他人的内心动机，也不替用户判断一段关系应该怎样处理。

## 2. 自适应路径

默认目标顺序为：

```text
实际互动
→ 用户期待的回应
→ 用户想守住的位置或边界
→ insight / honest_limit
```

策略会跳过已经被可信事实覆盖的目标。实际互动是必经目标；建立互动基础后，其余候选问题先通过新增价值门槛，再按容易回答、具体程度排序。只要现有事实已经支持一条有新增价值、且不包含他人动机推测的认识，可以零问收束。

问题示例：

- 实际互动：“当时你和对方之间，最关键的互动细节是什么？”
- 期待回应：“那次互动里，你当时最希望对方怎样回应？”
- 位置或边界：“在这段关系里，这件事让你最想守住什么？”

## 3. 边界与停止

- 每个问题只推进一个目标。
- 关系成果只写用户自己的期待、位置、信任、互惠或边界。
- 包含“对方其实、对方故意、对方一定”等未经用户事实支持的动机判断时，成果候选不生效。
- 用户回答“没有、不知道、想不起来、说不清、都不贴切、没法再具体、不想答”后直接收束；已有可信认识继续保留，其余情况写入`honest_limit`。
- 最多创建三次回答机会。达到上限时，有可信认识则写入 `insight`，其余情况写入 `honest_limit`。
- 用户要求停止时立即收束；已有可信认识继续保留。

## 4. 工程契约

公共编排调用：

```ts
decideRelationshipOrActionStrategy(input)
```

关系角度使用：

- `angle = relationship`
- `facts`：当前活动分支的有效事实编号与文本。
- `coveredTargets`：已经被可信事实覆盖的关系目标。
- `askedTargets`：当前成果版本已经创建过回答机会的目标。
- `candidateAssessments`：候选问题的新增价值、回答难度和具体程度评估。低价值候选退出本轮选择；通过门槛后优先选择更容易回答、更具体的问题。
- `supportedOutcome`：理解层生成的成果候选，必须声明依赖的事实编号、新增价值和证据强度。依赖事实都在当前活动路径、价值达到 `meaningful`、证据达到 `clear` 后才能零问收束。
- `questionOpportunityCount`：公共状态层持有的计数。历史快照中的`lowPressureAnchorUsed`继续可读，新会话不再写入。

返回 `ask / outcome`。问题继续经过现有问题规格与理解门检查；问题表达与现有换问法能力共用同一套 `questionSpec`。

## 5. 验证重点

- 从实际互动开始，并跳过已经覆盖的目标。
- 事实充分时零问收束。
- 他人动机推测无法成为角度成果。
- 文本否定或无法继续时直接收束。
- 三次回答机会后强制形成 `insight / honest_limit`。
- 回复版本切换复用当前回答机会，不重复计数。
- 回答机会计数必须是 `0–3` 的整数；异常状态直接抛出并交由公共恢复链路处理。
