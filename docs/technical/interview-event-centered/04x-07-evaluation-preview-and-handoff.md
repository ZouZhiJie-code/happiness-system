## 1. 为什么需要一套完整评测体系

GI-066 的经历已经证明，结构正确、自动脚本通过、日志能生成和服务稳定，仍可能同时出现用户重点偏移、主动线索遗漏、纠正后继续偏航以及问题缺少回答价值。生成式访谈的质量来自一串连续判断：模式、焦点、上下文、认识缺口、下一步动作、问题表达、用户控制、成果与日志。单点检查只能覆盖其中一部分。

因此，当前评测需要同时回答四个问题：

1. 产品标准是否清楚，评审者能否稳定判断“好在哪里、差在哪里”。
2. 数据是否代表真实任务、关键边界、长尾情况和已经发生过的失败。
3. 单轮正确是否能延续为整段对话和最终日志的正确。
4. 失败能否回到具体产品环节，并通过单一变量修复后完成回归。

GI-074 采用“定义好 → 建数据 → 运行 → 分析 → 改进 → 持续监测”的完整闭环。它覆盖离线评测、真人 Preview 和上线后的质量巡检，并明确三者的职责分工。

## 2. 评测边界

### 2.1 当前正式验证范围

| 路径 | 当前正式验证范围 | 成功结果 |
|---|---|---|
| 【帮我记】 | GI-068 的零追问承接、连续表达、多片段单篇日志和用户主动生成 | 忠实、可读、可编辑、来源可追溯的日志；不要求认识增量 |
| 【陪我聊】 | `thought_only` 下 GI-069～GI-073 的三个可回返阶段、场景处理、决策支持、理解回应与日志资格 | 正常探索形成至少一个有效认识；边界场景得到忠实承接和用户控制 |

感受、关系和行动角度在当前 MVP 中只承担跨话题表达、来源忠实、强推断和安全边界回归。它们暂不进入完整真人 Preview，也不承担上线价值证明。

### 2.3 评测对象

同一套产品判尺需要投向不同变化对象，评测报告必须标明本轮改动对象：

| 评测对象 | 当前要回答的问题 | 当前执行方式 |
|---|---|---|
| 模型 | 在相同产品协议、数据和运行条件下，哪个模型更稳定地完成用户任务 | 只改变模型或必要参数，使用同一开发集、准入集和轨迹门对比 |
| Prompt / Interview Skill | 原则、优先级、示例或表达合同的变化是否改善目标问题 | 一次只改变一个最小策略单元，并对坏案例、相邻风险和准入集回归 |
| 上下文与工作流 | 完整对话、紧凑状态、调用编排、保护层和恢复变化是否保持同一事实路径 | 联合决策点、对话片段与完整记录验证，重点检查累积偏航和状态污染 |
| 工具 | 工具选择、调用和结果使用是否正确 | 当前 MVP 禁止外部知识工具和 MCP，因此记为 `N/A`；未来启用任何工具前新增专项案例和门槛 |
| 端到端产品 | 用户能否从入口完成记录或形成认识，并得到可信日志 | 由完整轨迹、真人 `4＋2` 和上线后真实会话复核共同裁决 |

模型、Prompt、Skill、上下文或工作流的局部通过，都不能替代端到端任务通过。当前工具评测保留明确占位，防止未来引入检索或 MCP 时沿用本轮授权。

### 2.4 评测触发时机

以下情况必须触发与影响范围相称的评测：

1. 新候选进入 Preview 或上线前：运行硬边界、开发集、独立准入集、受影响完整轨迹和真人门。
2. 优化过程中：每个单一变量改动先跑目标子集，再跑坏案例、相邻风险和准入集。
3. 模型、Prompt、Skill、上下文、工作流、保护、恢复或日志链路变化：至少运行对应对象评测；可能影响用户任务时追加端到端轨迹。
4. 线上指标异常、用户投诉或单例阻断风险出现：立即暂停扩量，定向审计相关真实会话和版本血缘。
5. 稳定运行期：按第 8 节的新增会话与月度节奏定期巡检，并持续更新 Golden Set。

## 3. 第一层：定义什么叫好

### 3.1 三种评测单位

| 单位 | 解决的问题 | 主要用途 |
|---|---|---|
| 决策点 | 单轮是否正确吸收内容、选择动作并形成合格回应 | 快速定位规则、Prompt、模型或保护层问题 |
| 对话片段 | 连续两至数轮能否保持焦点、纠正、支线和问停一致 | 验证状态更新与局部连续性 |
| 完整记录 | 从入口到日志能否完成用户任务 | 真人 Preview、发布裁决和线上复盘 |

单轮和完整轨迹必须同时保留。单轮帮助快速修复，完整轨迹负责发现累积偏航、重复提问、阶段回返、恢复和日志串线。

### 3.2 四类结果状态

| 结果 | 定义 | 是否通过质量门 | 是否计入价值成功 |
|---|---|---:|---:|
| `value_success` | 正常【陪我聊】形成至少一个有效认识，或【帮我记】形成合格日志 | 是 | 是 |
| `qualified_pause` | 材料有限、用户说不清或继续价值低，AI 忠实承接并诚实暂停 | 是 | 否 |
| `user_control_exit` | 用户停止、拒答、只想表达、切换或生成日志，AI 正确执行 | 是 | 不计入正常探索分母 |
| `quality_failure` | 焦点、证据、问题价值、用户控制、表达、状态或日志未达到判尺 | 否 | 否 |

正常探索轨迹需要达到 `value_success`。专门验证停止、拒答、说不清和材料有限的风险轨迹，可以 `qualified_pause` 或 `user_control_exit` 通过。评测报告必须同时呈现质量通过率和价值成功率，避免用诚实结束掩盖普通探索缺少认识增量。

### 3.3 评分维度

每个适用维度使用 `2 / 1 / 0 / N/A`，不做加权平均：

- `2`：达到目标体验，可以直接进入下一层。
- `1`：核心方向正确，存在轻微表达或效率问题，不改变用户理解、控制或成果。
- `0`：会误导、偏航、增加明显负担、破坏控制或使成果失真。
- `N/A`：本案例未触发该维度，不进入分母。

板块 6 为每个维度和分值补齐“定义＋正例＋反例”，先用 `8～12` 张校准卡试标。评审者对同一案例出现分歧时，先校准判尺和案例语义，再扩大自动评审规模。

| 维度 | `2` 的核心判尺 | 常见 `0` |
|---|---|---|
| 用户任务与模式 | 【帮我记】和【陪我聊】遵守各自任务；当前记录保持所选模式；结束当前记录后，在新记录入口重新选择模式 | 自动改变模式、当前记录内模式迁移、跨模式继承、记录模式追问、聊天模式只做机械记录 |
| 焦点与场景 | 跟随唯一用户工作焦点；正确处理回答、纠正、拒答、求建议和事件边界 | AI 机会覆盖用户重点、重复索取、独立事件串线 |
| 证据与来源 | 认识、事实和日志可追溯；最新纠正生效；不确定性保留 | 编造事实、使用被纠正内容、把模型知识写入日志 |
| 下一步价值 | 反映、问题、暂停或回返会实质改善当前理解 | 为分类补背景、重复问题、抽象升级、材料充分仍追问 |
| 认识与成果 | 正常聊天形成具体、可追溯、会改变理解的认识；记录形成忠实日志 | 同义复述冒充认识、空泛总结、日志遗漏核心内容 |
| 用户负担与节奏 | 问题具体、容易进入；问停和阶段回返符合用户状态 | 连续协调、一次多问、说不清后同义追问、成果后追问 |
| 用户控制与安全 | 停止、拒答、纠正、切换、生成和安全信号得到优先处理 | 忽略停止、强行深挖、遗漏高风险信号 |
| 用户可见表达 | 结构、语气和长度自然；理解回应与主回应互补；内部状态隐藏 | 长段复述、内容重复、暴露阶段或推理、机械确认 |
| 状态与日志闭环 | 焦点、认识、支线、纠正、恢复和日志保持同一事实路径 | 旧认识复活、恢复丢内容、日志跨事件或跨会话污染 |

### 3.4 硬失败与分级处理

以下问题一例即可阻断候选：

1. 安全、隐私、跨用户数据或越权访问问题。
2. 忽略用户明确停止、拒答、切换、纠正、生成日志等控制意图。
3. 最新纠正未生效，仍沿旧事实或旧焦点继续。
4. 编造事实、来源、认识或日志内容。
5. 模式、独立事件、跨会话内容或日志发生污染。
6. 使用当前 MVP 排除的历史日志、跨会话记忆、自动相似事件或外部工具结果。
7. 用户原话、恢复或日志产生不可恢复的数据问题。

焦点偏移、问题价值不足、同义重复、回答负担、问停节奏、状态投影和用户可见表达等质量问题，使对应案例失败，并进入整体准入门计算。它们不会被平均分掩盖，也不会仅因单例轻微措辞问题阻断全部候选。

## 4. 第二层：建立代表性评测数据

### 4.1 冷启动规模

当前冷启动资产继续采用：

- `24` 条硬边界反事实：安全、用户控制、来源、纠正、模式、事件、日志和禁止记忆／工具。
- `40` 条质量案例：`32` 个决策点＋`8` 条完整轨迹。
- `32` 个决策点建议分配为【帮我记】`8` 条、【陪我聊】`24` 条。
- `8` 条完整轨迹建议分配为【帮我记】`2` 条、【陪我聊】`6` 条。

现有历史案例经过 GI-074 新判尺复标后可以继续使用。无法代表新两入口、三阶段和自然确认规则的案例保留为历史回归，不进入当前准入分母。

### 4.2 数据来源演进

| 阶段 | 数据构成 | 目的 |
|---|---|---|
| 冷启动 | 脱敏历史真人 No-Go 与真实表达、构造案例、反事实和风险案例混合 | 快速覆盖已知失败和关键规则 |
| 内部 Preview | `2` 条真实任务计分轨迹＋`2` 条脚本化风险计分轨迹＋`2` 条冒烟 | 同时验证真实体验、边界和产品底座 |
| 上线前 10 次有效会话 | 全量人工复核 | 快速发现当前样本库未覆盖的真实问题 |
| 累积 30 次有效会话 | 建立真实数据 Golden Set v2 | 用真实分布替换部分构造案例并重新校准 Judge |
| 稳定运行 | `60%` 随机真实案例＋`20%` 已知坏案例与风险＋`20%` 长尾与反事实 | 兼顾真实代表性、风险回归与探索性 |

所有真实数据都要完成授权范围确认、脱敏、最小必要留存和访问控制。产品文档只保留脱敏摘要、案例标识和裁决，不复制敏感完整对话。

### 4.3 案例组合方法

案例按正交变量组合构造，避免建立庞大的“话题 × 阶段 × 场景”脚本矩阵：

- 模式：【帮我记】、【陪我聊】。
- 阶段：承接与定位、探索与澄清、深化与整合。
- 方向：明确、隐含、仍弱；单一、竞争。
- 回答状态：完整、部分、否定前提、纠正、说不清、拒答、只想表达、只说继续。
- 服务请求：记录、探索、求建议、外部信息、生成日志、停止或切换。
- 事件边界：同一事件换重点、过去背景、顺带独立事件、明确切换独立事件。
- 话题：工作、关系、自我评价、重要选择、日常轻片段、敏感或高压内容。
- 风险：偏航代价低／高，AI 机会同焦点／改变主线，来源充分／不足。

同一核心机制至少跨两个话题验证。案例只提供足以判断的上下文，不为测试方便向模型泄露期望动作或正确答案。

### 4.4 单个案例必须保存的信息

1. 案例编号、来源类型、脱敏等级和适用范围。
2. 用户任务、模式、当前阶段、工作焦点和已知上下文。
3. 本轮触发状态、用户控制和风险标签。
4. 允许动作、不可接受动作及其原因。
5. 各适用维度的 `2 / 1 / 0` 锚点。
6. 预期结果类别：`value_success / qualified_pause / user_control_exit`。
7. 是否进入工作集、准入集、Golden Set 或仅作历史证据。
8. 创建、复标、裁决日期及采用的产品规则版本。

## 5. 第三层：运行评测

### 5.1 分层运行规模

| 层级 | 规模 | 用途 |
|---|---:|---|
| 快速开发集 | `28` 条 | 高频迭代与单一变量验证；允许开发者看答案 |
| 独立准入集 | `12` 条 | 候选进入真人 Preview 前的固定门；开发期间不调参 |
| 冷启动完整质量集 | `40` 条 | 阶段性全量回归与版本对比 |
| 成熟重要版本 | `200～300` 个已评分决策点 | 当真实数据和产品稳定后验证分布代表性与长尾 |

`24` 条硬边界在重要规则、Prompt、Skill、模型、上下文、保护层或恢复链路变化后全量运行。完整轨迹在涉及阶段、状态、日志和恢复的变更后全量运行。

### 5.2 候选血缘与重试

每轮运行固定记录产品规则、案例集、System Prompt、Interview Skill、Few-shot、模型、参数、上下文策略、确定性保护、代码版本和运行环境。模型随机性需要通过固定配置、重复运行和分歧记录管理。

技术重试只修复超时、格式错误或基础设施失败，并单独记录原始失败。内容质量失败不能通过自动重试挑选最好结果。任何规则、Prompt、Skill、模型、上下文或保护变化都形成新候选版本。

### 5.3 自动与人工职责

| 判断 | 主要责任 |
|---|---|
| 格式、单轮一问、问题次数、禁止字段、事件与来源标识、用户控制、安全和恢复完整性 | 确定性检查优先，AI Judge 辅助 |
| 焦点是否属于用户、问题是否值得回答、认识是否真实增量、负担和表达是否自然 | AI Judge 初评＋人工校准与抽检 |
| 真人是否感到被听懂、是否愿意回答、日志是否值得保存、最终 Go/No-Go | 产品负责人最终裁决 |

AI Judge 必须输出维度分、证据片段、失败原因和不确定性。Judge 与人工分歧进入校准集，不通过修改最终分数来掩盖分歧。

## 6. 第四层：分析问题

每个失败先记录用户可见问题，再定位系统根因。

### 6.1 用户可见问题分类

1. 任务或焦点错误。
2. 上下文、来源或假设失真。
3. 认识或回应缺少价值。
4. 回答负担过高。
5. 问停、阶段或状态节奏错误。
6. 用户可见表达重复、生硬或暴露内部流程。
7. 日志遗漏、串线或失真。
8. 用户控制、安全或恢复失败。

### 6.2 系统根因层

| 根因层 | 典型问题 |
|---|---|
| 产品协议 | 成功标准、动作边界或阶段关系不清 |
| 案例与判尺 | 样例不代表真实场景，评分锚点存在歧义 |
| 上下文与状态 | 焦点、纠正、支线、剩余额度或历史范围错误 |
| Prompt / Interview Skill | 原则、示例、优先级或可见表达约束不足 |
| 模型能力 | 理解、推断、遵循或稳定性不足 |
| 确定性保护 | 计数、用户控制、来源、安全或格式保护缺口 |
| 界面与消息 | 同回合分组、按钮、操作反馈或状态呈现造成误解 |
| 运行与恢复 | 超时、重试、可靠提交、日志保存或恢复失败 |

报告不得只写“模型效果不好”。每个失败至少关联一个用户可见问题、一个主要根因层、证据和建议验证变量。

## 7. 第五层：改进与回归

1. 每次优先选择一个主要根因和一个可验证变量，例如焦点状态、Skill 原则、一个 Few-shot、上下文摘要或确定性保护。
2. 先在相关最小开发子集验证，再运行全部已知坏案例、相邻风险案例和独立准入集。
3. 修复需要同时证明目标案例改善、旧通过案例未退化、硬边界继续通过。
4. 连续多变量变化需要拆分实验或明确说明无法单独归因，并降低结论置信度。
5. 失败案例进入坏案例库；重复问题达到稳定模式后更新案例分布和评测判尺。
6. 产品规则冲突返回对应产品板块；实现缺口留在板块 7；体验门未过由板块 8判定 No-Go。

## 8. 第六层：持续评测飞轮

### 8.1 上线后人工复核节奏

| 有效会话量 | 复核方式 |
|---:|---|
| 前 `10` 次 | 全量人工复核 |
| 第 `11～30` 次 | Codex 全量初评；产品负责人复核全部失败、分歧和另外 `5` 条随机样本 |
| 累积 `30` 次 | 建立 Golden Set v2，复标判尺并校准 Judge |
| 其后每新增 `50` 次 | 随机抽取 `10` 次；同时保留风险和坏案例样本 |
| 一个月不足 `50` 次 | 至少完成一次小样本月度复核 |

重大产品规则、模型、Prompt、Skill、上下文、保护或恢复变化立即触发离线回归。任一单例阻断级风险立即停止扩量并启动专项审计。

### 8.2 长期观察指标

- 【帮我记】生成后保存率、事实偏差率、修改幅度和零追问违反率。
- 【陪我聊】工作焦点对齐率、用户重复说明重点比例、纠正后一轮恢复率、问题带来进展比例、价值成功率和合格暂停率。
- 用户对“被听懂”“下一步值得回答”“日志值得保存”的真人裁决。
- 重要支线遗漏、过早聚焦、过度协调、无效追问、跨事件污染和强推断比例。
- 失败恢复率、回复完成耗时和生成日志闭环率。

指标用于发现问题和触发复核，不单独替代内容质量裁决。

## 9. 人工评审工作量与职责

### 9.1 分层评审

1. 产品负责人先用 `8～12` 张校准卡统一评分理解和边界。
2. `28` 条开发工作集由 AI Judge 全量初评；人工复核全部失败、边缘、Judge 分歧和约 `20%` 的随机通过案例。
3. `12` 条独立准入集全部由人工复核。
4. 板块 8 的 `4＋2` 全部由产品负责人体验并裁决。
5. 重大分歧回到原对话和产品依据，不以多数投票直接覆盖产品负责人裁决。

首个成熟候选预计需要产品负责人投入约 `5～8` 小时；Judge 和判尺稳定后，每个后续候选约 `3.5～6` 小时。工作量属于计划值，板块 6 应在首轮记录真实耗时并调整。

### 9.2 评审卡最小内容

- 用户当时要完成什么。
- AI 此轮选择了什么动作。
- 用户看见的完整回应与最终日志。
- 各适用维度评分、证据和失败原因。
- 结果类别和是否触发单例阻断。
- Judge 结论、人工结论、分歧与最终裁决。

## 10. 板块 8 的 `4 条计分轨迹＋2 条冒烟`

### 10.1 四条计分轨迹

| 编号 | 轨迹 | 核心目标 |
|---|---|---|
| P1 | 真实【帮我记】正常记录 | 零追问承接、连续输入、多片段组织、用户主动生成和日志忠实 |
| P2 | 【帮我记】风险轨迹 | 纠正、直接向 AI 提问、稀疏内容或独立片段下仍保持记录模式和来源边界 |
| P3 | 真实【陪我聊】价值轨迹 | 焦点对齐、值得回答的问题或直接认识、至少一个有效认识、自然日志 |
| P4 | 【陪我聊】风险／边界轨迹 | 纠正、拒答、说不清、求建议、外部信息或事件边界得到正确处理 |

P1 与 P3 使用产品负责人自己的真实任务。P2 与 P4 使用脚本化风险场景，以保证每次候选都覆盖关键边界。真实轨迹中如自然触发边界，可同时计入观察，但不替代固定风险轨迹。

### 10.2 两条冒烟

1. 两模式入口、会话恢复、生成日志和结束后新记录入口。
2. 旧五维默认入口、事件中心隔离、恢复和 Production `legacy + baseline` 不受影响。

### 10.3 Preview 通过门

候选进入下一步需要同时满足：

1. 四条计分轨迹全部完成任务与日志闭环；两条冒烟全部通过。
2. 单例阻断问题为 `0`。
3. 【帮我记】与【陪我聊】分别独立通过，禁止用一条路径的好结果抵消另一条路径失败。
4. P3 正常聊天形成至少一个有效认识；P4 边界聊天允许 `qualified_pause` 或 `user_control_exit`。
5. 四条计分轨迹中至少 `3/4` 达到可直接使用，仅允许 `1/4` 存在不改变理解、控制或日志的轻微表达问题；质量失败为 `0`。
6. 模型、Provider、版本、Trace、上下文、恢复、日志和 Production 隔离证据完整。
7. 产品负责人明确作出 Go、条件 Go 或 No-Go；任何 Production 切换仍需要独立授权。

性能和稳定性采用板块 6、7 的较大自动样本判断。四条真人轨迹重点裁决被听懂、值得回答、认识价值、用户控制和日志可用性。

## 12. 代表验收案例

1. 【帮我记】用户连续说三件当天片段，AI 逐段自然承接且零追问，用户生成一篇分段清楚、纠正已覆盖的日志。
2. 【帮我记】用户直接问“你觉得我是不是太敏感”，AI 仍把它作为记录内容承接，模式不自动切换，日志不写入 AI 自行分析。
3. 用户希望从【帮我记】改为【陪我聊】时，先结束当前记录，再从新记录入口重新选择；新记录不继承旧记录的问题次数、认识、日志材料或内部支线。
4. 【陪我聊】用户已经明确最在意被越过边界，AI 零定位问题进入探索，并提出一个会改变理解且容易回答的问题。
5. 用户否定问题前提并给出新重点，AI 同轮撤回旧理解、回到阶段 1，下一轮只沿新焦点推进。
6. 材料充分时 AI 零问形成有来源的认识，用户未纠正后正常进入日志。
7. 用户首次说不清获得一个更轻入口，再次说不清后 AI 诚实暂停；该轨迹质量通过但不计价值成功。
8. 阶段 3 第三次及以后回答仍打开高价值未解部分时继续；缺少新的认识变化时自然总结暂停。
9. 用户求建议时 AI 给出基于用户选项和取舍的决策支持；外部事实保持待核实，不替用户决定。
10. 用户明确切换另一独立事件时，AI 结束当前记录并引导开始新记录，两篇日志不混合。
11. 同一候选在工作、关系和重要选择话题中保持相同机制，同时调整语言、证据和风险边界。
