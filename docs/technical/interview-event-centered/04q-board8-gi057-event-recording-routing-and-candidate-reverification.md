## 1. 历史产品决策

### GI-057｜事件记录分流、统一问停与候选复验

- 决策编号：`GI-057`
- 状态与置信度：`产品方案已确认；高`
- 最终结论：事件记录阶段只确认当前事件和任一项个人反应。只有事件时追问个人反应，只有个人反应时追问具体事件，两者齐全后自然承接并平等展示感受、想法、关系、行动四个角度。用户选角度后才启动正式生成式复盘。
- 选择原因：入口阶段承担素材形成职责，正式复盘阶段承担认识推进职责。职责分开后，入口追问不会占用正式生成式降级预算，也能降低用户刚讲清楚就被要求再次补充细节的风险。
- 适用范围：事件中心新会话、事件记录阶段、第一检查点、四角度选角度、引导复盘和深聊；旧五维默认入口继续保持原链路。
- 依据与案例：GI-056 候选的 `8` 次运行降级中有 `6` 次发生在选角度前；此前测试还发现空控制动作可能提前生成“这个角度先停在这里”。GI-057 将入口追问固定为事件或个人反应单一目标，并为选角度后的首问增加未回答目标兜底。
- 影响板块：`2、4、5、6、7、8`
- 专项文档：[本文件](./04q-board8-gi057-event-recording-routing-and-candidate-reverification.md)、[04p](./04p-board8-preview-go-no-go-production-authorization.md)、[04o](./04o-board7-mvp-preview-candidate-handoff.md)
- 确认日期：`2026-08-03`

## 2. 实现口径

### 2.1 事件记录入口

- 事件记录阶段只写入事件事实和个人反应，不生成角度成果、成果关系或正式复盘问题。
- 入口追问使用固定目标、事实锚点和受控句式，不调用模型自由生成。
- 入口识别写入 `eventRecordingRecognition`，使用 `requestedStrategy=baseline`、`effectiveStrategy=baseline`，不写入运行降级事件，也不进入正式复盘降级分母。
- `select_current_event`、`select_exploration_angle`、`continue_exploration`、停止和退出继续作为确定性控制动作单独统计。

### 2.2 共用问停与选题

- 先处理停止、退出、纠正和日志动作。
- 材料足够形成当前认识时停止提问。
- 只有缺失内容会实质改变理解、只能由用户补齐、且存在具体低负担入口时继续追问。
- 已回答、已否定和已经问过的目标从候选中移除；每轮只保留一个回答目标。
- 用户选角度后沿用角度基础目标顺序；基础目标已覆盖时，进入仍未回答的低负担目标，避免空控制动作提前收束。

### 2.3 纠正与来源关系

- 纠正先撤销或更新旧事实，再以新事实推进后续提问、角度认识和日志素材。
- 正式生成式回应收到纠正标记，并在回应层自然承认一次纠正；若表达层漏承接，由服务端补充安全承接。
- 用户明确表达“某件事让我产生某体验”或“某行为放大某感受”时，按有来源关系处理。
- 无来源因果、他人动机、新人物、新动作、新结果、建议和证据外价值判断继续触发安全拦截。

### 2.4 同角度深聊成果

- 同一角度只保留当前有效成果；后续深聊写入新版本，由投影按当前活动路径选取最新有效成果。
- 纠正同步修正受影响成果；离开角度后固定当前版本，已聊角度不再出现在可选角度中。
- 不新增数据库迁移，沿用现有角度成果表、事实投影和路径投影。

### 2.5 定向修复与契约归一

- 每个生成阶段最多进行一次定向修复，重试提示携带具体校验原因。
- 来源、事实、纠正、停止和安全风险立即进入 baseline；结构或表达问题允许定向修复一次。
- 修复后通过计为生成式成功，并在 Trace 中标记 `generativeRepairApplied`；服务端局部承接修复标记 `correctionRepairApplied`。
- 事实、范围、立场、事件选项、关系期待等有限别名归一为标准字段；未知语义和新增事实继续拒绝。

当前候选血缘：策略 `5.52.0`、角度卡 `2.14.0`、Few-shot `quality-patterns.2026-08-03.v31`、语义 Prompt `2026-08-03.event-centered-generative-v74-gi057-source-contract`、可见回应 Prompt `2026-08-03.event-centered-generative-v74-gi057-source-contract-visible`、语义产物 `event-centered-semantic-plan.v7`。候选变化后此前 Preview 结果全部失效。

## 3. Board8 审计口径

报告版本：`board8.candidate-aware.v3`。

- 事件记录入口识别单独统计为 `eventRecordingTurnCount`。
- 确定性控制动作单独统计为 `deterministicControlCount`。
- 正式生成式尝试只统计 `interview_turn`、候选策略版本一致、实际尝试生成式且不属于入口或控制动作的回合。
- 运行降级只统计最终 `effectiveStrategy=baseline` 且有生成失败阶段或错误码的真实生成式回合。
- 定向修复成功、局部确定性承接和错误码分布单独记录。
- `recent20` 只取真实尝试过生成式的用户回合。
- 报告只保留会话、事件、日志和 Trace 标识、阶段、角度、来源、耗时、错误码和人工空白裁决字段；用户原话、AI 全文、日志正文、Trace 上下文和最终输出继续留在受控 Preview 数据中。

## 4. GI-054 完整 Preview 复验计划

候选冻结后使用新 Preview 数据库或明确 `candidateStartedAt`，从头重跑：

1. 感受、想法、关系、行动四角度 × 引导复盘 / 深聊共 `8` 条主链。
2. 第一检查点冒烟：门槛满足后只展示四个平等角度，不展示输入框和第一检查点日志动作；选角度后进入贴题首问。
3. 五维默认入口冒烟：启动、提交一次有效内容、刷新恢复。
4. 每条主链完成事件日志生成、编辑、正式保存、刷新和重新打开。

发布门沿用 GI-051，并增加 GI-057 阶段统计要求：`8/8` 主链完成，一票阻断为零，正式复盘运行降级累计最多 `2` 次、最大连续最多 `2` 次，日志全文 fallback 最多 `2` 条，至少 `6` 条完整使用生成式对话和生成式日志；回应中位数 `≤8s`、P90 `≤15s`，条件区间为中位数 `≤10s`、P90 `≤20s`。

任一动作、角度或回答目标需要产品负责人重新选择，轨迹判失败。Preview 期间候选代码、模型、Prompt、策略和角度卡保持冻结。
