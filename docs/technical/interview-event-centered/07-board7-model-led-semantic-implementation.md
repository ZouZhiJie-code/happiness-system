## 4. 模型与程序的职责边界

### 4.1 模型承担的语义判断

模型基于完整有效的当前记录语境，承担以下判断与表达：

1. 用户此刻在谈什么，当前工作焦点及其最新变化是什么。
2. 当前材料已经形成什么认识，哪些部分仍然开放或证据有限。
3. 下一步直接反映、提出一个问题、开放、暂停或阶段回返，哪种动作对用户更有价值。
4. 下一问预计带来什么认识变化，以及相应的回答负担是否值得。
5. 如何以自然、忠实、可纠正的中文呈现理解回应和主回应。
6. 如何在【帮我记】中忠实承接用户表达，并在用户主动生成时整理当前记录的有效材料。

Prompt／Interview Skill 用于提供目标、优先级、跨场景原则、解释边界和代表性正反案例。模型自主完成正常语义判断，评测和真人 Preview 负责裁决质量。

### 4.2 程序承担的稳定执行

程序负责可客观验证的产品边界：

1. 记录级模式选择、模式保持、结束记录和新记录隔离。
2. 用户停止、纠正、生成日志、结束记录等明确控制意图的优先执行。
3. 问题计数、单轮单问、回复版本分支与恢复一致性；具体合同继承板块 5 的冻结结论。
4. 用户原话、来源、纠正、撤回、事件和会话隔离。
5. 安全、隐私、结构合法性、可靠提交、幂等重试和失败恢复。
6. 用户可见消息分组、日志生成与保存、Trace、版本血缘和发布隔离。

程序硬保护服务于确定性边界。问题价值、焦点价值、认识增量、回答负担与自然表达继续由模型判断，并由板块 6、8 的证据体系验收。

### 4.3 仍待板块 7 决定的实现问题

以下内容当前均为开放实施问题：

- 正式候选采用单次或多次模型调用，以及每次调用的明确职责；GI-081 的一次调用／两阶段只用于首批离线诊断。
- Prompt 与 Interview Skill 的内容边界、版本方式和最小输入。
- 完整当前对话、焦点、认识、未解部分、重要支线、最近问答、剩余额度、用户控制与来源状态怎样组织，以及按需检索怎样参与。
- 模式、阶段、焦点、认识、未解部分、支线、纠正和动作依据采用哪些运行字段。
- 用户可见消息分组、兼容字段与现有前端协议怎样适配。
- 生成失败、输出不合法、恢复重试和可信降级怎样承接。
- 两模式日志来源、状态恢复和现有事件中心底座怎样复用。
- Trace、评测运行器、候选血缘和发布隔离采用哪些具体接口。

这些问题需要在板块 6 正式评测资产齐备后，结合当前代码事实、最小改动范围和评测证据形成候选。板块 5 的 `GI-075～080` 作为冻结输入；历史字段名、Prompt 版本、Provider 分段和候选架构只提供风险与可行性证据。

## 7. 候选设计与验证顺序

板块 7 启动后按以下顺序推进：

1. **核对输入**：逐项确认板块 5 行为约定和板块 6 评测资产完整，发现冲突时回到对应上游板块处理。
2. **读取当前实现**：确认现有会话、可靠提交、恢复、日志、Trace、Provider 和发布隔离的真实边界。
3. **提出最小候选**：一次明确一个主要变化对象，并说明用户价值、兼容范围、风险与预期证据。
4. **冻结候选规格**：产品负责人确认后再形成开发执行计划；产品规则继续以板块 4～6 为准。
5. **实现与客观验证**：完成结构、计数、来源、控制、安全、恢复、兼容和构建检查。
6. **运行质量评测**：依次使用目标开发子集、相邻风险、独立准入集和受影响完整轨迹。
7. **形成候选裁决**：通过全部板块 6 准入门后生成板块 8 交接；失败时保留候选、证据和单一变量归因。

具体测试数量、阈值和人工复核比例以板块 6 当时冻结的正式资产为准。
