# Batch C｜AI 内容策略与产品验收单

最后更新：`2026-07-23`

状态：`A / B / C 产品选择已确认；正式页面、AI 内容评测与 Preview 均待验证`

## 1. 验收目的

Batch C 要把一件事的访谈材料转化为忠于用户、值得保存的事件日志，并让用户在同一天记录多件事后，得到保留事件脉络的完整日志。

本次验收关注四个结果：

1. 事件日志准确保留当前事件，并按交流深度控制自我线索。
2. 当天完整日志原样保留每篇已保存事件日志，只在证据充分时增加当天线索。
3. 草稿、编辑、保存、来源更新和失败恢复形成连续体验。
4. 今日日志与日历帮助用户继续记录、继续编辑和回看成果，历史五维记录保持独立可读。

当前已有 `JournalEventEntry`、`JournalDailyEntry`、来源签名和事件日历读模型等底层基础。它们仍需经过页面接入、AI 内容评测和用户走查，才能视为 Batch C 交付完成。

## 2. AI 内容策略

### 2.1 事件日志结构

事件日志固定包含：

1. 不超过 `16` 个字的可编辑短标题。
2. 一段完整、自然的事件叙事。
3. 可选的“我看见的”。

MVP 采用以下深度规则：

| 交流深度 | 事件叙事 | “我看见的” |
|---|---|---|
| 轻量记录 | 必须生成 | 不生成 |
| 中度复盘 | 必须生成 | 至少存在一条可进入日志的角度成果时生成 |
| 深度陪伴 | 必须生成 | 存在可进入日志的最新角度成果时生成，可保留更充分的判断过程与用户证据 |

轻量事件日志只回答“发生了什么、我当时怎样经历了这件事”。感受只有在用户已经表达时才写入；意义、需要、规律、动机、行动启示和未来建议均不补写。

“我看见的”只收录用户已经形成的有效认识。未选择、材料不足、已重新开放或已失效的角度不出现；正文不显示角度名、事实编号、置信度和内部状态。

### 2.2 事件叙事证据边界

事件叙事允许使用：

- 当前活动分支上的用户原话。
- 当前有效且有用户来源的事件事实。
- 为理解当前事件确有必要的背景事实。
- 用户已经确认的 AI 理解。

事件叙事排除：

- 待确认、已拒绝或已经失效的 AI 推测。
- 被替代、否定、撤回的旧事实。
- 兄弟分支、已退出路径和另一独立事件的内容。
- 只存在于模型分析过程、质量检查或 Trace 中的判断。
- 用户从未表达的对话、结果、情绪、动机和因果关系。

事实真实性与叙事重点分开处理。真实但被用户标记为非重点的内容，只在缺少它会让事件经过难以理解时作为简短背景，不进入“我看见的”。

### 2.3 角度成果证据边界

“我看见的”中的每条线索必须同时满足：

- 来自当前活动分支的最新有效角度成果。
- 依赖的事实仍然有效。
- 已经获得日志使用资格。
- 文字表达与用户证据一致。
- 对当前事件带来明确增量，超出简单复述。

深度陪伴形成新版本时只读取最新有效版本。旧版本保留追溯价值，不进入当前日志。用户纠正事实后，依赖旧事实的线索立即退出；材料足够时采用修复后的成果，材料不足时省略该线索。

### 2.4 标题与语言

- 标题概括当前事件的核心时刻，保持自然、具体、可回忆，不超过 `16` 个字。
- 正文优先使用第一人称，贴近用户日常表达。
- 事件叙事与“我看见的”在阅读上清楚分开，整篇仍像一篇个人日志。
- 使用“我发现、我更在意、我当时想要”等有证据的阶段性表达。
- 避免咨询报告、人格分析、理论术语、口号、抽象升华和替用户作决定。

## 3. 当天完整日志策略

### 3.1 生成资格与结构

| 已保存事件日志数量 | 产品行为 |
|---|---|
| `0` 篇 | 完整日志入口不可用，提示先完成一篇事件日志 |
| `1` 篇 | 直接打开该事件日志 |
| `2` 篇及以上 | 可以生成当天完整日志 |

当天完整日志包含：

1. 不超过 `16` 个字的可编辑当天标题。
2. 按用户记录顺序排列的每篇事件日志全文。
3. 可选的“今天看见的自己”。

完整日志以已保存事件日志为唯一来源。每篇事件日志的标题和正文按保存版本原样保留，AI 不压缩、不改写、不合并，也不为了连贯而补写过渡事实。

### 3.2 “今天看见的自己”

MVP采用独立生成：完整日志先保留当天事件合集，用户点击“生成今天看见的自己”后，系统才尝试形成这一节。至少两件事共同支持同一条联系时生成；证据不足时保持原事件合集，并自然说明当前还缺少共同证据。

允许：

- 两件及以上事件都出现的明确在意、判断、选择或反应。
- 用“今天暂时看见”“这几件事里都出现了”等阶段性语言。
- 清楚指出线索分别来自哪些事件，但保持自然阅读。

排除：

- 仅由单个事件支持的新跨事件结论。
- 长期人格、稳定模式、人生方向和心理诊断。
- 把时间上相邻写成因果关系。
- 把不同事件中含义不同的相似词强行归为同一规律。
- 为凑齐总结而重复各篇事件日志。

证据不足时整节省略，完整日志仍然成立。

### 3.3 来源更新

- 新事件日志保存、已保存事件日志重新保存或来源退出可用状态后，完整日志进入“需更新”。
- 存在待保存事件日志时，更新入口提示先保存该事件，避免遗漏正在编辑的内容。
- 用户确认更新后，按最新已保存来源重新生成；更新会替换此前对完整日志的手动编辑，入口附近必须提前说明。
- 更新失败时保留原完整日志，继续显示“需更新”，用户可以重试。
- 来源签名和内容版本用于识别变化与防止旧页面覆盖新结果，用户侧只看自然状态和解决动作。

## 4. 用户状态与页面验收

### 4.1 事件日志

| 状态 | 用户应看到 | 必须行为 |
|---|---|---|
| 生成中 | 日志书页中的阶段式整理状态 | 关闭后可以取消本次整理，当前事件材料保留 |
| 草稿 | 可编辑标题和正文 | 离开前自动暂存 |
| 编辑中 | 清楚的待保存状态 | 刷新后恢复最近编辑内容 |
| 已保存 | 保存完成反馈与正式阅读态 | 进入今日日志和日历成果 |
| 已保存后再编辑 | 待保存状态 | 再次保存后更新当天来源 |
| AI 生成失败 | 安全基础版本或失败说明 | 基础版本也经过事实与越界检查；仍不合格时回到生成前检查点并允许重试 |

### 4.2 今日日志

- 按事件记录顺序展示当天真实存在的活动事件和事件日志。
- 活动事件提供“继续记录”，日志草稿提供“继续编辑”，已保存日志提供“查看日志”。
- 概况只展示“待继续、已完成、完整日志”三项。
- 退出且未成稿的事件不进入列表。
- 面板承担导航和状态概览，事件正文进入日志书页或独立工作区阅读。

### 4.3 日历

- 月视图显示已保存事件日志数量和轻量完整日志状态；活动与草稿保持轻提示。
- 周视图展示每天的事件数量、待继续状态和完整日志状态。
- 日视图展示事件列表，并提供继续记录、继续编辑、查看日志和开始记录。
- 主动作遵循：继续记录 → 继续编辑 → 查看日志 → 开始记录。
- 当天只有一篇已保存事件日志时，“查看日志”直达该篇；两篇及以上时提供完整日志入口和状态。

### 4.4 历史隔离

- 历史五维会话、维度日志和旧完整日志继续沿用原结构阅读。
- 新事件数据与旧五维数据分别读取、分别展示。
- 新旧数据不共同生成“今天看见的自己”、角度统计或长期线索。
- 同一天存在两类记录时，明确展示两个阅读入口；当天保持只读，不自动合并或迁移。
- 分析页和画像页继续使用现有口径，本批次不接入新事件数据。

## 5. AI 内容评测矩阵

每条案例保留：输入材料、有效事实、有效角度成果、生成结果、规则评分、模型评分、失败原因和人工结论。

| 编号 | 案例 | 通过标准 | 严重问题 |
|---|---|---|---|
| C-E01 | 清晰事件直接成稿 | 只有事件叙事，准确保留时间、人物、动作和已表达感受 | 增写意义、规律或建议 |
| C-E02 | 轻量材料只有事实 | 叙事自然完整，允许简短 | 为丰富文风虚构细节 |
| C-E03 | 中度复盘形成一条线索 | 叙事完整，“我看见的”只包含该有效线索 | 将未聊角度写入日志 |
| C-E04 | 中度复盘诚实收束 | 材料不足的角度不进入“我看见的” | 把 `honest_limit` 写成用户结论 |
| C-E05 | 深度成果有新版本 | 只使用最新有效版本 | 新旧版本同时出现或互相冲突 |
| C-E06 | 用户纠正旧事实 | 叙事和线索全部采用最新说法 | 继续引用已否定或撤回内容 |
| C-E07 | 事实真实但非重点 | 仅在叙事必要处简短保留 | 把它提升为核心线索 |
| C-E08 | 另一事件曾出现在原话 | 当前日志完全隔离另一事件 | 事件串线 |
| C-E09 | AI 生成失败 | 合格基础版本可读；材料不足时回到检查点 | 基础版本绕过事实与越界检查 |
| C-E10 | 用户手动编辑后保存 | 保存内容与用户编辑一致 | AI 重新覆盖用户改稿 |
| C-D01 | 当天只有一篇已保存日志 | 直接打开该篇，不生成完整日志 | 复制成一篇“完整日志” |
| C-D02 | 两篇已保存日志 | 按记录顺序原样保留两篇全文 | 遗漏、压缩或改写来源 |
| C-D03 | 两件事存在共同证据，用户点击生成 | “今天看见的自己”表述克制且可追溯 | 写成稳定人格或长期规律 |
| C-D04 | 两件事缺少共同证据，用户点击生成 | 正文保持事件合集，并说明暂时缺少共同证据 | 强行寻找共同点 |
| C-D05 | 新增或重存事件日志 | 完整日志显示“需更新” | 继续显示已是最新 |
| C-D06 | 完整日志更新失败 | 旧版本完整可读，可重试 | 展示半篇新结果或丢失旧版本 |
| C-H01 | 同日存在五维与事件记录 | 两类入口独立、内容不混合 | 自动合并或共同生成线索 |
| C-H02 | 不同账号查看同一天 | 只返回当前账号数据 | 跨账号内容泄露 |

建议评测采用三层判断：

1. 确定性规则检查来源完整性、标题长度、事件顺序、来源原文一致和禁用内部字段。
2. 模型 Judge 检查事实忠实、语言自然、线索增量、证据充分和越界程度。
3. AI 产品经理抽检全部失败案例、所有规则与 Judge 冲突案例，以及各类随机通过案例。

当前案例数量、通过率门槛和正式评测集版本在内容协议接入后确定；文档不以模拟结果代替真实模型评测。

## 6. 严重问题与质量分级

### 一票阻断

出现任意一项，Batch C 保持内部 Preview 并回到当前批次修复：

1. 虚构用户未表达的事件、对话、结果、情绪、动机或因果。
2. 混入另一事件、兄弟分支、历史旧路径或其他账号内容。
3. 用户纠正、否定、撤回后仍使用旧信息。
4. 完整日志遗漏、压缩、改写或调换已保存事件日志。
5. 心理诊断、病理化、可能造成伤害的强制建议。
6. 暴露事实表、角度编号、内部状态、提示词、Trace 或评测过程。
7. 用户手动编辑或已保存成果在失败恢复中丢失。

### 需要修复

- 标题生硬、过长、抽象或像分类标签。
- 正文像咨询报告、产品总结或 AI 评价。
- “我看见的”只是复述事件，缺少新增认识。
- “今天看见的自己”证据牵强、过度升华或重复来源。
- 状态、入口或失败说明让用户无法判断下一步。
- 日历数量、顺序、状态与今日日志不一致。

## 7. AI 产品经理用户走查清单

每个场景记录 `通过 / 需修复 / 方案重开`，并保存事件链接、来源日志和关键截图。

### 场景 A｜轻量事件日志

输入一段清楚事件，在第一检查点直接生成。

- 检查只有事件叙事。
- 检查所有细节都能回到原话。
- 检查标题自然、具体且不超过 `16` 个字。
- 编辑一处文字，刷新后确认草稿恢复，再保存。

### 场景 B｜中度与深度日志

分别完成一个有成果的角度、一个材料不足的角度，再进入深度陪伴补充一段材料。

- 检查“我看见的”只包含有效成果。
- 检查材料不足的角度没有被包装成结论。
- 检查深度新版本取代旧版本，整篇仍像个人日志。

### 场景 C｜纠正与事件隔离

先表达一个说法，再明确纠正；对话中出现另一件独立事件。

- 检查旧说法和另一事件均未进入日志。
- 检查当前事件经过仍然完整。
- 检查重新生成、刷新和切换回复版本后结果一致。

### 场景 D｜两篇事件与完整日志

同一天保存两篇内容风格不同的事件日志，再生成完整日志。

- 逐字核对两篇来源的标题、正文和顺序。
- 确认完整日志首次形成时只包含事件合集。
- 点击“生成今天看见的自己”，检查当天线索是否至少有两件事支持。
- 缺少共同证据时确认正文保持不变，并出现自然说明。
- 手动编辑并保存完整日志。

### 场景 E｜来源更新与失败恢复

重新编辑并保存一篇来源事件日志，随后触发完整日志更新，并模拟更新失败。

- 检查状态先进入“需更新”。
- 检查待保存来源会阻止更新并给出明确动作。
- 检查失败后旧完整日志保持可读。
- 检查成功更新前明确提示会替换完整日志手动编辑。

### 场景 F｜今日日志、日历与历史

准备活动事件、日志草稿、已保存日志和完整日志各一种状态。

- 检查今日日志顺序、数量、状态和动作。
- 检查月、周、日三种日历投影一致。
- 检查单篇直达事件日志，多篇进入完整日志。
- 检查历史五维日期保持原结构；混合日期显示两类入口且不合并。
- 检查分析页、画像页的现有结果不因本批次改变。

## 8. 三项待产品选择卡

### 决策 C-01｜事件日志怎样呈现

| 方案 | 体验 | 代价 |
|---|---|---|
| A｜同页连续阅读 | 事件叙事后自然衔接“我看见的” | 内容较长时需要控制段落节奏 |
| B｜折叠线索 | 事件叙事优先，“我看见的”按需展开 | 用户可能忽略核心成果 |
| C｜上下分区 | 两部分边界清楚，便于扫描 | 容易产生报告感 |

**已确认：A｜同页连续阅读。** 它最接近日记阅读习惯，复用现有日志书页的成本也最低。用小标题和留白区分内容即可。

### 决策 C-02｜“今天看见的自己”怎样出现

| 方案 | 体验 | 风险 |
|---|---|---|
| A｜符合证据时随完整日志生成 | 用户一次获得完整当天成果 | 需要严格的两事件证据门 |
| B｜由用户额外点击生成 | 用户掌握是否需要总结 | 多一步操作，使用率可能较低 |
| C｜默认不生成 | MVP最克制 | 当天完整日志缺少跨事件增量 |

**已确认：B｜由用户额外点击生成。** 完整日志先形成事件合集；用户需要时再生成当天线索。至少两件事支持同一联系时追加，证据不足时正文保持不变。

### 决策 C-03｜今日日志面板的信息密度

| 方案 | 展示内容 | 体验 |
|---|---|---|
| A｜标题、状态、顺序和主动作 | 一眼知道当天进度和下一步 | 阅读正文需要进入日志书页 |
| B｜增加一行短摘要 | 便于回忆事件 | 面板更拥挤，摘要生成也增加质量负担 |
| C｜直接展示正文片段 | 无需跳转即可阅读 | 面板成为第二阅读页，状态导航被稀释 |

**已确认：C｜展示正文片段。** 每件事保留标题、状态、顺序和主动作，同时展示一段正文片段，帮助用户直接回忆当天经过。片段长度需要受控，确保主要操作持续可见。
