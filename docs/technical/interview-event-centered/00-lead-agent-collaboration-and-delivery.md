## 1. 协作目标

事件中心重构的核心价值来自 AI 访谈质量。提问是否准确、自然、有增量价值，决定用户是否愿意继续表达，也决定最终日志是否值得保存。

后续协作采用三条原则：

1. AI 产品经理深度参与 AI 能力、逐轮提问策略、质量标准和用户体验设计。
2. LeadAgent 负责技术设计、工程实现、Subagent 调度、集成、测试、Preview 和文档维护。
3. 每批次开发前先完成复用调查；现有能力能够承载新结果时直接复用或扩展。

统一闭环为：

```text
批次原则与 AI 策略共同确认
→ LeadAgent 调查现状并冻结公共契约
→ Subagent 在独立工作树并行开发
→ LeadAgent 集成、测试、AI 评测和修复
→ 提供独立 Preview 与验收材料
→ AI 产品经理完成用户级验收
→ 进入下一批次
```

## 2. 决策权边界

### 2.1 AI 产品经理确认事项

以下事项需要形成明确产品结论后，相关开发线才能继续：

1. AI 怎样理解用户表达、事件边界、背景和另一事件。
2. AI 每轮为什么提问、提问目标、追问路径和停止时机。
3. 用户不同回答怎样影响下一问、回应、收束或检查点。
4. 四个角度的轮次策略、完成标准、深度边界和越界红线。
5. 自然理解、自然回应、事件日志和当天线索的质量标准。
6. AI 失败、信息不足、用户拒绝和无法确认时的用户体验。
7. AI 评测维度、代表性案例、严重问题和发布门槛。
8. 每批次前端可操作 HTML 的方案选择。
9. 每批次 Preview 用户验收和最终发布决定。

### 2.2 LeadAgent 自主事项

LeadAgent 在已确认产品目标和 AI 策略内自主完成：

- 数据结构、接口、事务、迁移和历史兼容。
- Prompt 的工程组织、结构化输出协议和模型调用方式。
- 幂等、并发、缓存、重试、降级、Trace 和监控。
- 代码组织、Subagent 分工、工作树、分支集成和技术审查。
- 已确认前端方案的组件实现与工程适配。
- 自动化测试、完整回归、构建、Preview 部署和技术文档。

### 2.3 新产品门处理

开发中出现以下情况时，LeadAgent 暂停受影响开发线，继续其他独立任务，并提交决策卡：

- 用户旅程、入口、操作或可见状态需要实质变化。
- AI 理解范围、推测边界、回应方式或质量标准需要变化。
- 用户数据、隐私、成果覆盖或不可逆处理出现新风险。
- 发布门槛、质量门槛、MVP 范围或回退条件需要变化。

决策卡固定包含：用户场景、已知事实、推荐选择、其他选择、产品影响、实现影响和验收方式。

## 3. AI 能力共同设计方法

### 3.1 逐轮共同设计

AI 访谈提问策略采用逐轮共同设计。顺序为：

1. 四角度公共访谈协议。
2. 理解感受第一问、第二问、第三问和深度陪伴。
3. 理清想法第一问、第二问、第三问和深度陪伴。
4. 梳理关系第一问、第二问、第三问和深度陪伴。
5. 复盘行动第一问、第二问、第三问和深度陪伴。
6. 公共问题修复、拒绝、未知回答、停止和降级策略。

每个角度策略确认后即可进入独立开发；下一角度的产品讨论可以同步继续。四个角度完成集成后统一进入批次 B Preview 验收。

### 3.2 AI 策略板

每项 AI 能力统一回答：

1. 用户此刻希望获得什么。
2. AI 已经拥有哪些可信信息。
3. 当前轮次希望新增什么认识。
4. 为什么此时值得提问。
5. 推荐问题及表达方式。
6. 不同回答对应的下一步。
7. 何时继续、换方向、回应或收束。
8. “没有、不知道、不想继续、问题看不懂”等边界怎样处理。
9. 允许的推测范围和越界红线。
10. 好问题、普通问题和严重问题示例。
11. 自动评测标准与人工验收场景。

### 3.3 提问质量基线

每个问题需要满足：

- 服务当前事件和当前角度。
- 每次推进一个清楚目标。
- 用户容易理解和回答。
- 已表达内容得到吸收，后续问题具有新增价值。
- 用户边界得到尊重，完成条件成立时及时收束。
- 事实、推测和角度解释保持清楚来源。
- 避免心理诊断、人格归因、他人动机断言和未经请求的行动建议。

## 4. 复用优先机制

### 4.1 批次复用清单

每个批次技术设计前必须登记：

| 分类 | 处理方式 |
|---|---|
| 已满足新目标 | 直接复用 |
| 基础能力可用，协议需要扩展 | 在原能力上扩展 |
| 新旧职责需要隔离 | 保留旧链路并增加适配层 |
| 仓库缺少对应能力 | 新增实现并记录原因 |

技术方案的“当前实现事实”和“可复用能力”章节共同承担复用证据。代码审查需要检查新增能力是否与既有实现重叠。

### 4.2 优先复用的 AI 能力

- `InterviewUserTurn`原话可靠保存、幂等提交和失败续接。
- 现有意图识别、纠正优先和边界意图处理。
- `question-protocol`、`question-realizer`和各维度已有提问策略。
- 确定性问题修复、重复问题防线和低压力选择。
- 自然理解层、回复重新生成、活动分支和 checkpoint。
- `AIGenerationTrace`、Prompt 血缘、质量评分、Badcase、回放和发布回退能力。

### 4.3 优先复用的前端能力

- 现有访谈工作台、消息区、输入区和回复组。
- 纠正理解、换问法、反馈和失败续接入口。
- 今日日志面板、日志工作区和生成状态体验。
- 月、周、日日历工作台及其读模型。
- `Surface / Card / SectionHeading / Divider / ActionButton`等共享原语。
- 现有暖纸色视觉系统、圆角、边框、动效和无障碍规范。

### 4.4 复用与扩展边界

| 能力 | 默认处理 |
|---|---|
| 事件中心可靠提交、`clientTurnId`幂等、消息版本并发校验 | 直接复用 |
| 模型运行时、结构化输出解析、AI Trace、Prompt血缘、规则评分、Judge和回放 | 直接复用 |
| T1-03事实修订投影与原子修订 | 技术验证通过后直接作为T1-04上游契约 |
| 意图识别和操作决策 | 扩展事件选择、角度选择、检查点和事件生成动作 |
| 公共提问协议、问题生成器和确定性修复 | 扩展四角度目标、轮次深度、停止规则和专项修复模板 |
| 自然理解层 | 复用内部解释到用户可见理解的投影方式，增加事件与四角度语义 |
| 换问法、回复版本和活动分支 | 复用版本与分支机制，接入稳定`eventId`和有效事实投影 |
| 输入草稿与outbox | 复用恢复机制，增加事件中心身份与动作适配 |
| `InterviewShell`、今日日志和日历 | 复用布局与交互，通过事件中心适配层接入新状态和读模型 |

### 4.5 新增能力边界

新增实现集中在：

1. 当前事件、背景和另一事件的分级边界判断。
2. 四角度成果、来源事实、有效性、失效原因和重算关系。
3. AI产品经理确认后的四角度逐轮提问策略与专项评测集。
4. 事件中心检查点与用户控制状态。
5. 纠正后的角度线索自适应更新、移除和重新开放。
6. 一事件一日志、日级事件来源和新旧读模型适配。

五维槽位、完成条件和五维正文策略继续保持原链路职责；事件中心通过公共协议和适配层复用运行能力。

## 5. 前端 HTML 设计门

每个批次进入正式前端开发前，LeadAgent 提供一份可操作 HTML 原型：

1. 沿用现有视觉规范、组件形态和页面结构。
2. 集中展示本批次新增或变化的完整用户流程。
3. 在同一份 HTML 内切换两至三个关键布局或交互方案。
4. 覆盖空白、进行中、检查点、生成中、完成、失败和恢复等相关状态。
5. 标注直接复用、扩展和新增部分。
6. 给出 LeadAgent 推荐方案和选择原因。
7. AI 产品经理选定方案后，LeadAgent 冻结交互契约并进入正式前端开发。

原型位置：

```text
docs/prototypes/interview-event-centered/
├── batch-a-core-runtime.html
├── batch-b-ai-interview.html
├── batch-c-outcomes-and-pages.html
└── batch-d-release-observability.html
```

HTML 是产品设计决策材料；正式实现继续使用仓库现有 React 组件和共享设计原语。

## 6. 四个交付批次

| 批次 | 范围 | AI 产品经理共同设计 | 产品验收重点 |
|---|---|---|---|
| A｜核心运行骨架 | 完整验收覆盖阶段1至3；接管后开发T1-04至T1-08、阶段2至3 | 事件边界、事实理解、纠正传播、未知与冲突案例、批次A HTML | 统一入口、事件隔离、纠正、检查点、刷新恢复与用户控制 |
| B｜AI访谈能力 | 阶段4至5 | 公共协议、四角度逐轮提问、深度陪伴、修复、停止、批次B HTML | 四角度真实对话、自然理解、问题质量、重新生成与边界 |

阶段继续承担技术依赖与文档组织；批次承担产品确认、Preview 和用户验收门。

## 7. 已确认的批次 A 原则

### 7.1 角度线索自适应修复

事实纠正使已完成角度线索失效时：

- 最新材料仍足够：基于最新有效事实更新线索。
- 最新材料不足：移除失效线索，并把该角度重新开放给用户选择。

### 7.2 事件边界分级澄清

- 当前主线清楚时直接继续。
- 两件独立事件都可能成为主线时，只提出一次聚焦选择。
- 过去经历只承担解释作用时，作为当前事件背景继续处理。

## 8. LeadAgent 与 Subagent 开发机制

### 8.1 接管条件

T1-03 的技术回传、核对、数据库检查与完整回归已经完成。LeadAgent 已从 T1-04 正式接管，并采用以下连续执行方式：

1. 每个子题先恢复产品事实、阶段契约和最新代码状态。
2. LeadAgent 维护公共数据关系、核心事务和最终集成。
3. Subagent 分别承担独立实现、持久化验证和代码审查。
4. 每个子题完成定向测试、完整回归、真实迁移与生产构建后回填事实文档。
5. T1-04 已完成角度成果与自适应修复底座；当前从 T1-05 继续批次 A。

### 8.2 并行配置

- LeadAgent：公共契约、集成、冲突处理和最终验证。
- 最多两个实现 Subagent：在独立分支和工作树开发互不重叠的模块。
- 一个审查或评测 Subagent：独立检查、回归和 Badcase 验证。

数据库结构、migration、公共类型、核心状态机和核心事务保持单一负责人。公共契约冻结后，仓储、AI能力、评测、日志、读模型和页面可以按边界并行。

每个 Subagent 必须回传：提交编号、变更文件、测试命令与结果、方案差异、遗留风险和后续影响。LeadAgent 统一完成集成、全量验证和文档回填。

## 9. 质量与批次验收

每个内部里程碑至少完成定向测试；每个批次交付前统一完成：

- 数据迁移和历史兼容验证。
- 定向测试、完整回归、类型检查和生产构建。
- AI 正反例评测、独立保留集和严重问题检查。
- Preview 主链走查、失败恢复和可访问性检查。

每批次向 AI 产品经理提供：

1. AI 策略与评测说明。
2. 一份内含多方案的可操作 HTML。
3. 独立 Preview 地址和测试账号。
4. 五至十个核心用户场景。
5. 自动化测试与 AI 评测摘要。
6. 已知限制和下一批次影响。

验收结果继续使用`验收通过 / 验收后修复 / 方案重新打开`。生产发布只在批次 D 完成，并由 AI 产品经理确认最终发布决定。

## 10. 文档维护

- 产品规格保存用户体验、AI行为、质量标准和验收场景。
- 重构讨论地图保存批次状态、产品决策、开发状态、Preview 和验收结果。
- 阶段技术方案保存技术选择、实施顺序、测试证据和方案差异。
- 本文档保存长期协作、AI共同设计、复用、HTML原型和Subagent规则。

每次恢复工作时先读取产品规格、讨论地图、本文档、当前阶段方案和最新代码，再继续当前批次。
