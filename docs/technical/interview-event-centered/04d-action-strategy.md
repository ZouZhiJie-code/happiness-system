## 板块 3–4 原冻结基线与当前校准

本文继续保存 `0.20` 的复盘行动实现基线。生成式目标产品要求有效成果带来认识增量，只使用当前有效事实并保持行动角度与安全边界；内容成立而表达晦涩时直接重写，不增加回答机会。`honest_limit` 在目标产品中只承担收束说明，不构成角度成果或日志认识。

原“关键选择 → 目标、推进效果、有效条件或阻力”继续作为证据基础。`3.29.0` 用户裁决表明，复述动作顺序或继续收集点击对象、时间和步骤，无法形成行动认识。生成式成果现改为：识别选择发挥了什么作用、保护了什么、受到什么阻力影响，或形成了什么取舍。

### 当前提问标准

- 引导复盘聚焦已发生的行动，帮助用户看见关键选择的功能、阻力或取舍。
- 深度聊天继续理解行动背后的价值、自我表达、当时需要和选择所保护的内容。
- 问题优先使用已经发生的关键时刻，探索用户为何继续、停住或反复，而非收集下一步点开了什么。
- 用户明确强调“代表自己、认真准备、想保护准确性”等意义线索时，优先沿该线索推进。
- 未来计划和下一次尝试继续退出当前 MVP 的正式成果；用户主动求建议时自然回应，并保持事实与选择权边界。

## 1. 用户结果

复盘行动帮助用户看清当时想推进什么、实际做了什么选择，以及什么条件推动或阻碍了行动。生成式引导复盘形成“关键选择 → 推进关系”后及时收束；用户明确请求建议时由模型在公共事实与安全底线内自主回应。`0.20` 当前实现继续使用“先确认一个关键条件，再给少量带取舍备选”的协议。

## 2. 自适应路径（`0.20` 现有实现基线）

默认目标顺序为：

```text
当时目标
→ 关键选择
→ 有效条件或阻力
→ insight / honest_limit
```

策略会跳过已经被可信事实覆盖的目标。当时目标和关键选择保持为必经路径；后续候选问题先通过新增价值门槛，再按容易回答、具体程度排序。现有事实已经支持一条关于目标、选择、有效条件或阻力的新增认识时，可以零问收束。

问题示例：

- 当时目标：“这件事发生时，你当时最想推进的一件事是什么？”
- 关键选择：“为了推进这件事，你当时实际做出的关键选择是什么？”
- 条件或阻力：“哪个具体条件最影响这次选择能不能推进？”

### 生成式目标产品

- 当前材料已经把关键选择与目标、推进效果、有效条件或阻力连接起来时，零问形成成果。
- 关系缺少一部分、且一个具体问题很可能帮助用户看清选择怎样影响推进时，继续一问。
- 最低成果成立后立即进入第二检查点；下一次尝试和行动计划留给用户主动进入的深度聊天。
- 用户主动求建议时，模型在公共事实与安全底线内自主回应，不设置生成式 MVP 的专用必经流程。
- 代表案例：用户说清“临时改方案后先删掉非核心细节、保住汇报主线，最后按时讲完”时，AI 零问完成。

## 3. 建议协议（`0.20` 现有实现基线）

`0.20` 当前实现中，用户明确请求建议时执行：

```text
检查是否已有关键条件
→ 缺少时只澄清一个条件
→ 条件明确后生成 2–3 个备选
→ 每个备选说明一项主要取舍
```

建议表达保持选择权：

- 过滤“你应该、你必须、唯一办法”等强制表达。
- 最多保留三个有明确取舍的备选。
- 过滤后少于两个可用备选时，本轮写入 `honest_limit`，避免用单一答案伪装用户选择。
- 建议条件澄清也计入三次回答机会。
- 中度复盘已经达到三次回答机会且关键条件仍缺失时，当前角度先收束；用户可在深度陪伴继续讨论建议。

生成式目标产品不把这套建议步骤设为必经路径；模型根据当前表达自主回应，并继续遵守事实、安全、选择权和角度边界。

## 4. 未知、停止与上限

- 当前无法形成最低成果，且继续提问也难以带来明显新认识时，展示 `honest_limit` 收束说明，角度成果保持为空。
- “没有、不知道、想不起来、说不清、都不贴切、没法再具体、不想答”等用户边界继续交由公共保护层稳定执行。
- 最多创建三次回答机会；问题修复形成新的回答机会时由公共层正常计数，回复版本切换继续复用当前机会。
- 用户要求停止时立即收束；已有可信认识继续保留。
- 行动成果只总结已经发生的目标、选择、条件和阻力，不把建议写成用户事实。

## 5. 工程契约

公共编排调用同一入口：

```ts
decideRelationshipOrActionStrategy(input)
```

行动角度使用：

- `angle = action`
- `facts / coveredTargets / askedTargets`：事实包含编号与文本，用来决定下一项最有增量的目标。
- `candidateAssessments`：候选问题的新增价值、回答难度和具体程度评估。低价值候选退出本轮选择；通过门槛后优先选择更容易回答、更具体的问题。
- `supportedOutcome`：必须携带成果陈述、依赖事实编号、新增价值和证据强度。依赖全部属于当前事实、价值达到 `meaningful`、证据达到 `clear` 后才可生效。
- `adviceRequested / adviceCondition / adviceOptions`：建议请求、已确认条件和生成后的备选。
- `questionOpportunityCount`：公共状态层持有的计数。历史快照中的`lowPressureAnchorUsed`继续可读，新会话不再写入。

返回：

- `ask`：继续一个问题，并返回现有问题协议可直接使用的 `questionSpec`。
- `outcome`：形成 `insight / honest_limit`。
- `advice_options`：关键条件已经明确，进入少量备选表达。

## 6. 验证重点

- 按目标、选择、条件/阻力顺序自适应推进。
- 事实充分时零问收束。
- 明确求建议后先补一个关键条件。
- 建议数量不超过三个，每项保留取舍，强制性建议被过滤。
- 文本否定或无法继续时直接收束。
- 三次回答机会后强制收束。
- 回答机会计数必须是 `0–3` 的整数；异常状态直接交给公共恢复链路处理。
