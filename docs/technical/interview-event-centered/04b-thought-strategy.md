# 批次 B 附录｜理清想法策略

状态：`策略模块与定向测试已完成，等待公共编排层接入`

## 1. 用户结果

理清想法帮助用户说清当时怎样理解、判断和衡量。中度复盘专注澄清已经出现的想法，另一种解释和认知挑战留给用户主动进入的深度陪伴。

## 2. 自适应路径

基础路径固定为：

```text
当时念头 → 判断所依据的具体事实
```

基础路径完成后，只把原话已经呈现迹象的方向放入候选：

- 默认期待。
- 衡量标准。
- 取舍条件。

候选问题先通过新增价值门槛，再按好回答程度和具体程度排序。中度问题保持一个目标，不要求用户同时解释原因、比较其他观点和总结规律。

## 3. 收束与边界

- 可信事实已经支持一句新增认识时，允许零问收束为`insight`。
- “没有、不知道、想不起来、说不清、都不贴切、没法再具体、不想答”后直接收束；已有材料形成`insight`，其余情况形成`honest_limit`。
- 第三次回答机会用尽后立即收束。
- 用户要求停止时立即收束。
- 中度阶段不主动提出“另一种理解”，也不挑战用户判断。
- 成果只能依赖当前活动事实，事实不足时诚实保留当前范围。

## 4. 问题质量

问题使用确定性模板，并通过现有理解质量门。代表性问题：

- “当时脑子里最先冒出来的具体念头是什么？”
- “当时哪个具体事实最影响你这样判断？”
- “你当时最看重的一个具体衡量点是什么？”

## 5. 接入契约

公共编排层调用`decideFeelingOrThoughtStrategy`。策略返回`ask`时包含问题目标、问题文本、表达层级和下一回答机会计数；返回`outcome`时包含`insight / honest_limit`及自然陈述。

现有问题修复和回复版本能力继续由公共层使用。修复形成新的回答机会时更新计数；用户回答前切换回复版本时沿用原计数。
