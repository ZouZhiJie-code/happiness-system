# 04｜四角度公共访谈协议

最后更新：`2026-07-23`

版本：`0.16`

状态：`A｜对话内纸笺正式接入完成；MVP文本边界、第一检查点最低成果与单目标回复质量修复已落实，等待模型额度恢复后的全量回放`

## 1. 背景、原因与用户结果

事件中心把用户的进入方式从“先选维度”调整为“先讲一件事”。四个角度共享同一事件事实，也需要分别保持提问目标、完成标准和越界边界。公共协议承担三项结果：

1. 清楚事件能够快速进入第一检查点，用户可以停在轻量记录。
2. 用户选择角度后，每个新问题都有新增价值，通常一至两问、最多三次回答机会。
3. AI能够在事实充分时及时收束，在材料有限时诚实保留范围，在深度陪伴中允许只回应而不机械追问。

本协议是阶段 4 与阶段 5 的共同契约。角度专项策略见：

- [理解感受](./04a-feeling-strategy.md)
- [理清想法](./04b-thought-strategy.md)
- [梳理关系](./04c-relationship-strategy.md)
- [复盘行动](./04d-action-strategy.md)
- [评测与 Badcase](./04e-batch-b-evaluation-and-badcases.md)

## 4. 可复用能力与职责变化

| 能力 | 处理方式 | 在事件中心的职责 |
|---|---|---|
| 原话可靠保存、outbox、同轮续接 | 直接复用 | AI失败前先确保用户表达可恢复 |
| 意图识别与纠正优先级 | 扩展复用 | 把内容、纠正、停止、修复和明确按钮动作分开 |
| `question-protocol`、`question-realizer`、`comprehension-gate` | 扩展复用 | 继续约束单一目标、具体锚点、可回答性和问题降级 |
| 问题修复 | 扩展复用 | 保持当前事件与角度，形成新的回答机会 |
| 回复重新生成和活动分支 | 适配隔离 | 使用稳定`eventId`，切换时同步恢复事实、成果和问题版本 |
| 自然理解、Trace、Prompt血缘和质量评分 | 扩展复用 | 使用事件专属结构协议与质量口径 |
| 事件事实和角度成果 | 直接消费 | 成为问题、成果和日志的可信来源 |
| 事件对话阶段与四角度策略 | 新增 | 替代五维阶段推进，承担检查点和角度节奏 |

五维理论字段、五维完成条件和五维日志质量门继续服务历史链路，不参与事件中心策略判断。

## 5. 最终技术选择及原因

### 5.1 轻量记录

1. 能辨认用户想留下的核心经历或时刻时，直接进入第一检查点。
2. 感受、原因、意义和行动都不构成第一检查点的必答项。
3. 事件过于模糊且用户尚未表达无法继续时，只增加一次事实锚点；用户表达否定或无法继续时直接进入第一检查点。
4. 两件并列事件都可能成为主线时，只做一次聚焦选择；背景经历作为背景，另一独立事件保持隔离。
5. 第一检查点前只整理已有证据，不提出缺少原话支持的新推测。
6. 第一检查点的最低成果是当前版本的事件；材料有限时保留严格受现有材料约束的轻量记录，不包装成洞见。

这样可以保护“先把一件事留下”的低门槛价值，并让深入探索保持用户自愿。

### 5.2 中度复盘公共节奏

1. 四个角度平级，由用户通过检查点明确选择，AI不推荐。
2. 各角度先完成必经目标，再把剩余候选问题放入评估。
3. 候选问题先达到新增价值门槛，再按容易回答、具体程度排序。
4. 当前事实已经支持一条有新增价值的认识时允许零问收束；换词复述不能成为成果。
5. 每个新问题只推进一个目标。
6. “没有、不知道、想不起来、说不清、都不贴切、没法再具体、不想答”直接结束当前角度，不追加问题。
7. 每个角度最多创建三次回答机会。问题修复形成新问题时计数；用户回答前切换同一位置的回复版本不计数。
8. 达到上限后写入可信`insight`或`honest_limit`，随后进入第二检查点。

### 5.3 四角度共同契约

| 角度 | 必经目标 | 可选增量方向 | 完成边界 |
|---|---|---|---|
| 理解感受 | 直接体验、具体触发 | 变化、混合感受、身体状态、有证据的在意/需要/边界 | 对感受形成比原话更准确的区分 |
| 理清想法 | 当时念头、判断依据 | 默认期待、衡量标准、取舍条件 | 说清当前判断及其依据；另一种解释留在深度陪伴 |
| 梳理关系 | 实际互动 | 期待回应、位置、信任、互惠或边界 | 看见用户重视什么；不推测他人动机，不替用户作关系决定 |
| 复盘行动 | 当时目标、关键选择 | 有效条件、阻力、可调整部分 | 看见目标、选择或影响条件；明确求建议时先澄清一个条件 |

各角度成果必须显式引用当前活动路径事实。依赖事实全部存在、证据清楚且具有新增价值时，`insight`才能生效；事实有限时使用`honest_limit`。一个角度自然出现的内容可以成为共享事实，不会自动完成另一个角度。

行动建议只在用户明确请求后出现。系统先确认一个关键条件，再生成两至三个各自说明主要取舍的备选；过滤后缺少足够可用选项时诚实收束。

### 5.4 推测与深度陪伴

- 角度内只有事实已经呈现清楚迹象时，允许自然理解包含一个可能性推测。
- 推测必须与内部待确认命题一致，纠正轮、轻量记录和角度成果只使用已经获得事实资格的内容。
- 深度陪伴默认先吸收、回应和整理。只有存在具体未理解点、答案会实质改变当前理解或未来日志、用户没有表达停止边界时才继续提问。
- 深度补充实质改变或补足旧线索时，追加不可变成果新版本；活动投影只读取最新有效版本。

### 5.5 用户控制

- 自然语言“换个角度”保持当前角度和问题，并提示用户在检查点手动选择。
- “换种问法、简单点、看不懂”修复当前问题，并形成新的回答机会。
- “没有、不知道、想不起来、说不清、都不贴切、没法再具体、不想答、不想继续、先停下”优先停止施压并按现有材料收束。
- “看不懂、简单点、换种问法”继续使用问题修复，维持当前问题和回答机会规则。
- 事件选择、角度选择、继续深入、退出和未来的生成日志均通过明确动作改变状态。

## 6. 领域对象、状态和数据所有权

### 6.1 状态所有权

`InterviewEvent.snapshotData`中的事件协议版本 3 保存可重建缓存：

- `phase`：`event_recording / event_focus_clarification / checkpoint_one / guided_reflection / checkpoint_two / deep_companionship`。
- `activeAngle / lastCompletedAngle`。
- 每个角度的状态、回答机会计数、已问目标和已回答目标；历史快照中的低压力锚点字段继续可读，新会话不再写入。
- 当前问题目标、表达层级、回答机会编号、修复次数和消息位置。
- 待确认推测、待修复角度成果和最近处理轮次。

缓存只负责恢复对话进度。可信信息分别由以下对象持有：

| 信息 | 权威所有者 |
|---|---|
| 用户原话与可靠轮次 | `InterviewUserTurn` |
| 当前有效事实与修订 | `JournalEventFact`及其修订关系 |
| 待确认AI推测 | `JournalEventUnderstandingClaim` |
| 四角度成果及依赖 | `JournalEventAngleOutcome`及事实引用 |
| 用户当时看见的自然理解与回应 | `InterviewMessage`中的事件助手载荷 |
| Prompt、模型尝试与质量判断 | `AIGenerationTrace`及Prompt血缘 |
| 事件身份和终态 | `JournalEvent` |

### 6.2 状态不变量

- 中度角度的回答机会只能是`0–3`整数，异常状态直接失败并进入恢复链路。
- 一个时间点最多一个活动角度和一个当前问题。
- 第一检查点没有活动角度；第二检查点保存最近完成角度。
- 角度成果只引用当前有效事实，`honest_limit`完成角度但不进入日志候选。
- 待事实澄清或角度修复时，向前动作继续受现有门禁保护。

## 7. 输入、输出、接口与数据流

### 7.1 AI结构协议

`EventCenteredUnderstandingDecision`输出：

- 当前事件、背景、另一事件、两件并列事件或边界不清。
- 核心事件是否可辨认，以及本轮属于有效回答、未知、拒绝、纠正或无关内容。
- 只引用本轮原话精确摘录的事实候选。
- 四角度证据及是否可能形成新增认识。
- 可空的成果候选、单个无原话推测、建议请求、纠正目标和边界原因。

`EventCenteredAssistantPayload`输出：

- `naturalUnderstanding`。
- `naturalResponse`。
- 回应类型。
- 可空的问题规格、检查点和自然角度成果。

理解决定与自然表达分两次结构化生成。确定性策略层拥有阶段、活动角度、问题目标、回答机会和检查点的最终决定权；模型负责理解内容和自然表达。

### 7.2 工作台读写契约

统一工作台读模型返回：

- 活动分支完整可见对话与原话。
- 当前阶段、活动角度、完成/可选/重新开放角度、自然成果和检查点。
- 当前允许动作与三段进度。
- 回复版本与活动分支。
- 待恢复轮次、错误码、尝试次数。
- 事件日志的只读状态占位；正文能力由批次 C 接入。

统一流式写入请求以`rootSessionId + clientTurnId`标识可靠操作，并携带活动分支、基础消息序号、动作、原话、角度、事件选项、目标消息或重新生成意图。流式响应继续复用`turn / summary / message / session / error`语义，事件模式返回事件专属工作台。

### 7.3 每轮数据流

```text
可靠保存用户轮次或按钮动作
→ 校验事件、活动分支和基础消息序号
→ 区分内容、纠正、停止、修复和明确动作
→ 处理待确认推测、事实冲突与事实修订
→ 读取活动路径事实、角度成果和对话状态
→ AI生成结构化理解决定
→ 确定性策略决定回应、下一问、成果或检查点
→ AI生成自然理解与自然回应
→ 校验原话摘录、事件边界、推测、成果依赖、重复、增量和越界
→ 提交消息、事实、成果、状态、Trace与checkpoint
→ 流式返回最新工作台
```

## 8. 用户纠正、重试、恢复和并发规则

### 8.1 纠正

- 纠正意图优先于隐式确认和普通内容处理。
- 纠正先提交事实修订、推测拒绝和角度失效传播，再生成自然回应。
- 纠正轮不产生新的无原话推测。
- 旧成果依赖失效时立即退出；材料充分时追加替代版本，材料不足时重新开放角度。

### 8.2 问题修复与回复版本

- 修复保持当前事件、角度和问题目标，降低表达难度或增加具体锚点。
- 修复形成新的回答机会，计数最多到三。
- 回答前重新生成或切换同一位置的回复版本复用当前回答机会。
- 活动回复版本变化时，问题、事实投影、成果投影和checkpoint一起切换。

### 8.3 失败续接与并发

- 原话或动作可靠落库后，后续AI失败不会丢失输入。
- 同一`clientTurnId`续接只补齐未完成阶段，不重复保存原话、事实、推测或成果。
- 状态落后的并发请求返回`409 EVENT_STATE_CHANGED`，页面刷新最新对话并保留输入框/outbox内容。
- 回复结果提交前复检活动分支和基础消息序号；迟到结果不能覆盖新状态。
- 刷新恢复当前阶段、问题、角度计数、待恢复轮次和活动回复版本。

## 9. 数据演进与历史兼容

- 事件对话继续使用`conversationSchemaVersion = 3`和`kind = event_centered`。
- 新状态字段由严格schema读取；无法解析的事件缓存回到安全初始状态，并保留事实、消息和可靠轮次供恢复。
- 历史五维会话不生成事件状态、事件事实或四角度成果。
- 旧五维API、Prompt、回复协议、日志和日历读取保持独立。
- 事件中心Prompt使用独立key、版本和Trace归因，避免与五维质量数据混合。

## 10. 失败降级、可观测性和回退方式

### 10.1 降级

- AI理解不可用或原话摘录校验失败时，使用保守理解，只保存可直接从原话确认的内容。
- 自然表达不可用或与推测/成果不一致时，使用确定性策略文案。
- 候选问题未达到新增价值或问题质量门时，换用安全模板；仍无合格问题时收束为`honest_limit`。
- 角度成果缺少当前事实依赖、证据不清或只复述原话时不生效。
- 建议过滤后不足两个可用备选时，不输出单一强制答案。

### 10.2 可观测性

每轮Trace至少记录：

- 事件、根会话、活动分支、用户轮次和动作。
- Prompt版本、解析/修复尝试、输出来源和耗时。
- 事件边界、事实候选、推测、问题目标、回答机会变化和阶段迁移。
- 成果候选、支持事实、价值/证据判断、拒绝原因和质量问题。
- 问题修复、回复版本、失败续接和并发冲突。

### 10.3 回退

- Batch B只进入内部Preview。
- Production继续使用五维入口和五维写入链路。
- `event_recovery`可以停止事件新写入并保留既有事件数据只读恢复。
- 回退不删除、不转换事件数据，也不反向迁移历史五维数据。

## 11. 分步骤开发顺序

1. 冻结事件对话状态、助手载荷和统一工作台类型。

5. 接入统一策略编排、事实/成果提交、Trace和checkpoint。
6. 接入纠正、问题修复、重新生成、回复版本和失败续接。
7. 接入完整事件工作台读模型、流式接口和正式前端。
8. 运行自动化、580条AI评测、完整回归、构建和内部Preview验收。
