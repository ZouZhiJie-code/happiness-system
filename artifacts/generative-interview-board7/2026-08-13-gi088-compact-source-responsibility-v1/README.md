## 1. 为什么做这次候选

父级双合同配对中，精简组有 `15` 份结果只因 `REQUIRED_EVIDENCE_MISSING` 失败。逐项复核显示，模型已经选择本轮新增用户来源，程序投影也已经把当前任务的历史来源保存在正式状态里；最后一道评测仍要求模型重复提交历史来源。

产品负责人确认把“来源责任重划”作为下一单一主要因素：程序承担可以从当前有效任务唯一确定的历史来源继承，模型继续承担新增语义、修订、撤回、替换、返回和追问所需的语义来源选择。

## 2. 实施范围

- 复用父级报告中 `15` 份既有模型提案，模型调用 `0`；
- `continue` 继承当前活动任务来源；
- `return` 继承目标可返回任务来源；
- `replace` 不继承旧任务来源；
- 来源只允许同一记录中的用户消息；
- 原 Prompt、Skill、模型配置、开发集、动作门和状态结构保持当前版本。

## 3. 验证门与停止点

- 正向门：`15/15` 通过来源责任规则；
