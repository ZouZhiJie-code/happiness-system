## 三、第一性原理根因

### 1. 第二段的结构化输出约束没有在请求层闭环

第二段使用 `response_format=json_object`，DeepSeek 要求 Prompt 中显式出现 `json`。当前第二段 Prompt 缺少这一协议词，供应商在生成前直接拒绝请求。两次技术尝试重复发送同一无效合同，因此六例共出现 `12` 次相同失败。

这属于通用结构化输出基础设施的合同缺口。后续修复应由结构化调用层保证：只要声明 `json_object`，请求中就一定包含中性的 JSON 输出要求。该约束不承担任何产品策略，也不改变第一段决定。

### 2. 第一段仍未稳定区分“用户说出的关系”和“AI 新连接的关系”

行动案例中，用户只提供“乐谱横排”和“连续弹完”两条事实。模型把句子相邻理解成用户已经表达关系，选择 `user_articulated + coexistence`。预期成果需要结合此前翻谱中断的事实，形成 `ai_synthesized + change_effect`。

当前来源规则还缺少一条可执行边界：用户原话必须显式表达关系，事实在同一句或同一轮共同出现只能证明并存，不能自动证明用户已经说出作用关系。

### 3. 纠正和有限材料缺少“必须携带内容”优先级

纠正案例漏掉否认旧理解和“房间没有变暗”的限定；有限材料案例漏掉唯一剩余事实“终于”。两者说明模型会完成主要状态判断，同时丢失决定成果边界的内容。纠正、否认、必要限定和唯一剩余证据需要先进入强制携带集合，再生成语义骨架。

## 四、处理结论

本轮同时存在一个共同技术根因和三个第一段产品失败，已经满足停止条件：

1. v72 候选不进入隐藏集、工作集、准入集或板块 8。
2. 当前账本保持 `completed / technical_failed`，全部原始结果继续作为正式失败证据。
3. 停止新的模型运行、Prompt 调优和自动重试。
4. 下一轮先修复结构化输出基础合同，并重新打开第一段的显式关系归属、纠正优先级和必要证据覆盖规则。
5. 多个产品原因仍未收敛为一个变量，因此当前不使用“单变量修正”额度。
6. 新候选需要新的版本、案例指纹、离线验证和独立运行授权。

Production 继续保持 `legacy + baseline`；界面、数据库、生产模型、配置和数据保持现状。
