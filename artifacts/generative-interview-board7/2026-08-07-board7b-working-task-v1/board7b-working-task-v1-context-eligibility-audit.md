## 2. 当前输入准入原则

当前候选的质量评测按以下方式建立输入：

1. **纯净起点**：从用户第一段自然表达开始。实际产品固定开场可以作为零调用界面文案进入上下文，但不得包含焦点判断、原因假设、选项收窄或提问策略。
2. **同候选血缘**：第一段用户表达之后，进入上下文的每条 AI 语义回应都由同一候选、同一版本、同一轨迹实际生成，并绑定 Trace。
3. **真实分叉**：纠正、深入、暂停等多轮行为通过同候选完整轨迹验证。真人根据实际回应自然回答；自动角色脚本只能依据预先冻结的用户事实与行为边界，对当前实际回应作出相应反应。
4. **历史内容分轨保存**：旧候选或人工编写的 AI 回合可以继续用于历史失败复现、恢复探针或程序合同检查；其结果单独标记，不进入当前候选质量通过率、架构比较、模型能力结论或真人轨迹开放门。
5. **证据身份先于评分**：输入血缘不合格时先停止当前质量评分。九维分数、产品裁决和聚合门只统计通过上下文资格检查的案例。

## 4. 当前调优方法

当前 AI 调优以影响模型效果的因素为操作对象。每次先根据 Trace 判断问题主要来自哪一层，再选择一个主要因素形成新版本：

| 影响因素 | 主要观察内容 |
|---|---|
| 模型与生成参数 | 模型版本、Thinking、温度、输出长度和技术稳定性 |
| 基础 Prompt | 用户结果、身份、优先级、动作空间和输出要求是否清楚 |
| Interview Skill | 共同聚焦、形成认识、动态深入、纠正、问停和表达方法是否充分 |
| 上下文 | 输入消息来自谁、是否完整有效、状态摘要是否失真、顺序和噪声是否影响判断 |
| 任务与输出结构 | 模型需要完成的判断是否清楚，字段是否造成语义收窄或冲突 |
| 程序保护与反馈 | 来源、单轮一问、状态合并、恢复和错误反馈是否帮助或干扰模型完成任务 |
| 交互流程 | 用户怎样进入、怎样自然回答、怎样结束，以及评测是否保留真实分叉 |

每次调优遵循以下节奏：

1. 用纯净起点或同候选完整轨迹复现问题；
2. 通过 Trace 定位主要影响因素；
3. 修改一个主要因素，记录版本、指纹和预期影响；
4. 使用同口径回归验证，并补一条真实轨迹检查端到端体验；
5. 重复、跨场景且可解释的缺口才进入 Prompt 或 Interview Skill 的通用原则；单个表达和长尾案例进入评测集；客观稳定边界进入程序保护。

冻结的 GI-068～080 继续作为用户结果、产品边界和评测标准。它们通过职责分流进入 Prompt、Interview Skill、程序保护或评测资产，避免把全部规则堆入模型输入。
