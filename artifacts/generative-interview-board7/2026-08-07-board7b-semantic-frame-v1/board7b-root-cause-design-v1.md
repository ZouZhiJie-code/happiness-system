# GI-085 候选｜semantic-frame-first 根因设计

## 1. 已验证根因

v0.1～v0.3 的结构与可见表达问题已经逐步收敛，v0.3 达到结构 `8/8`。剩余两个秋招失败都从内部语义层开始：一次焦点直接丢失近期准备与长期方向的关系；另一次焦点保留关系，开放部分和下一步目标又重新缩成类别选择。可见回应忠实执行了错误目标。

当前合同让同一个推进决定分别出现在 `focus`、`understandingDelta`、`openPart`、`questionDecision.goal`、`expectedChange` 和可见回应中。每个字段都可以重新选择方向，语义血缘因此中断。旧模型输入同时暴露内部状态编号、失效历史和回答次数账本，进一步混合了模型判断与程序执行。旧 Skill 又逐步吸收了评测案例，旧 8 题已经成为开发回归，不能继续承担泛化证明。

## 2. 根因级调整

新候选从头整理四层职责：

| 层 | 唯一职责 |
|---|---|
| 基础 Prompt | 身份、用户结果、优先级、事实源和输出要求 |
| Interview Skill | 用户控制、焦点、认识变化、开放部分、问停和自然表达 |
| 输出合同 | 字段、空值与跨字段硬约束 |
| 程序 | 来源、单轮一问、计数、状态合并、幂等和恢复 |

具体变化：

1. 删除 Skill 中全部对照案例，避免开发样本进入常驻模型规则。
2. 删除合同中的程序合并算法、状态 ID 说明和重复的动作教学。
3. 将 `understandingDelta = none + null + []` 改为直接 `null`；认识修订通过 `invalidatedRefs + understandingDelta` 形成确定性替换。
4. 删除 `questionDecision.goal` 与模型输出中的 `expectedChange`，让 `openPart` 成为下一问唯一语义来源；程序只把它投影为回答机会账本中的内部目标。
5. 建立自包含状态迁移：当前焦点被替换或清空时，模型显式选择“失效、归档、保留为重要支线”中的唯一去向；失效内容永久退出，归档焦点保留原账本与可返回索引，重要支线继续参与当前判断；用户后续否定归档焦点时，程序同步删除其索引与账本；程序不再默认保存或复制旧焦点。
6. 允许 `focus = null` 承接纯停止和无内容场景；`ask / synthesize` 继续要求有效焦点，避免为了满足结构伪造焦点。
7. `keep` 保持焦点摘要与引用稳定，新的细化进入认识和开放部分；`keep / return` 必须保留证据血缘；等价焦点不能通过 `set` 重建引用并重置回答机会。重要支线拥有独立账本，暂停时清空待回答任务，返回时复用原账本；新增支线同时与活动语义、可返回归档焦点和同批新增支线去重。
8. 重建模型输入：保留完整对话、当前活动语义、可返回归档焦点的最小索引和程序计算的可提问边界；原始次数、失效历史、不可返回的归档内容、合并算法和幂等字段留在程序。
9. 继续使用一次调用。当前失败起点在语义选点；两阶段候选等待跨场景证据。

## 3. 执行与授权根因

候选内容正确仍不足以保证运行证据可信。GI-085 进一步绑定四类事实：

1. 候选指纹绑定模型实际读取的 Prompt、Skill、输入合同、输出合同与参数。
2. 数据指纹绑定 8 个版本化输入；请求集指纹绑定运行前一次性物化并校验的 8 个完整请求。
3. 评测判尺与执行源码分别拥有指纹；授权同时绑定候选、数据、请求集、判尺和实际执行链。
4. 一个授权 UUID 只能原子消费一次。运行文件排他创建；每次请求先保存 `in_flight` 记录，再调用 Provider，再保存单题原始结果。
5. 凭据、Provider 构造、本地写入与全部确定性检查在消费授权前完成；Production 环境直接拒绝。仓库提供经过测试的只读检查与正式执行命令，执行指纹同时绑定启动入口、依赖锁、配置、Node 和关键已解析依赖版本。

## 4. 两阶段触发条件

只有在至少两个全新题材中连续出现以下证据，才建立两阶段候选：

- `focus` 与 `openPart` 均正确；
- 可见回应仍反复偏离 `openPart`；
- 偏离无法通过当前一次调用合同稳定解决。

届时两阶段用于验证语义计划与表达执行的单变量差异，不提前预设胜出。

## 5. 评测身份调整

- v0.1～v0.3 的旧 8 题：开发回归。
- v0.4：运行前关闭，模型调用 `0`。
- semantic-frame v1：使用旧秋招两个决策点各一次，加两个全新关系场景各两次、独立内容反事实一次、用户暂时放下一侧一次。
- 全新案例不进入 Prompt 或 Skill，运行输入不包含判尺与预期答案。
