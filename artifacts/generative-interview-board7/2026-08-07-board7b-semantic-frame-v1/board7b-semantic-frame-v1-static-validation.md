# semantic-frame v1｜静态与独立前向验证

验证身份：候选结构与方法检查。全部输入为合成材料，DeepSeek 调用 `0`；本结果只承担运行授权前的完整性证明。

## 1. 既有失败作为 RED

v0.3 已完成的真实 DeepSeek 回归提供两条失败证据：语义焦点直接缩成类别选择；关系焦点已经建立后，`openPart` 和问题目标再次缩成类别选择。两条失败都发生在可见表达之前。

第一版 semantic-frame v1 接受两个未进入常驻资产的独立场景后，又发现两处接口问题：

1. 关系场景保留了共同影响，但可见问题同时索取“确定程度”和“最晚时间”，形成两个可分别变化的回答内容。
2. 用户暂时放下一侧时，代理采用了新焦点，却把待回答机会编号写入 `invalidatedRefs`，并停在单独承接动作。

据此完成第一轮三项通用调整：待回答机会使用专用 `opportunityRef`；用户控制先更新有效语境，再选择剩余价值最高的动作；一个问题只请求一项可以直接回答的内容。

最终根因审计继续发现：旧状态合并器会把被切换的焦点默认保存为重要支线；输出合同又要求任何场景都生成焦点；授权只绑定候选和数据，实际执行源码、精确请求和单次消费缺少完整约束。GI-085 因此改为自包含状态协议，并把运行证据链一起重建。运行前复审又补齐可返回归档焦点的原账本、归档焦点被用户否定后的失效出口、归档焦点参与新增支线去重、同回合重复支线拒绝、仓库正式执行入口、实际依赖环境指纹，以及模型合同失败与技术失败的分账。

## 2. 修正后的独立前向检查

两个新代理只读取基础 Prompt、Interview Skill 与输出合同，未读取回归输入、判尺和历史结果。

| 新场景 | 语义结果 | 可见结果 | 裁决 |
|---|---|---|---|
| 搬近公司、睡眠和家庭照料互相影响 | `keep` 保留原焦点血缘，认识同时吸收睡眠、耐心和照料转移；新增家庭照料支线 | 只询问当前照料中最难替代的一项帮助 | 通过 |
| 外地岗位与照顾父亲；用户完成照顾安排并纠正焦点 | 旧焦点、旧认识和旧开放部分进入归档；返回已有“岗位成长价值”支线并复用其账本 | 只询问最能支撑搬迁的一项成长价值 | 通过 |

两份结果均使用最终 `focus / invalidatedRefs / archivedRefs / importantBranchDelta` 合同，满足：结构合法、用户原话来源正确、关系与边界处理正确、旧焦点去向唯一、一个动作、一个问题、一个回答任务。
