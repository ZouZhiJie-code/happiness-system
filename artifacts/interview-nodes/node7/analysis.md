# 节点七：上下文与 Prompt 组装

> 事实基准：2026-07-20 当前代码。本文只解释现有功能设计，不展开优化方案或后续行动。

## 一、这一层为什么存在

动作决策层和追问目标规划层已经确定了“这一轮继续追问”以及“要追哪一类信息”。模型仍需要一份边界清楚、信息足够的任务说明，才能把内部目标表达成自然中文。

因此，这一层负责把分散在系统各处的信息整理成一次模型可执行的输入：

- 产品层面的访谈目标与表达规则；
- 当前维度、阶段、动作和问题目标；
- 当前事件档案与其他事件摘要；
- 最近对话、当前用户输入和可选历史记忆；
- 系统根据现有材料生成的维度语义解释；
- 模型必须遵守的输出协议。

它的输出是一组 `AIChatMessage`，供下一层“模型生成”使用。正常追问时，这组输入固定由两条消息组成：一条 `system` 消息和一条 `user` 消息。

## 二、这一层在什么情况下运行

当前实现只在系统已经决定继续生成访谈追问时组装问题 Prompt，动作包括：

- `reply`：处理用户本轮正常回复；
- `continue_current_event`：用户选择继续深聊当前事件。

以下分支由服务端直接处理，不进入本轮问题 Prompt：

- 问题修复的确定性重问；
- 事件完成选择；
- 材料不足时的低压选择；
- 开心维度转向改进维度的选择；
- 固定开场问题。

结构化槽位提取使用另一套独立 Prompt，属于前面的“槽位提取”节点。本文所说的 Prompt 组装，专指访谈摘要与下一问的生成输入。

## 三、输入由哪些部分组成

### 1. 上游已经确定的控制状态

这一组信息告诉模型“当前任务是什么”：

- 当前维度；
- 当前动作：正常回复或继续深聊；
- 目标阶段；
- `questionSpec`：追问目标、细分目标、提问意图、表达层级、事件锚点和修复次数；
- 会话总有效轮次与当前事件有效轮次；
- 本轮回复是否有效；
- 之前和当前已经到达的访谈深度；
- 当前事件累计覆盖的访谈视角，以及本轮探索覆盖的视角。

`questionSpec` 是追问目标规划层交给这一层的核心任务单。它可能包含：

- `target`：具体事件、原有判断、反应证据、新理解证据或判断线索；
- 感谢维度的 `subTarget`：对方行动、被看见的需要、感谢原因或关系线索；
- `stageIntent`：推进、继续深挖或修复；
- `surfaceLevel`：默认、简化或具体锚点；
- `anchorText`：提问应围绕的当前事件片段。

### 2. 当前事件与会话内其他事件

Prompt 会注入两层事件信息：

- `activeEvent`：当前正在追问的事件，包括事件序号、探索轮次、覆盖视角和最新快照；
- 全部事件摘要：会话内每个事件的序号、状态、阶段、探索轮次和维度化快照。

这一设计使模型能够专注当前事件，同时知道会话里已经谈过哪些事件。系统提示明确要求当前轮只深挖 `activeEvent`，下一事件由产品动作触发。

### 3. 最近对话与当前输入

Prompt 对对话历史进行了固定窗口筛选：

- 最近 8 条“用户可读对话”：用户原话，以及 assistant 的可见思路摘要和问题；
- 最近 3 条 assistant 原始结构化消息；
- 正常回复场景下，单独追加本轮用户输入；
- 继续深聊场景下，追加“继续当前事件”的动作说明，本轮内容仍可从最近对话和事件状态中获得。

最近 assistant 原始消息通常包含上一轮保存的内部载荷，例如摘要、问题、`questionSpec`、状态更新和已达深度。它与可读对话同时进入 Prompt。

### 4. 可选长期记忆

生成问题前，服务会尝试读取用户已保存的长期记忆。当前调用默认具备这些特征：

- 只有用户开启长期记忆时才会生效；
- 默认检索当前维度的记忆；
- 查询文本来自当前快照的通用字段与本轮用户输入；
- 默认最多返回 5 条；
- 注入内容包括记忆摘要和主题标签；
- Prompt 提醒模型把记忆作为参考，并避免直接引用或主动提及。

优先使用向量相似度检索；嵌入能力或查询失败时，会尝试按维度读取记忆；两条路径都失败时，Prompt 中省略记忆内容。代码会等待这次检索完成后再发起问题生成。

### 5. 产品规则与维度规则

系统消息包含三层规则：

1. 通用身份：当前维度的 Daily Light 访谈者；
2. 通用交互协议：一次一个开放式问题、摘要不能成为第二个问题、当前轮只围绕当前事件、收尾选择交给前端等；
3. 维度专属目标、访谈路径、困难场景兜底和禁区。

### 6. 服务端语义解释层

系统会先根据当前维度、快照、阶段、动作、事件和消息，运行一套确定性语义解释规则，然后把其中七项注入 Prompt：

- `themeKey`：内部主题标识；
- `themeLabel`：主题名称；
- `theorySummary`：为什么当前材料在该维度成立；
- `thinkingSummaryLead`：可见思路摘要的语义起点；
- `followUpFocus`：当前阶段应继续处理的焦点；
- `followUpQuestionHint`：部分开心场景的追问提示；
- `antiFlatteningTargets`：防止把材料写平的约束。

这一解释由服务端规则生成，模型负责将其转化成自然表达。解释层的其他字段，例如正文写作前提、结尾前提、标题候选和维度元数据，本轮问题 Prompt 不会注入。

## 四、上下文怎样被筛选和组装

当前流程可以分为六步：

1. **建立生成任务**：服务层汇总当前阶段、最新快照、事件、轮次、覆盖视角和 `questionSpec`。
2. **尝试补充长期记忆**：根据用户设置和当前语境检索同维度历史认知，失败时省略。
3. **转换维度化快照**：把通用内部字段投影成用户容易理解的维度字段，例如充实的“具体经历—进展证据—值得感标准”。
4. **生成语义解释**：服务端从快照中确定当前主题、成立原因、追问焦点和防写平要求。
5. **裁剪对话窗口**：保留最近 8 条可读对话和最近 3 条 assistant 原始结构化消息。
6. **拼成两条消息**：规则、角色和输出协议进入 `system`；当前任务、状态和上下文进入 `user`。

## 五、最终 Prompt 的组成

### System 消息：规定模型“怎样工作”

主要内容包括：

- 当前维度访谈者身份；
- 该维度的产品目标；
- 推荐访谈路径；
- 困难场景的处理原则；
- 通用提问与表达规则；
- 维度专属规则；
- 输出格式协议。

输出协议要求模型只生成两个标记段：

```text
<<SUMMARY>>一句到两句思路摘要
<<QUESTION>>一个具体追问
```

当前问题生成采用标记文本协议，Prompt 明确要求不输出 JSON、Markdown、解释或额外前后缀。`thinkingSummary` 和 `question` 都必须有内容。

### User 消息：提供模型“这一次要处理什么”

主要内容包括：

- 当前维度、动作和目标阶段；
- 当前事件与全部事件摘要；
- 深度、轮次、有效性和覆盖视角；
- 服务端语义解释；
- 可选 `questionSpec`；
- 充实维度的额外问题合同；
- 可选长期记忆；
- 最近可读对话；
- 最近 assistant 原始结构化消息；
- 本轮用户输入或继续深聊说明。

## 六、五个维度的 Prompt 差异

| 维度 | 注入的快照结构 | 专属访谈约束 | 特别控制 |
|---|---|---|---|
| 开心 | 开心时刻、开心来源、状态变化、意义需要、个人线索、轻快乐特征、轨道与类型等 | 允许轻快乐成立；意义轨道和轻快乐轨道采用不同收尾方向；避免抽象理论词诱导 | 语义解释会判断开心主题与轨道；部分负向铺垫场景会注入专属追问提示 |
| 充实 | 具体经历、感受、充实类型、进展证据、值得感标准 | 先找真实推进、积累或贡献证据，再寻找什么样的努力算数 | 额外生成 `fulfillment question contract`，明确本轮必问目标与禁止重复目标 |
| 思考 | 触发片段、感受、思考类型、新理解、判断变化 | 从具体触发和证据走向新的判断依据；避免行动计划、心理诊断和宏大结论 | 继续深聊时，如果历史对话显示用户否认过具体经历或对话，会注入“改问低压具体锚点”的守卫说明 |
| 改进 | 情境、轨道、状态判断、具体卡点或重复条件、可控因素、下次尝试和成功信号 | 先分清重复好状态或避免坏状态，再追关键条件、具体卡点与最小动作 | Prompt 禁止建议式、归责式和空泛决心式提问 |
| 感谢 | 感谢时刻、对象、具体行动、被看见的需要、内在影响、感谢原因、关系线索和回应意愿 | 从具体善意证据走向被回应的需要和关系线索 | `questionSpec` 可携带感谢细分目标和假设标识；已否认的需要或关系方向会影响上游目标及语义解释 |

## 七、这一层输出什么

这一层输出两条 `AIChatMessage`：

1. `system`：角色、目标、规则、维度策略和输出协议；
2. `user`：当前任务、结构化状态、语义解释、对话与可选记忆。

这两条消息直接传给下一层模型调用。模型调用的温度、最大输出长度、流式生成和输出解析属于“节点八：模型生成”。

## 八、哪些内容会进入模型，哪些内容会留在系统内部

### 会进入本轮问题模型

- 维度、动作、阶段和轮次；
- 当前事件及全部事件的结构化摘要；
- 覆盖视角和访谈深度；
- `questionSpec`；
- 服务端语义解释的七个选定字段；
- 最近 8 条可读对话；
- 最近 3 条 assistant 原始结构化消息；
- 当前用户输入；
- 可选的同维度长期记忆摘要与标签；
- 通用与维度专属 Prompt 规则。

### 不会进入本轮问题模型

- 用户 ID、会话 ID和事件 ID；
- 记录日期与数据库时间字段；
- 埋点、请求日志和 provider 诊断；
- 当前日志草稿与正式日志正文；
- 早于最近 8 条窗口的原始对话全文；
- 长期记忆的向量、相似度、置信度和数据库元数据；
- 语义解释层的正文写作前提、结尾前提和标题候选；
- 当前 `pendingDecision` 的数据库表现形式。

会话内较早事件仍可能以“全部事件摘要”的形式进入模型，因此“较早原始对话全文”与“较早事件的结构化摘要”需要区分理解。

## 九、当前设计中存在的问题

### 1. 同一材料会在多个区块重复出现

当前事件快照、全部事件摘要、语义解释、最近对话和最近 assistant 原始消息都可能表达同一事实。重复有助于强化约束，也会扩大 Prompt，并可能让旧表达继续影响新一轮措辞。

### 2. 对话采用固定条数窗口，事件摘要采用全量列表

最近对话固定保留 8 条，较早的用户措辞会退出窗口；全部事件摘要会继续累积。随着事件增多，Prompt 的主要体量会逐渐从对话转向事件快照。

### 3. 最近 assistant 内容同时注入可见版本和原始版本

模型既会看到最近 assistant 的用户可见摘要与问题，也会看到最近 3 条原始结构化载荷。原始载荷包含内部分析和状态字段，形成了上下文重复，也增加了模型沿用旧问题表达的可能性。

### 4. 五维的硬约束强度存在差异

充实维度具有额外的问题合同；感谢维度具有细分目标和假设标识；思考维度具有特定否认守卫。开心和改进主要依赖通用 `questionSpec`、维度规则与语义解释。不同维度的 Prompt 控制颗粒度存在差异。

### 5. 当前事件快照的序列化口径存在差异

充实、思考和感谢的 `activeEvent` 使用维度专属精简投影；开心和改进在这里注入完整内部快照。全部事件摘要又采用维度专属投影。模型在不同维度、不同区块中看到的字段范围并不完全一致。

### 6. 长期记忆通过自然语言直接拼入 User 消息

记忆以摘要和标签文本进入同一条 `user` 消息。Prompt 用文字要求模型只作参考、避免直接引用。当前结构依赖模型遵守这项语义边界。

### 7. “深度”与“覆盖视角”沿用开心维度的通用投影方式

`previousDepthReached` 和 `nextDepthReached` 由一套以开心字段访问器为基础的通用方法推导，再用于全部维度；覆盖视角也通过通用层级表示。它们能够提供统一进度提示，同时无法完整表达改进和感谢维度更细的专属槽位差异。

## 十、节点结论

上下文与 Prompt 组装层承担的是“把已确定的产品决策翻译成一次模型任务”。当前设计通过系统规则、结构化事件状态、确定性语义解释、近期对话和可选长期记忆共同约束模型，再以 `<<SUMMARY>>` 与 `<<QUESTION>>` 两段协议要求模型生成可见思路摘要和一个追问。

它是规则决策与自然语言生成之间的接口层：上游决定方向，这一层组织证据和约束，下一层完成表达。
