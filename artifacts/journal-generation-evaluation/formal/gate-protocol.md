# 正式日志生成评测门槛

## 当前状态

当前只完成评测资产骨架。`dev28` 中 10 个合成种子已有内容，9 个真人案例等待本地私有解析，9 个派生案例只有配方。`hidden12` 与 Judge 校准 20 包只有空槽位。所有正式门槛均处于“未运行”。

## 为什么按阶段冻结

开发集用于找问题和迭代，独立准入集用于验证候选是否能迁移到未见故事。两者混用会让准入结果失去独立性。因此，候选、`dev28`、Judge 校准包和 `hidden12` 分阶段冻结，并保留指纹与时间。

## Gate 0：本地隔离

进入任何数据解析或评测前，必须同时满足：

1. Web origin 使用 `http://localhost` 或 `http://127.0.0.1`；
2. `DATABASE_URL` 与 `DIRECT_URL` 都显式覆盖为本机地址；
3. 两个数据库 URL 的 database 都是 `happiness_system_codex`；
4. 两个数据库 URL 的 schema 都是 `journal_daily_eval`；
5. 环境中不存在 `VERCEL_ENV`，`NODE_ENV` 也不为 `production`；
6. 运行数据目录位于 `artifacts/journal-generation-evaluation/.private/formal/`；
7. `.private` 下除 `.gitignore` 外无任何 Git 跟踪文件，隐私探针路径能被 Git 忽略。

任一条件失败，安全检查脚本直接退出。检查脚本只解析环境和 Git 状态，不连接数据库。

## Gate 1：开发集冻结

冻结前需要：

- `dev28 = 10 个种子 + 9 个真人 + 9 个派生`，共 28 个唯一 `case_id`；
- 9 个真人案例全部由私有 importer 解析，来源文件 SHA-256 与 task/branch 可回溯；
- 9 个派生案例按配方物化，每个案例绑定一个真人父案例并沿用 `source_group_id`；
- 每个案例都有记录卡层、今日日志输入层、规则、来源和预期结果；
- 形成数据集指纹。冻结后的结构或内容变更必须生成新版本。

## Gate 2：开发与回归

候选可使用 `dev28` 迭代。进入 Judge 校准和独立准入前需要：

- P0 七项全部为零；
- 独立记录覆盖率 100%；
- 必要事实宏平均覆盖率至少 95%，单案例至少 90%；
- 错误事件合并为零；
- 必要事实覆盖不低于简单基线；
- 真人“像用户原话”和“自然度”均至少 4 分；
- 重大事实修正案例为零。

精确字段与阈值以 `../metrics-template.json` 为事实源。

## Gate 3：Judge 校准

20 个校准包完成双人标注、分歧裁决和指纹冻结后才能运行 Judge。准入门槛为：

- P0 召回率 100%；
- 精确率至少 90%。

低于门槛时，Judge 继续承担诊断作用，不能承担自动准入裁决。

## Gate 4：候选与隐藏集冻结

产品负责人确认候选指纹和 `dev28` 版本后：

1. 停止使用 `dev28` 调整当前候选；
2. 收齐 3 个全新真人案例；
3. 独立创作 9 个合成案例，故事不得来源于 `dev28`；
4. 为 12 个案例分配新的 `source_group_id`；
5. 内容只写入 `.private/formal/hidden12/`；
6. 冻结 `hidden12` 指纹后才向执行者开放。

任何内容泄漏到候选迭代过程，该槽位立即失效并用新的独立案例替换。

## Gate 5：独立准入与真人盲评

`hidden12` 使用随机匿名候选顺序连续运行 3 次：

- 每次 12 个案例 P0 通过率均为 100%；
- “可直接使用 + 轻微修改”占比至少 80%；
- A/B 偏好独立记录，不替代四级质量标签；
- 每次运行保留候选指纹、数据集指纹、静态报告、Judge 报告与真人裁决覆盖率。

## Gate 6：发布裁决

全部前置门槛通过后，只形成“可提交发布裁决”的候选。Preview、Production 切换、部署、生产数据写入和回滚方案仍需产品负责人单独授权。
